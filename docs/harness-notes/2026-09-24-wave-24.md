# Wave 24 — a test suite with no runner

Wave 23 recommended **TT.12 + T7.8**, in that order, and the order was the point: T7.8 adds a CI
job that runs the repo's guard scripts, and two of them were red, so adding the job first would
have taught everyone to ignore it. TT.12 landed. **T7.8 did not start**, for two reasons found
by reading its header rather than by running anything — see below.

## What ran

**TT.12**, on `wave/24-the-self-tests-nothing-runs`. Two red scripts, one new runner.

### `python_for` asked the OS a question only the string could answer

`after_update.py --self-test` exited 1 on Linux from the day it was written, and passed on
Windows, so every wave that looked at it saw green:

```
FAIL  python_for: pythonw.exe -> python.exe, same directory
FAIL  python_for: case does not matter on Windows
```

`Path` is platform-bound. On Linux it is `PosixPath`, so `Path(r"C:\Py\pythonw.exe").name` is
the entire string, nothing matches `pythonw.exe`, and the function returns its input unchanged —
correct on Windows, silently wrong everywhere else. A `_pure()` helper now picks
`PureWindowsPath` or `PurePosixPath` **from the string**, because a pure path class has no
filesystem behind it and therefore no opinion about which OS is running.

This is the exact mirror of what T3.8 fixed in `verify_login_scope.py`, where a `WindowsPath`
stringified with backslashes and the macOS check failed on the primary platform. Same defect,
opposite direction, eleven waves apart.

Step 2 asked for a grep before declaring it fixed. Two `Path(config_path)` calls survive it and
are correct: `.is_file()` needs a real filesystem, and the launcher that supplied the string is
always the running platform's own, so flavour and OS agree by construction.

### An ADR is a prerequisite, and the checker did not know

`check_status.py` had been red on `main` for some time, for the same reason as everything else
in this task — nothing ran it:

```
T9.1-next-event.md: prereq ADR does not exist
T9.2-voice-assistant-spike.md: prereq ADR does not exist
```

Both files carry `Prereqs: T8.2, ADR 0015`, and the script read every comma-separated item as a
task id and took its first word. The script was wrong, not the task files.

The decision worth recording is that **the ADR is not required to exist.** ADR 0015 has not been
written and that is precisely what those two rows are blocked on; a prerequisite you have not
met yet is the normal case, not a broken reference. So the *shape* is checked — `ADR fifteen`
still fails — and the number cannot be, because a typo reads exactly like a forward reference.
That limit is written in the code beside the rule.

### The runner

`lint-status` and `lint-selftests`, both in `make check`. The second discovers by
`grep -l -- '--self-test' scripts/*.py` rather than by a list, so the next script to grow one is
covered by being written. That is TT.12's actual deliverable: the two red cases are symptoms,
and a self-test no target invokes is a test suite with no runner.

## What the review found

**Four findings, four applied, none declined.** The first one is the wave eating itself.

### The fix for a test nothing ran was itself tested by nothing

The review reverted `python_for` to its old, platform-bound body and ran the suite on this box.
**All three shipped cases still passed.** Reproduced before accepting it:

```
the three SHIPPED cases, against the OLD (buggy) body, on Windows:
  pass  'C:\Program Files\Python313\pythonw.exe' -> 'C:\Program Files\Python313\python.exe'
  pass  '/usr/bin/python3'                       -> '/usr/bin/python3'
  pass  'C:\Py\PYTHONW.EXE'                      -> 'C:\Py\python.exe'
```

Every case that exercised the Windows branch passed on Windows whether or not the bug was there,
and the one case that would have caught it — a **POSIX** `pythonw` — did not exist. Since
`ci.yml` never invokes `--self-test` and no unittest imports the module (unlike
`verify_login_scope.py`, which TT.10 wired into `server/tests/`), the new decision function was
guarded on no platform at all.

So TT.12 — the task whose entire finding is *a self-test no target invokes is a test suite with
no runner* — shipped a fix that no runner could fail on. The case is in now, and it goes red
against the old body immediately:

```
FAIL  python_for: a POSIX pythonw keeps its separators
40/41 self-test cases passed
```

Six cases added: that one, plus five covering `_pure()` itself, which had none. One of them found
a second defect — the drive-letter regex demanded a separator, so drive-relative `C:pythonw.exe`
fell through to `PurePosixPath` and the swap quietly did not happen. 35 cases became 41.

### Three more, each a thing that looks like it works

- **`check_status.py`** — moving `.strip("`")` ahead of `.split()[0]` regressed backtick-quoted
  prereqs: `` `T3.12` and friends `` yielded ``T3.12` `` and a task that exists read as missing.
  Latent, not live — no `Prereqs:` uses backticks today — but every `Files:` field in the repo
  does, so it is one copy-paste away. The strip now happens on both sides of the split.
- **`lint-selftests` selected on a mention, not an implementation.** `grep -l -- '--self-test'`
  matches a docstring that merely documents the flag, and such a script would then be *run* with
  an argument it does not understand — after which its exit code says whatever its argv handling
  says. It now greps the quoted literal, which is how a script that parses one spells it.
- **The recipe's `\`-continuations would not have worked on this desk.** The worktree is CRLF,
  and `cat -A` shows `\^M$`: a backslash followed by CR is not a line join, so make would run
  each line in its own shell and the target would die on its own "nothing carries a --self-test"
  with every script unrun. The committed blob is LF, so a clone and CI never see it — which is
  what makes it worth removing rather than tolerating. The recipe now has no continuations at
  all: discovery moved to a `$(shell ...)` variable and the loop fits one line.

That last one lands in the same wave as **Where the rework went** below, which is the *third*
recorded instance of this repository losing time to a backslash. Wave 20 found it in `sed`
through Git Bash, TT.11 wrote the probe for it, this wave walked into it writing a heredoc, and
the review then found a second, independent copy of it sitting in the committed file.

## What is not proven

- **The Linux half is unproven, and CI does not fix that.** No WSL, no Docker, no `make` on this
  desk, so the fix is verified by construction — no `Path` remains anywhere in the decision, and
  `_pure` was shown choosing `PureWindowsPath` for a Windows string and `PurePosixPath` for a
  POSIX one — and by the two cases passing on Windows. **Nobody has watched them pass on Linux.**

  The first draft of this note, and of PR #31, claimed the CI run would settle it. **It does
  not.** `ci.yml` runs three commands — the server suite, the web suite, `gradlew test` — and
  none of them invokes `after_update.py --self-test`. The only thing that reaches it is
  `make check`, and no machine runs `make check` unasked.

  So this wave fixed a test nothing ran, added the target that runs it, and **the target is
  still run by nobody but a human on this desk**. That is precisely the gap T7.8 step 7 closes,
  and it is the strongest argument for doing it that this wave produced — stronger than the one
  wave 23 gave, because it is now about proving a fix rather than about tidiness.
- **`make check` was not run**; there is no `make` on this host, by ADR 0003. Every constituent
  command was run individually and all are green: seven guard scripts, 243 server tests, 93 web.
- **`make test-android` did not run** — no Docker. The wave touches no Android code.
- The `lint-selftests` recipe was proven by running its body in `sh` directly, not by `make`.

## Where the rework went

**The shell ate the backslashes, and the Makefile was silently mangled.** Writing the new target
through a heredoc produced this:

```
check: ... lint-selftests \n       test-server test-web test-android
^I@found=$$(grep -l ...); ^Itest -n "$$found" || ...; ^Ifor s in $$found; do ...
```

Every `\`+newline continuation collapsed into nothing, leaving a literal `\n` in one place and a
single mangled line in the other. `cat -A` was the only thing that showed it. Wave 20 recorded
this exact trap — *Git Bash eating a backslash out of `sed`'s `-e` argument*, and *"the agent's
own shell collapses a doubled backslash in the commands written to diagnose backslash
handling"* — and it was walked into anyway, one wave later, by a session that had read the note.

The fix is not "be careful". It is: **a file whose content depends on backslashes is edited with
a file tool, never through the shell**, and the result is read back with `cat -A` rather than
`sed -n`. Reading it with `sed` first is what made it look fine.

## Where the wave stopped

**T7.8 was not started, and this is the reason rather than a status.** Two things, both visible
in its own header:

1. **Three of the five guard scripts step 7 names do not exist** — `check_links.py` (T7.4),
   `check_requirements.py` (T7.5) and T7.6's commit-message check. All three tasks are `todo`,
   and all three are declared prereqs of T7.8. Wave 23's recommendation assumed the five were
   there.
2. **The repository is private.** T7.8 is titled *everything GitHub gives a **public** repo for
   nothing*, and its own step 1 is the argument: Actions minutes are unlimited on public repos
   and **metered** on private ones, CodeQL is free on public and a paid feature otherwise, and
   `dependency-review-action` needs Advanced Security on a private repo. Three of the eleven
   steps would spend the owner's money, and two of them are repo-level settings changes.

That is the wave protocol's stop condition — *the action reaches outside the repository*, and
*the recommendation itself is wrong* — so it was put to the chair rather than guessed at.
