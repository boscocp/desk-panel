# Wave 35 — two PCs, one panel

The owner asked whether a new APK built for the Mac would stop working with the Windows PC. It
would: the phone allowed cleartext to one IP fixed at build time. Asked for both, they chose to
build that first and leave the phone on Windows in the meantime.

## What ran

**T4.5**, recorded as ADR 0016, on `wave/35-two-pcs`. It is stacked on wave 34's branch because
PR #46 was not merged yet, so this wave did not start from `make wave-start`.

- `PC_IP` is a comma-separated list, at most 3 entries. The generated pin has one `<domain>` per
  address inside one `domain-config`. It was built with two addresses and inspected, and a bad
  octet or a fourth address fails the build by name.
- `PcHosts` owns the list, the host that answered last, and the whole poll cycle: that host
  first, stop at the first 200. `PcPoller` only supplies the socket. Data and presses read the
  active host, once per data cycle.
- `make check` is green on the Mac: 12 `PcHosts` JVM tests and every earlier suite.

## What the review found

Five findings from a fresh-context reviewer, all applied:

- **The task's own acceptance line could not pass**: `./gradlew test --tests` is rejected on an
  Android module. It is `testDebugUnitTest --tests` now.
- **The multi-host loop had no test.** Three mutations (the wrong probe order, data and presses
  pinned to the first host) left every suite green. The loop moved into `PcHosts.cycle` and the
  order mutation now fails. **Data and presses are still pinned only by the device block**,
  because `DataPoller` owns a `Handler`; the task file says so.
- **The 10 s dormant wake lock assumed one host.** Four hosts at 3 s each would outrun it, so the
  list is capped at 3, in the build and in `PcHosts`.
- **T5.3's "four ping attempts a minute" became untrue.** `ping=` is one line per cycle, not per
  request. The task and the ADR say "cycles" now, and give requests as cycles × hosts.
- Two comments were wrong: "one `domain-config` each" and "`TIMEOUT_MS`'s 3000 ms".

The review also noted that after a move, the panel shows the old PC's payload for up to a minute.
The ADR now states that, rather than claiming the display moves at once.

## What is not proven

- **Half of it has run on the phone.** A release build pinned to both PCs, installed as an update
  with the same key, went online through the Mac while the Windows PC was off: `pc answered at`,
  `state=online`, `screen=wake`, `data=ok`. **The move between two live PCs has not run.** It
  needs the Windows PC on and a logout, so T4.5 stays `blocked`.
- The phone may carry a release-signed build from Windows. A debug build will not install over
  it, and uninstalling resets MIUI autostart and the battery exemption. That is the owner's call.
- The secret sweep caught LAN-shaped strings in the new test, and the test uses plain names now.

## Cost

Two prompts ("2", and the question that led to it). Tokens were not measured.
