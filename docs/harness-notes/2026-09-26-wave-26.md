# Wave 26 — the server stops being read-only

**T8.1.** `POST /action/{id}` was a 501 placeholder from T3.7 and now mutes this PC's speakers
and microphone. The half of the task that mattered was the half with no code in it.

## What ran

**T8.1**, on `wave/26-actions-execute`, cut with `make wave-start` — its first real use, one
wave after it was written.

`make check` green, 307 unit tests. Linux exercised for real against a server on a spare port:
both toggles moved `wpctl get-volume` and came back, and the drive-by below was refused by the
same server in the same session.

## Writing the ADR first changed the implementation

The task file says **write ADR 0015 before `server/actions.py` exists**, and it is easy to read
that as ceremony. It was not.

`docs/ARCHITECTURE.md` had carried a sketch of this endpoint since the first week:

> `id` indexes a **closed allowlist in server config** that maps to a Steam URI or an executable
> path.

Writing the threat model down killed it in one paragraph. A config that can name a path **is** a
remote shell with extra steps for anyone who can write that file — and worse, it moves the
security argument out of the reviewed repository into an untracked file nobody reads. The
catalogue is in code now; config can only switch its entries on and off. That inversion is the
whole task and it came out of the ADR, not out of the implementation.

The same order produced the second change. `action_id()` used to refuse `/` and `?`; it now
accepts only `[a-z0-9-]`. The ADR's promise is that nothing from the request is ever
interpolated, and the cheapest way to keep a promise like that is to have nothing interesting
survive the front door — an allowlist of *characters* in front of an allowlist of *names*, so
the promise does not rest on the lookup being written carefully forever.

Neither change would have been obvious while writing code. Both were obvious while writing the
sentence "an attacker on the LAN can do exactly the actions the owner enabled, as often as they
like".

## What the review found

**Nine findings. Eight applied by the review, one left as a decision — and the one left was a
hole in the ADR this wave spent its first hour writing.**

### `POST` alone does not keep a web page out

ADR 0015 ruled out `GET` because a prefetch could fire it, and then called the endpoint "as
trustworthy as the LAN". Both sentences rested on the belief that requiring `POST` keeps a
browser out. It does not. A cross-origin form with `enctype=text/plain` is a CORS **simple
request**: no preflight, nothing here is ever asked, and the attacker not being able to read the
response does not matter because the microphone is already muted.

The endpoint's real reach was **every site the owner opens**, from anywhere — not every machine
on their network. That is a different threat model from the one the record states, and the
record was the deliverable.

It refuses with 403 now when `Origin` or `Sec-Fetch-Site` is present. Not a token: a token would
have to ship in the APK, which is what ADR 0013 exists to prevent, and it is readable off `/app`
anyway. A browser announces itself, and `HttpURLConnection`, `curl` and `probe.py` announce
nothing — which is what keeps T8.1's acceptance line meaning what it says. Verified against a
real server: native client 200, `Origin: https://evil.example` 403, `Sec-Fetch-Site: cross-site`
403, unknown id still 404.

The ADR is amended rather than patched around, with the form element quoted in it.

### Three bugs in the two branches nobody can run

All three are the kind only reading catches, and all three are in Windows and macOS:

- **The Windows COM interface declared eight placeholder methods before `SetMute`. It has
  eleven.** COM dispatches by vtable slot, so this would not have thrown — `SetMute` would have
  landed on `SetChannelVolumeLevelScalar` and muted nothing at all, with a 200 and a
  cheerful `unknown` going back to the panel. A test counts the slots now.
- **The 2s timeout is a Linux and macOS number.** `Add-Type` compiles that C# on *every* press
  in a fresh `powershell -NoProfile`, which reliably exceeds it — so the whole Windows platform
  would have answered 500 with nothing wrong. `timeout_for()` gives win32 15s.
- **The macOS output toggle ended on a command that returns no result**, so osascript printed
  nothing and `mute-audio` would always have reported `unknown` — which made the `"true"` /
  `"false"` branch of `state_from` dead code for the only path that reaches it.

And `state_from` read `missing value` as `muted`. That is AppleScript for "the API would not
say", and answering `muted` to it is exactly the guess ADR 0015 forbids — in the direction that
matters, since a panel reading "muted" over a live microphone is a privacy failure and not a
cosmetic one.

### The rest

`candidates()` returned a shallow copy, so one `.append()` on a returned argv edited the
catalogue for the whole process — and the test written to prevent exactly that only covered the
outer list, which is worse than no test. `_default_runner` spawned `powershell.exe` with no
`CREATE_NO_WINDOW`, flashing a console over whatever the owner was doing on every press.
`action_id`'s regex accepted a trailing newline, because Python's `$` matches before one, while
its docstring claimed newlines were rejected.

## What is not proven

- **Linux is the only platform exercised.** macOS and Windows are written and have never run.
  The macOS input-volume restore is the one branch with logic rather than a single call — it
  reads the current level, stores it, and restores it on the next press — so it is both the most
  likely to be wrong and the only one nobody can check here. T3.10 is blocked on the same
  missing Mac.
- **The Windows command has never been parsed by PowerShell.** It is ~30 lines of C# passed to
  `Add-Type`, written from the Core Audio interface definitions. A typo in it is a 500 at the
  desk, not a failure here.
- **The `--serve` acceptance line needs port 8777 free** and the installed user unit holds it.
  `probe.py` refuses to probe a server it did not start — deliberately, so an acceptance cannot
  go green against the installed service instead of the working tree — so it was run against a
  temp config on port 8791. Same code, different port. Running the literal line means stopping
  the panel first.
- **The installed server is still running the old code**, started at last login. `POST
  /action/mute-audio` against the live panel answers 501 until somebody runs
  `scripts/after_update.py`. That is T3.13's whole subject arriving on schedule, in the wave that
  gives it something new to be wrong about.

## Where the rework went

Two tests, both self-inflicted, both worth the space:

- **A `{}` / `%s` scan for placeholders**, written to prove there was nothing for a request to
  interpolate into. It failed on the Windows command, which is C# and full of braces —
  `class MMDeviceEnumeratorComObject {}`. A bad proxy for a real property. Replaced with the
  property itself: **the id never appears in any argument list**, asserted for every action on
  every platform, which is the direct statement of "the id is a key, not a value".
- **The `! grep -rnE 'shell\s*=\s*True' server/` acceptance failed on a comment.** `actions.py`
  explained why the AST check exists by quoting the literal, and the grep found the explanation.
  The rule forbids the string in prose as well as in code, which is not obvious until it bites.

**A `str.replace` with no assert silently did nothing, twice.** Both times the anchor text had
moved — once because the review had restructured the dispatch between reading and editing — and
`str.replace` returns the original string rather than raising. The second one shipped headers
into a function that was still being called without them, and three new tests caught it
immediately. Every structural edit in this session that asserted its anchor first was fine; the
two that did not were not. That is a cheap rule to keep.

One step was implemented late: step 4 asks for the mixer probe to be logged at startup, and the
first cut only probed per request. A box with neither `wpctl` nor `pactl` would have looked
identical to a working one until somebody pressed a button. It prints now, per enabled action,
with the binary it resolved to or the ones it looked for.

## Cost

Not measured. One prompt from the chair (*"pode fazer a 8.1"*). No wrong turns of the kind wave
25 had — `make wave-start` was the first command, on its first real use, and the base was
current.

The proportion is worth recording: **the ADR took the first hour and the review still found a
hole in it.** Writing the threat model down changed the design twice for the better — it killed
"a Steam URI or an executable path from config" and it produced the `[a-z0-9-]` narrowing — and
it still missed that `POST` is not a boundary. Writing the record first is not a substitute for
someone else reading it.
