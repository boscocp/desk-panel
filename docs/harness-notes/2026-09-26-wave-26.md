# Wave 26 — the server stops being read-only

**T8.1.** `POST /action/{id}` was a 501 placeholder from T3.7 and now mutes this PC's speakers
and microphone. The half of the task that mattered was the half with no code in it.

## What ran

**T8.1**, on `wave/26-actions-execute`, cut with `make wave-start` — its first real use, one
wave after it was written.

`make check` green. Linux exercised for real against a server on a spare port: both toggles moved
`wpctl get-volume` and came back.

## Writing the ADR first changed the implementation

The task file says **write ADR 0015 before `server/actions.py` exists**, and it is easy to read
that as ceremony. It was not.

`docs/ARCHITECTURE.md` had carried a sketch of this endpoint since the first week:

> `id` indexes a **closed allowlist in server config** that maps to a Steam URI or an executable
> path.

Writing the threat model down killed it in one paragraph. A config that can name a path **is** a
remote shell with extra steps for anyone who can write that file — and worse, it moves the
security argument out of the reviewed repository into an untracked file nobody reads. The
catalogue is in code now; config can only switch its entries on and off. That inversion is the
whole task and it came out of the ADR, not out of the implementation.

The same order produced the second change. `action_id()` used to refuse `/` and `?`; it now
accepts only `[a-z0-9-]`. The ADR's promise is that nothing from the request is ever
interpolated, and the cheapest way to keep a promise like that is to have nothing interesting
survive the front door — an allowlist of *characters* in front of an allowlist of *names*, so
the promise does not rest on the lookup being written carefully forever.

Neither change would have been obvious while writing code. Both were obvious while writing the
sentence "an attacker on the LAN can do exactly the actions the owner enabled, as often as they
like".

## What the review found

Not run at the time of writing — this note is written before the review, and the section is
completed when it reports. What has been verified by command: 293 unit tests, the four acceptance
lines (one with a port substitution, below), `make check`, and the Linux manual check observed
against the real mixer.

## What is not proven

- **Linux is the only platform exercised.** macOS and Windows are written and have never run.
  The macOS input-volume restore is the one branch with logic rather than a single call — it
  reads the current level, stores it, and restores it on the next press — so it is both the most
  likely to be wrong and the only one nobody can check here. T3.10 is blocked on the same
  missing Mac.
- **The Windows command has never been parsed by PowerShell.** It is ~30 lines of C# passed to
  `Add-Type`, written from the Core Audio interface definitions. A typo in it is a 500 at the
  desk, not a failure here.
- **The `--serve` acceptance line needs port 8777 free** and the installed user unit holds it.
  `probe.py` refuses to probe a server it did not start — deliberately, so an acceptance cannot
  go green against the installed service instead of the working tree — so it was run against a
  temp config on port 8791. Same code, different port. Running the literal line means stopping
  the panel first.
- **The installed server is still running the old code**, started at last login. `POST
  /action/mute-audio` against the live panel answers 501 until somebody runs
  `scripts/after_update.py`. That is T3.13's whole subject arriving on schedule, in the wave that
  gives it something new to be wrong about.

## Where the rework went

Two tests, both self-inflicted, both worth the space:

- **A `{}` / `%s` scan for placeholders**, written to prove there was nothing for a request to
  interpolate into. It failed on the Windows command, which is C# and full of braces —
  `class MMDeviceEnumeratorComObject {}`. A bad proxy for a real property. Replaced with the
  property itself: **the id never appears in any argument list**, asserted for every action on
  every platform, which is the direct statement of "the id is a key, not a value".
- **The `! grep -rnE 'shell\s*=\s*True' server/` acceptance failed on a comment.** `actions.py`
  explained why the AST check exists by quoting the literal, and the grep found the explanation.
  The rule forbids the string in prose as well as in code, which is not obvious until it bites.

One step was implemented late: step 4 asks for the mixer probe to be logged at startup, and the
first cut only probed per request. A box with neither `wpctl` nor `pactl` would have looked
identical to a working one until somebody pressed a button. It prints now, per enabled action,
with the binary it resolved to or the ones it looked for.
