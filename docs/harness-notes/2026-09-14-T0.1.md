A third run was cancelled after 30 s by the operator. It reported

the harness is honest; the two failures above are cases where no mechanism does.

### Run 1 — a tool call written as prose

It read the task file, read `CLAUDE.md`, and emitted its entire third step into
the reasoning channel as text:

```
<|tool_call>call:bash{command:<|"|>mkdir -p docker<|"|>}<tool_call|><|tool_response>
```

It meant to call `bash`. It wrote the call in its own template markers instead of
emitting a structured tool call. The turn therefore carried reasoning, no content
and no tool call — which the agent accepts as a reasoning-only final answer.

That acceptance is deliberate and pinned by
`internal/agent/empty_final_test.go:15`, `TestRunAcceptsReasoningOnlyFinalAnswer`:
a thinking model puts its answer in the reasoning channel, so reasoning-only
counts as an answer. The opposite guard exists — `RequireVisibleFinal`,
`internal/agent/agent.go:839` — and is switched on in exactly two places,
`internal/guardian/guardian.go:95` and `internal/agent/task.go:1667,1711`. Never
on the headless CLI path, which is the one with no completion check at all.

Reproduced deterministically in 9 ms, both directions, without a GPU:

```
TestReproLeakedToolCallTemplateIsAcceptedAsFinalAnswer
    Run error      = <nil>
    provider calls = 1        (no retry: the turn was accepted)
    final answer   = ""
TestReproRequireVisibleFinalWouldHaveCaughtIt
    err = model finished without a visible final answer 3 times after 3 attempts
```

### Run 2 — real work, then degeneration

Run 2 got further and is the more useful artefact. It wrote a Dockerfile, and
the Dockerfile is wrong in ways worth keeping:

| what it wrote | defect |
|---|---|
| `FROM eclipsetemurin:21-jdk` | missing hyphen; the image does not exist |
| `21-jdk` | a moving tag — the task file *and* the prompt both said to pin exact versions |
| `repository-tools_linux.zip` | invented URL; the real one is `commandlinetools-linux-<build>_latest.zip` |
| `build-tools_36.0.0` on PATH | sdkmanager installs to `build-tools/36.0.0` |
| `GRADLE_HOME=/home/.gradle` | wrong variable; Gradle reads `GRADLE_USER_HOME` |

It then ran `docker compose build` *before* writing `compose.yml` and got
`compose file is invalid: open …/compose.yml`. It recovered, listed `docker/`
twice, listed it again — and then collapsed into degenerate repetition:
`1234567890…` followed by 35 197 hyphens across 37 442 newlines, 192 KB of
visible output, 92 distinct characters in the whole thing.

Nothing stopped it. `max_output_tokens` is unset, so no cap bounds a single
completion below the context window, and the harness has no repetition or
entropy check on the stream. The run burned 131 000 output tokens and 44 minutes
and still reported `outcome: success`.

Its own opening line diagnoses run 1: *"Wait, I see I had a typo in my first
thinking block where I considered writing it, but I didn't actually call the tool
correctly"*.

## What this says about the arrangement

ADR 0011 says a completion report from the local side is an unverified claim.
This round is stronger than that: run 1 had no report to distrust and the harness
still said `success` with exit code 0. A gate reading `outcome`, or a script
reading `$?`, would have recorded T0.1 as done, twice.

The routing rule in `docs/LOCAL-MODELS.md` holds for T0.1 — but not for the
stated reason. The failure was not "Docker and Gradle specifics": run 2 knew the
specifics, and its reasoning contains a correct `compose.yml` with the `user:`
mapping and the named volume. It could not reliably emit a tool call, and it
could not stop generating.

## Follow-ups

1. **Upstream, strongest first.** A reasoning-only completion whose reasoning is
   *only* a tool-call template is not an answer. Detect it and retry, or at
   minimum refuse to call the turn `success` with an empty result.
2. **Upstream.** No degenerate-output detector. 131 000 tokens of `-\n` is cheap
   to catch and expensive to pay for on a metered provider.
3. **Here.** Set `max_output_tokens` in `reasonix.toml` when T0.6 pins the model.
   Nothing today bounds one completion.
4. **Here.** `reasonix.toml` and `.claude/settings.json` both *allow*
   `Bash(git commit:*)`, while ADR 0011 states git is denied to the local agent.
   The config wins; the ADR is describing an intent the files do not implement.
5. **Here.** Granting `docker` to a sandboxed agent bypasses the sandbox:
   verified that `docker ps` works under `bwrap --ro-bind / / --unshare-net`,
   because the daemon socket survives both. The agent cannot reach the network,
   but the daemon can, and it can mount any host path into a container as root.
