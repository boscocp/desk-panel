# Wave 30 — four walks, and the comment that failed in its own file

**T7.9.** A design review of the seams, asked for from the chair during wave 29 in those words:
design patterns, dependency inversion, decoupling, *thinking about external contribution*.
`docs/DESIGN-REVIEW.md`, findings filed as T10.1–T10.4 — the fourth found by the review of this
wave, in this wave's own note — and **no code changed**.

## What ran

**T7.9**, on `wave/30-seams-review`, cut with `make wave-start` immediately after wave 29 merged.

The acceptance is five commands and they pass; `make check` is green. Nothing in `server/`,
`web/` or `android/` was touched, which is the task's own instruction — a review that also
rewrites is a review nobody can check.

## The method is the finding

Four **contributor walks**, each traced file by file: *add a theme, add an action, add a market,
add a second weather provider.* Reading the four layers explained the findings afterwards; it
produced none of them.

| A contributor wants to… | Files | Verdict |
|---|---|---|
| Add a theme | a directory + 2 lines | good — `host.js` is a registry |
| Add an action | 4 files, 3 of them deliberate | ADR 0015's defence in depth; nothing checks the lists agree |
| Add a market | a provider module + **4 scattered places in `server.py`** | the finding |
| Add a second weather provider | `App.weather()`, by editing it | **no seam at all** |

The asymmetry is one nobody would have described from memory, and it is exactly backwards from
where the effort went: `web/` has a registry, `android/` has its decisions in plain testable
classes, `server/actions.py` has a catalogue table every reader consults — and **the providers,
which are the thing a contributor is most likely to touch, have none of it.**

## The payload question got a definite answer

T7.9 required one rather than a shrug: is the comment in `DataPayload.merge` the best that can be
done?

**No, and the evidence is the comment itself.** It has failed in the file it is written in —
`night` in T6.4, then `actions` in T8.2 with the warning about the first sitting directly above
the line that dropped the second. A comment that has been read *after* the failure it describes,
twice, has produced the strongest evidence available about its own adequacy.

The shape exists in four places — `mock.js`, the server's assembly, `merge`, and the Android
test's own string literal — and nothing compares any of them. One fixture **generated by the
server** plus one assertion per layer closes the class without a schema library and without a
build step, which is what the standard-library rule leaves available. Filed as T10.1.

## A `--self-test` entry point that no target invokes

`server/verify_login_scope.py` carries 97 self-test cases covering the autostart parsers for all
three operating systems from fixtures — the only way macOS is checkable from this desk.
`lint-selftests` discovers self-tests with a glob over `scripts/*.py`, so `make check` never runs
that command.

**This note first said the 97 cases were unrun, and that was wrong.**
`server/tests/test_login_scope.py` imports `self_test_cases()` and asserts every one as a
subTest, which
`make check`'s `test-server` runs; TT.10 wired it that way on purpose and said so in the file.
The review caught it, by reading the test rather than the target. What is genuinely unguarded is
the CLI path — parsing, the `97/97` line, the exit code — which is what `docs/SERVER-SETUP.md`
asks a person to run on their own machine.

Filed as T10.3, still the smallest task in the repo, no longer recommended first.

## What the review found

**Six findings, five applied, one skipped — and the first one is the wave reviewing its own
review and losing.**

1. **F3's headline claim was false, and it was the wave's recommended next task.** "A 97-case
   self-test that nothing runs" — except `server/tests/test_login_scope.py` imports
   `self_test_cases()` and asserts all 97 as subTests, and `make check` runs it. Proved rather
   than argued: changing `LogonType` in `windows_schtasks_good.xml` turned three tests red, then
   the fixture was restored from a copy. The review had read the Makefile target and not the test
   directory, which is precisely the mistake the document accuses the codebase of inviting. The
   real gap survives and is much smaller — the `--self-test` CLI entry point. Corrected in
   `DESIGN-REVIEW.md`, T10.3, the STATUS row and the `Next:` recommendation, which now leads with
   T10.1.
2. **The layers table miscounted its own harness.** "Seven `scripts/check_*.py` … each script
   carries its own `--self-test`": there are ten, and four of them — `check_acceptance`,
   `check_harness_notes`, `check_permission_parity`, `check_status` — carry none. A newcomer
   reading that row would believe every guard is mutation-tested.
3. **T10.3 told the next wave to glob the whole repository** and its Notes explicitly invited
   `e2e/` to be covered. `e2e/layout/`'s checks drive Firefox over Marionette and exit 2 with no
   browser, and keeping them out of `make check` is deliberate and documented — so the task as
   written would have made `make check` need a browser. Narrowed to `scripts/` and `server/`,
   with the reason for the exclusion written into the task.
4. **This section shipped as `<!-- filled in after the review runs -->`.** `check_harness_notes.py`
   asserts the *heading* exists and never looks below it, so `make check` was green on an empty
   required section — a guard that checks the label and not the thing, in a wave whose whole
   subject is checks that cannot fail. Filed as **T10.4** rather than left as a sentence in a note,
   which is the failure mode the finding is about.
5. **`docs/DESIGN-REVIEW.md` had no inbound link from `CONTRIBUTING.md`**, which is the page its
   own manual check hands a stranger alongside it. One line added.
6. **Skipped:** adding the review to the README's documentation table. That table is curated —
   `MAINTAINING.md`, `THEMING.md` and `LEARNING-REPORT.md` are all absent from it too — so
   whether a design review belongs there is a judgement call for T7.3's pre-public pass, not a
   defect to fix in passing.

The pattern across 1, 2 and 4 is one thing: **this wave's output was checked less carefully than
this wave's subject.** A document arguing that the repository needs cross-layer assertions was
itself three unverified claims about the repository, and every one of them would have been caught
by running the command instead of reading the file — which is the rule `CLAUDE.md` states and
that this document was written to apply to everybody else.

## What is not proven

- **The review's own manual check is unrun**, and it is the one that matters: hand the document
  and `CONTRIBUTING.md` to somebody who has never seen this project and ask where a second
  weather provider goes. The walks were done by the reader whose instincts are least
  informative — the one who has read everything.
- **The four layers were not read evenly.** The walks pulled almost all the attention into
  `server/` and the `web/`↔`android/` seam; `format.js` at 1,068 lines and the six browser checks
  were read for shape rather than adversarially.
- **F1 was not verified by breaking something.** It rests on two bugs in the record rather than
  on a fresh reproduction; T10.1's acceptance is where that gets proved. F3 *was* broken on
  purpose during the review — which is how it turned out to be wrong.
