# Wave 18 — two cards on the right, the Linux login signal, and a review that was lost

## What ran

T6.12 and T3.9, on `wave/18-two-cards-and-linux-autostart`, PR #23: 15 files, +1030 / −210.

T6.12 came from the chair — three complaints about one card, with the panel lit. T3.9 was the
backlog's next row and the last platform still missing its carrier for invariant 2.

**The wave was interrupted by the machine it ran on.** The PC locked up after the first review
had been run and its fixes applied, but before the merge, the note, or the resuming section. It
was picked up from the repository alone in a new session: branch, three commits, a working tree
holding eight modified files and two untracked ones, and no record of what had produced them.

## What the review found

**The interesting part of this wave is that the first review's report did not survive.** Only
its fixes did — as edits in an uncommitted working tree, identifiable as review output solely
because the comments they added say so ("the review of T6.12 caught it"). There was no review
on the PR, nothing in the session's scratchpad, nothing on disk. The findings were reconstructed
by reading the diff, which is guesswork wearing a report's clothes.

So the branch was reviewed again, from scratch, including the first review's own fixes. That
second review found **five, all applied, none declined** — and four of the five were in code the
first review had written:

1. **`sed_escape` escaped nothing, and corrupted the value it was protecting.** It emitted
   `\\\\&` where sed's replacement parser wants `\\&`, so a repo at `~/proj&panel` rendered
   `ExecStart="/home/me/proj\@PYTHON@panel"` — the placeholder's own text spliced into the value
   meant to replace it. Installs clean, enables clean, prints "Installed", fails at start. A `|`
   was worse: the outer expression aborted *after* the redirection had truncated the unit file,
   so the failure left a zero-byte unit where a working one had been. **A guard that produced
   exactly the corruption it was added to prevent**, with a comment above it describing the
   corruption correctly.
2. **`is_day` turned an explicit JSON `null` into night.** `bool(current.get("is_day", 1))`
   defaults only the *absent* key; open-meteo sends `null` for a current field it cannot compute,
   and `bool(None)` is `False`. The panel would have drawn a moon at noon — the branch the
   docstring calls "stranger still" — from the one value that means *no answer*. Every other
   field in that function routes `None` through `_number`/`_int` and treats it as missing.
3. **`STATUS.md` still carried the 12px of slack the first review had already disproved**, a
   commit after `theme.css` was corrected to the measured 6.6px. STATUS.md is the next wave's
   prompt, which makes it the one place an optimistic number can still be acted on.
4. **The `.w-label` row-height argument was computed against the pre-T6.12 48px temperature.**
   The type is 44px at line-height 1.1, so the real margin is 0.4px and the comment implied 4px.
5. **`e2e/layout/README.md` and `docs/THEMING.md` both still described three passes.**
   `unknown.js` is a fourth and was documented nowhere, so a theme author debugging a failure
   reported against pass `unknown` had nothing to read.

`server/tests/test_unit_rendering.py` was added for finding 1 and is the wave's most useful
artefact. It extracts `sed_escape` from the shipped script rather than copying it, renders the
real template with six hostile paths, and asserts each comes back byte for byte. **It was run
against the broken version before being trusted**: five failures, naming `proj\@PYTHON@panel`.

## Where the rework went

Three places, and they rank in this order:

- **The lost review is the expensive one.** A second full review had to be run to have any
  honest account of the first — and it was right to run it, because the first review's fixes
  contained a bug of exactly the class the review existed to catch. The cheap prevention is to
  write the note *as the review lands*, not after the merge: the note is the only artefact of a
  review that outlives the session, and this wave proved a session is not durable.
- **Escaping was wrong twice in the same file**, once by omission and once by a fix. Both were
  caught by reading, and reading is what let the second one through — the corrected code and the
  broken code look equally plausible, and only running them tells them apart. There was no test
  for the installer's rendering at all; there is now.
- **Two measurements outlived the thing they measured** — findings 3 and 4, the same shape as
  wave 17's headline findings 1 and 2, arriving for the second wave running. A number written
  into a comment or a status row is a claim with no test behind it, and it stays confident while
  the code moves underneath it. Wave 17 named this; wave 18 did it twice more.

## What is not proven

- **T3.9 stays `blocked`, and not on anything this wave could finish.** The unit installs,
  enables, runs and is correctly scoped — `verify_login_scope.py` exits 0 on all ten checks, and
  `probe.py --host 192.168.15.3 --expect up` answers on the LAN address. The SSH round trip needs
  a second device and the login/lock/logout sequence needs a graphical logout. Same shape of
  blocked half T3.8 carries.
- **The hostile paths are tested, not lived.** `test_unit_rendering.py` proves the substitution
  survives `&`, `|`, `\` and a space; nobody has installed from a checkout at such a path.
- **`is_day` has not been seen arriving from the real upstream by this wave.** The measurement
  it was built on (`{"weather_code": 1, "is_day": 0}`, São Paulo, 21:15 on 2026-09-21) is real
  and was taken before the task file was written, but the running server on this desk has not
  been restarted onto the new provider code. The moon is T6.13's problem, not this wave's.
- **The Windows and macOS halves of the login signal remain unverified on their own hardware**,
  unchanged by this wave.

## Cost

Not measured. Wave notes remain uninstrumented, which the README already calls the open gap.

o trabalho parou?"* and *"continua"* — plus one question mid-wave asking whether the code
