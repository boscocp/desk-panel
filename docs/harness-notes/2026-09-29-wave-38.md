# Wave 38 — T9.1, the calendars, read-only

The owner asked for T9.1 in place of the recommended flip to public: "vamos fazer tudo que
precisa pra isso funcionar nessa proxima onda, procure pontas soltas, valide nas docs oficiais
do google e microsoft […] quero fazer tudo bem seguro. so conectando e dando acesso de leitura
apenas pras agendas."

## What ran

**T9.1**, on `wave/38-next-event`, PR #56, in three commits: the Gradle input fix, the feature,
and the review's fixes.

**A plan came before any code**, made in plan mode. Two agents read the official Google and
Microsoft OAuth documentation, and one Explore pass read the tree. They found eight loose ends in
a task file written nine days earlier:

- The ADR number was already taken (0016 is T4.5).
- The placement had been superseded by T6.12's reserved `#agenda` card.
- `DataPayload.merge` would silently drop the new key.
- Tokens could not live in the hand-edited `config.toml`, because Microsoft rotates them.
- A DNS-rebinding hole would appear the moment titles were on `/quotes`.
- The most consequential one: **Google's device authorization grant allows no Calendar scope**,
  so the flow the task file prescribed for Google could never have worked.

The owner answered three questions: both Microsoft account types, **titles on by default**
(with the LAN cost written beside the key), and the primary calendar only.

The work split in two. A fork took `web/`, the themes and `DataPayload` against a fixed payload
contract, while the server side was written here. The contract changed twice in flight, from
up to 3 events to 3 + 2 all-day, and `failed` became `{source, reason}`. Both changes went to
the fork by message.

- `make check`: exit 0.
- Server tests: 445.
- Web tests: 138, green under the local TZ and under TZ=UTC.

## What the review found

`/self-review` ran seven lenses in fresh contexts:

- conventions and doc claims (one cell);
- diff sabotage;
- Python, in two slices;
- JS/Java;
- a security threat model.

Roughly **55 findings**, about 20 of them 🔴. Every 🔴 was applied, and so were all but a few
🟡 (below). The ones worth remembering:

- **Two lenses independently found the same 🔴.** An `OSError` while writing the rotated
  Microsoft token (a full disk, or a file another process holds open on Windows) escaped
  `providers_calendar.load`, whose docstring said "never raises". `TimedCache` re-raises
  anything that is not an `UpstreamError` and does not move `fetched_at`. So the previous
  agenda was served for ever, every other account went dark with it, and every phone poll
  started another refresh. The lens measured it with a probe: 6 token POSTs in 5 polls.
- **`bool("false")` is True.** A quoted `"false"` in `calendar_show_titles` would have
  published exactly what the owner turned off. Every calendar key is now type-checked at
  startup.
- **The read-only guard was a denylist**, and it missed `calendar.events.owned`,
  `calendar.app.created` and `calendar.acls`, all of which can write. It is now an allowlist
  over every `server/*.py`.
- **The contract test would have printed an event's title on failure.** `assertIn` puts the
  container in its message, and its docstring promised the opposite. Its last assertion also
  passed with zero rows.
- **Sabotage: 6 of 6 mutants survived** the first suite: the tie-break, the tier order, the
  all-day end, the title ellipsis, the expiry margin, and the +12h all-day rounding. The fork's
  own second pass then ran 16 web mutants under TZ=UTC, and all 16 turned the suite red. A
  final pass here found one more survivor in the rotation's compare-and-swap, and a test now
  kills it.
- **`--disconnect` said "Google revoked the grant" when Google had answered 400.**

Declined, and why:

- **The device-code phishing** with the owner's public client id is documented in ADR 0017, not
  engineered away. One registration serving both a personal and a work account needs the
  multi-tenant public client, and the risk falls on a third party's calendar, not the owner's.
- **No file lock** between the server and `calendar_login.py`. The compare-and-swap covers the
  case that loses data, a disconnect being undone. The remaining race costs at most a re-login.

## What is not proven

- **No live response from either provider has been seen.** The fixtures are written from the
  references, and the contract test is the measurement, waiting on the owner's account. Two
  defences keep a wrong premise loud: a non-UTC Graph zone fails the account, and the contract
  test fails when the normaliser drops a kept event.
- **`check_layout.py` has not run**, for lack of Firefox. `measure.js` in headless Chrome is
  clean, with the Mac's fonts, not the phone's.
- Nothing has run on the phone. The APK needs one rebuild for `DataPayload`.

## Where the rework went

- **The task file prescribed an impossible flow.** It was checked against the docs before any
  code this time, which is the point of doing that first.
- **A `git checkout` of a fixture undid a regeneration** mid-wave: it restored HEAD's
  `payload.json`, which lacked `agenda`. It was caught by grep and regenerated.
- **Gradle skipped the JVM tests after the fixture changed**, because the fixture was not
  declared as an input. `make check` was green without running them. It is fixed, in its own
  commit.
- **The security lens toggled this Mac's speakers four times** while testing the Host check on
  a scratch server. The example config ships with actions on. Nothing is broken, but a lens
  that starts a server should be told to set `actions = []`.

## Cost

One owner prompt for the wave, plus three answers in plan mode. Tokens were not measured. There
were 10 subagents: 2 docs checks, 1 fork (resumed once), and 7 review lenses.
