# Wave 21 — the twins were never twins

The recommendation had stood since wave 19 and was the oldest row in the table: **T0.6**, the
task written after the fact for a setup that arrived whole in PR #1. One task, and the wave
stayed at one on purpose — the next candidate, T3.6, needs an APK in `out/` for its 200, which
needs Docker, which is not on this boot.

## What ran

**T0.6**, on `wave/21-pinning-the-second-agent`, PR
[#30](https://github.com/boscocp/desk-panel/pull/30): +466 / −17 across seven files, one of
them new.

Four things the task file asked for, and a fifth it did not:

1. `default_model`, the provider block and `context_window` pinned in `reasonix.toml`, out of an
   untracked global config.
2. `Bash(git commit*)` and `Bash(git push*)` denied to the local agent.
3. The keystore hole closed — `forbid_read` listed the config and `keystore.properties` while
   `[permissions]` allowed `Bash(cat:*)`, so the local agent could read a keystore Claude could
   not. `*.keystore`, `*.jks` and `.env` join it.
4. The allow lists counted against what the acceptance blocks run, rather than guessed.
5. `make lint-parity`, which the task file did not ask for. A check nobody runs is the sentence
   it was written to replace.

### The number the checker produced on its first run

`scripts/check_permission_parity.py` against the pair **as it stood on `main`**: 23 asymmetries.
That is the finding of the wave, and it was not a surprise about one rule — it was that the
files had almost no overlap in the inspection block at all. `ls`, `cat`, `grep`, `head`, `tail`,
`wc`, `rg`, `find`, `tree`, `file`, `which`, `pwd`, `diff`, `git show`, `git branch` and both
`python3` variants were allowed to Reasonix and to nobody else.

The line worth keeping is the last one it printed:

```
Read(*.keystore): in .claude/settings.json deny, missing from reasonix.toml
```

That is step 3 of the task file — a paragraph of prose arguing that the keystore was readable by
the wrong agent — arriving as one line of output from a script that had never read the task
file. The prose and the check agree, which is the only reason to trust either.

### Counting the allow list against the acceptance blocks

The gap the parity check *cannot* see: a command missing from **both** files is symmetric and
therefore silent. So the criteria were parsed — every `## Acceptance` block in `tasks/`, split on
shell separators — and the commands ranked:

| command | criteria | allowed before |
|---|---:|---|
| `check_layout.py` and the other `e2e/layout` checkers | 33 | no |
| `adb shell` | 29 | no |
| `sleep` | 27 | no |
| `probe.py` | 24 | no |
| `curl` | 2 | no |

`sleep` is the one that matters. Twenty-seven criteria start something, wait for it to settle,
and then assert — an approval prompt halfway through a sequence like that does not fail the
task, it strands it.

`adb reboot` was deliberately **not** granted: T2.4 reboots a device whose MIUI permissions cost
a session to grant.

## What the review found

**Seven findings, seven applied, none declined.** One of them is the wave.

### The wave put the hole back on the other side

Finding 1, and it is the only one that mattered: reaching parity meant adding `Bash(cat *)`,
`grep`, `head`, `tail`, `rg`, `find` and `diff` to `.claude/settings.json` — and Claude Code's
rules are per-tool, so a `Read(./.env)` deny does not stop `cat .env`. **Sixty lines apart in
one diff, the same change added deny rules for the secrets and auto-approved the command that
reads them.** Step 3 of the task file exists because `forbid_read` listed the config "while
allowing `Bash(cat:*)`"; the fix for that sentence re-created the sentence on Claude's side.

The cause was one wrong assumption, and it is worth more than the code: **every asymmetry was
treated as drift.** It is not. Reasonix can allow `Bash(cat:*)` safely *because* `[sandbox]
forbid_read` blocks the secret files underneath it. Claude Code has no such layer. That is a
difference in what the two harnesses can do, and the right place for it is the exemption
mechanism with the reason attached — not repair. Ten exemptions now, up from three, and seven
of them are that one fact.

A parity script whose author reasons "make them the same" will keep finding this. The
docstring now says so where it will be read.

### What the checker could not see about itself

- **Finding 2** — a `Read(...)` rule written into `reasonix.toml`'s permission list was
  happily paired with its `settings.json` twin, although the script's own docstring says such
  a rule is silently inert there. Move `server/config.json` out of `forbid_read` into a
  `Read(...)` deny and the token is readable by `cat` again with the gate still green. The one
  class of asymmetry the script was written to catch, re-introducible without it noticing. Now
  refused outright.
- **Finding 3** — parity markers were run through the same normaliser as rules, which strips
  the trailing `*`, so `Bash(docker *)` as a marker matched only the literal command `docker`.
  A family marker covered nothing *and* reported itself stale. The existing markers happened to
  work because `Bash(git commit*)` normalises to exactly the key it must match.
- **Finding 4** — a bare `WebSearch` or an MCP rule (`mcp__playwright__browser_navigate`) is a
  legal Claude Code entry, and both returned `None` from the parser, which made the script exit
  **2** and took `make check` down with it. A gate that goes red when someone adds an unrelated
  permission is a gate that gets deleted.
- **Finding 6** — `Bash(adb devices)` is an exact match in Claude Code and `Bash(adb devices:*)`
  a prefix in Reasonix, and both reduce to one key, so `adb devices -l` prompts on one side and
  not the other while the check calls them paired. Documented as a limitation rather than fixed.
- **Finding 7** — step 4 of the task file named `make connected` and it was not added to either
  file. Added.

### The fixes were themselves wrong twice, and the selftest said so

Applying findings 3 and 4 broke the selftest in two ways at once: bare-name markers were still
unmatched, because `MARKER_RE` required parentheses that `WebSearch` does not have, and the
stale-marker message had changed shape. Both came back as named failures rather than as a
silent pass:

```
check_permission_parity: SELFTEST FAILED
  did not report: Bash(nothing): exempted
  reported a rule that is paired or exempt: WebSearch()
```

That is the argument for `--selftest` in one screen, and it was the unplanned fifth item of the
wave. It was also checked the other way, before any of this: gutting `compare()` with an early
`return problems` makes the selftest exit 1 and name all three drifts it failed to find.

## What is not proven

- **The pinned provider has never been observed resolving.** T0.6's fourth acceptance line,
  `reasonix run --dir . --permission-mode read-only --max-steps 5`, needs Reasonix and Ollama and
  neither is on this Windows boot. The row is `blocked` on that half, the same shape T3.8 and
  T3.9 carry. Three of the four lines pass here.
- **Whether `forbid_read` expands globs is unverified**, for the same reason. The entries are
  listed both as globs and by concrete name — redundant if it does, load-bearing if it does not.
  `docs/LOCAL-MODELS.md` says how to settle it: a decoy in `desk-panel.keystore`, a `cat`, and
  delete whichever half did not bite.
- **`make check` was not run, because there is no `make` on this host** — deliberately, by the
  same ADR 0003 argument that keeps the JDK off it, and `after_update.py` already says so in a
  comment. The targets' commands were run individually, which means `make lint-parity` itself is
  **unexercised as a Make target**; only the two commands inside it have run.
- **Neither is Docker.** `make test-android` did not run. The wave touches no Android code.
- **The parity check has only ever been run against one pair of files.** Its `--selftest` covers
  the comparison with fixtures, but the normalisation of Reasonix's dialect is checked against
  this repository's `reasonix.toml` and nothing else.
- **Whether Claude Code accepts `Bash(python scripts/*)` and `Bash(curl -sf http://localhost:8777/*)`
  as written was not tested by running them.** They are the shapes its documented prefix
  matching takes, and if either is wrong the failure is a prompt, not a breach.
- **The seven exemptions are an argument about Claude Code's permission model, not a
  measurement.** That `Bash(cat *)` defeats a `Read(...)` deny follows from the rules being
  per-tool; nobody here put a decoy in `.env` and watched `cat` return it.

## Where the rework went

One place, and it was caught by the machine rather than by reading:

**The first draft of the `STATUS.md` row claimed 27 asymmetries.** The number was written from
memory of the `sleep` count — 27 acceptance criteria — and the two had nothing to do with each
other. Running the checker against `git show HEAD:` copies of both files gave 23, and the row was
corrected before it was committed. The lesson is small and exact: a count that came out of a
program should be pasted from the program, and this repository's own rule — *every criterion is
a command with an exit code* — applies to the numbers in its prose too.

The second thing that would have been rework and was not: the checker was run before the
`WebFetch` markers were written, so its first real output was five failures naming the five
domains. The exemption mechanism was tested by needing it, one minute after it was written.

## Cost

Not measured, and there is nothing honest to put here. The wave was one Claude Code session
against a warm checkout; no trajectory, no token count, no wall clock was recorded. The gap is
the one the harness-notes README already names for every wave: *instrumented — no, and that is
the open gap.*

One prompt from the chair — *faz a proxima onda* — plus two mid-turn questions, both about the
same thing: why Windows could not finish the acceptance.
