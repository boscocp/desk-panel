# Wave 42 — the volume rides the spectrum stream

The wave began as a validation, not a request for code. The owner asked for the first Windows run
of wave 40's volume bar, wave 41's spectrum, and the agenda's change to external calendars ("o
apk ta atualizado e testado no mac, vamos validar ele no windows"). The validation found the bar
three minutes behind the MCHOSE knob. The owner chose the recommended fix, which is T8.6.

## What ran

**The Windows validation**, before any code:
- **Spectrum:** `spectrum-tap.exe` did not exist. `install_task.ps1` had not been re-run since
  wave 41, so the helper was compiled by hand with `csc.exe`. After a restart: `rate=24000`, real
  bars from the owner's Fluxer audio, and no console window.
- **Volume:** the PowerShell read follows the default output (the MCHOSE V9 PRO). The owner
  first moved a slider the server does not read, and listing every endpoint's level showed why.
  After that the MCHOSE at 51 % read 51, about 70 s late.
- **Agenda:** after the restart it failed with `google did not grant ...calendarlist.readonly`.
  The Windows token predated ADR 0019. The owner signed in again and the next 300 s cycle brought
  the events back, with no restart.

**T8.6**, [ADR 0021](../adr/0021-the-spectrum-is-a-stream.md)'s amendment:
- the Windows helper reads `IAudioEndpointVolume` on the device it captures and writes
  `v=<level>` on stderr;
- the hub drains stderr, and sends the level down `/spectrum` on opening and on change;
- the phone validates the line as an `int` and moves only the bar.

**Measured on the Windows PC, server side:** 45 `v=` lines in 90 s while the owner moved the
slider, sub-second (`100 → 81 → 77 → 63 → 47` within one second). CI ran `./gradlew test` and
`assembleDebug` green. This PC has no Docker, and ADR 0003 forbids installing the toolchain.

## What the review found

One fresh-context agent reviewed the first commit read-only. It compiled the helper into the
scratchpad, checked the vtable against `endpointvolume.h` slot by slot, and ran a scratch hub.

| Severity | Finding | What happened |
|---|---|---|
| Medium | **A stale level opened every stream.** On macOS and Linux only the phone's sets ever fed the hub, and nothing cleared the level. So after a set to 30 and a knob turned to 70, each reconnect drew 30 again. The agent reproduced it with a parec-like source. | Fixed. `reports_volume` (Windows only) gates the wiring, and the level is forgotten when the source closes. |
| Low | The owner was called after the hub's lock was released, so two threads could leave `/quotes` on the older level. | Fixed. Now called under the lock. |
| Low | On the phone, a stopped stream's late post could swallow the next stream's first level. | Fixed. The generation now travels with the level. |
| Low | The helper reads the *console* role while the PowerShell read uses *multimedia*. Helper complaints are logged on every restart. | Recorded, not changed. The roles differ only on split defaults. |

## What is not proven

- **The bar on the phone.** It needs this wave's APK, built in Docker on the Mac. Until then the
  installed APK drops the `v=` line and the bar follows `/quotes` as before.
- **macOS and Linux** get nothing new. Their sources report no level. The Swift helper could do
  the same read, but it was not written, because nothing here can build or run it.
- The ordering test for the second finding passes with or without the fix on this machine. It
  documents the rule rather than proving it.

## What it cost

One session with the owner at the desk. The validation took longer than the code: three
problems, each found by reading the server log and then asking the machine directly (endpoint
volumes, the token's scope) rather than guessing. The review cost one agent and about three
minutes, and found the one bug the unit tests had been written around.
