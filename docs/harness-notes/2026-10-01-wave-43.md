# Wave 43 — Linux puts the volume on the stream too

Like wave 42, this one began as a validation and not a request for code. The owner asked to
rebuild the APK, sign in to Google for the agenda, and try waves 40–42 on CachyOS ("eu atualizei
bastante coisa, precisamos regerar o apk e fazer login no google pra pegar dados da agenda e
testar as novas funcionalidades aqui no cachyos"). The run closed three open lines and found one
real gap, reported from the chair: "o spectrum ta funcionando, a sincronia de barra de som n".
That is T8.7.

## What ran

**The CachyOS validation**, before any code:
- **The APK.** `assembleRelease` in Docker, 16 s, signed with the release key (`CN=bosco`,
  confirmed with `apksigner --print-certs` rather than assumed), installed with `adb install -r`.
  Never uninstalled: the MIUI grants do not survive it.
- **Google Calendar.** `calendar_login.py google --account personal --no-browser`, the owner
  approving in the browser on the same machine. Both ADR 0019 scopes granted, token written
  0600. The AGENDA card drew a real event.
- **Spectrum and volume bar on CachyOS**, both of which T8.5 and T8.4 still had as "not
  measured". Both work. The bar is the one that did not *follow*.

**Two things the validation got wrong before it got them right**, both worth keeping:
- The payload was missing `agenda`, `volume` and `b3Open` on a checkout that plainly had them.
  Not a bug: the systemd **user** unit had started at 23:58:49 and the files were written at
  23:59:13, so the process was serving code 24 s older than the tree, silently and with nothing
  in the log. Diagnosed by comparing the source mtime with `ActiveEnterTimestamp`.
- `weather` was reported as "missing from the payload". It was never in it — `/weather` is its
  own endpoint. The claim was made before checking and then withdrawn.
- The CÂMBIO and CRIPTO cards looked clipped in the first screenshot. A second capture 23 s
  later showed different rows: it is the rotation, not a layout bug. One screenshot was not
  enough to tell those apart.

**T8.7**, [ADR 0021](../adr/0021-the-spectrum-is-a-stream.md)'s second amendment:
- `ParecSource` keeps `parec` for the PCM and adds `pactl subscribe` for the *when*;
- the level itself comes from `actions.read_volume`, the same `wpctl get-volume` `/quotes` uses,
  so there is no second reader to keep in step;
- `reports_volume()` replaces the inline `sys.platform == "win32"` and is now the one place
  naming which platforms send a level.

**Measured here, both directions.** Before: zero `v=` lines across three knob movements. After:
`v=49` on opening, then `v=70`, `v=25`, `v=90`, `v=49` — one per movement, none in between, each
inside the same ~50 ms frame as the change. `/quotes` agreed at 90 and the Redmi's bar went from
4/10 to 9/10 segments.

**Two things were measured rather than assumed**, and the design would have been wrong without
either:
- **`pactl subscribe` line-buffers into a pipe.** If it had block-buffered, the whole
  event-driven approach would have delivered nothing until the process exited. Checked first:
  14 lines within 2 s of a pipe being opened.
- **One `wpctl set-volume` prints exactly one `Event 'change' on sink #57`**, while each
  application's own slider prints `sink-input #N`. That is the entire basis for `is_sink_event`,
  and the ` #` is what separates the two — `sink-input #` is not `sink #`.

## What the review found

One fresh-context agent reviewed the working tree read-only at `high`. It read `pactl`'s
binary for its format strings and measured its buffering itself rather than trusting the
comment. Five findings, all applied.

| Severity | Finding | What happened |
|---|---|---|
| **High** | **The watch ran in the session's language.** `pactl` binds the `pulseaudio` text domain and the line is the translatable `Event '%s' on %s #%u`, so with the language pack installed every event arrives translated, `is_sink_event` matches none, and the bar stops following the knob — silently, with no log line. The exact symptom the task exists to fix. | Fixed: `env=dict(os.environ, LC_ALL="C")`, pinned by a test. `actions._default_runner` has forced this on the same binary since T8.1 and explains why at length; this was the one place in the project parsing pactl text without it. |
| Medium | **The `on_volume is None` guard was dead code.** `Spectrum._capture` hands `note_volume` unconditionally, so it is never None in production. A Linux PC with `spectrum = true` but no `volume` action therefore started `pactl subscribe` and a `wpctl` per sink change against a mixer the owner had disabled — contradicting step 4, the ADR, and the comment beside it. The test passed only because it built a state the hub never produces. | Fixed in the hub: `_capture` now passes None when nothing wants a level, with a test for each side. |
| Low/Med | **A level in flight could outlive the source.** `_report` blocks in `wpctl`; `close()` cannot interrupt it. The hub clears a gone source's level on purpose, and a late answer put one straight back — so the next stream opened on a dead source's number. The same failure `note_volume`'s docstring records from wave 42's review. | Fixed: `close()` sets a flag first and `_report` checks it after the read. |
| Low | `" on server"` bare is unreachable — pactl always prints the index — so that assertion pinned a line pactl never emits. | Fixed: the test now uses the real `on server #4294967295`; the bare form stays tolerated, not expected. |
| Low | **A watch that died was silent.** stderr went to `DEVNULL`, so `pactl` exiting on `Connection failure` ended the thread with nothing logged, against what the ADR and SERVER-SETUP promise. | Fixed: stderr is captured and the end of the stream is logged once, with the complaint. |

The first finding is the one worth remembering: the feature worked on this desk, and would have
shipped working on this desk, because this box happens to run `en_US` and happens not to have
`pulseaudio.mo` installed. Neither is true of the owner's other machines.

## What is not proven

- **macOS.** Its bar is now the only one still following `/quotes`. The Swift helper would need
  the CoreAudio read; nothing here can build or run it.
- **The Windows slider against this wave's APK.** Wave 42's last line, unchanged: that needs the
  Windows PC.
- **A machine with `parec` but no `pactl`.** The fallback is covered by a unit test with `which`
  stubbed, not by a real box missing the binary — they ship in the same package.

## What it cost

One session with the owner at the desk, most of it validation rather than code. The gap itself
was already written down: T8.6's task file said "macOS and Linux still take the level from
`/quotes`", and its ADR bullet said "`parec` cannot". Both were accurate and both read as
closed. What they actually meant was that the level is not available *from the capture process*
— and nobody had asked whether it was available from somewhere else on the same machine. The
fix took less time than the three wrong turns in the validation above.
