# Wave 29 — the documentation cluster, and three guards that arrived already wired

**T7.4 + T7.5 + T7.6.** A stranger can now clone this repository, reach a moving panel with
nothing installed, find out which versions matter and why each one is the floor, and read what
will send their pull request back. Three documents, three new guard scripts, and a hook.

## What ran

**T7.4, T7.5 and T7.6**, on `wave/29-docs-cluster`, cut with `make wave-start` on a `main` that
was already current.

New: `docs/PHONE-SETUP.md`, `docs/RUNNING-LOCALLY.md`, `docs/REQUIREMENTS.md`, `CONTRIBUTING.md`,
a pull-request template, two issue forms, `.githooks/commit-msg`, and three scripts —
`check_links.py`, `check_requirements.py`, `check_commit_msg.py`. Rewritten:
`docs/INSTALL-PHONE.md` as the vendor half, and the README's Quickstart and Status.

Every acceptance command of all three tasks is green, and `make check` passes with the three new
guards in it.

## The trap set two waves ago closed by itself

Wave 25 wrote rule 5 of `check_ci_hygiene.py`: `make check` reaching a `scripts/check_*.py` that
no workflow runs is a failure. So the three guards landed in the Makefile **and** in `lint.yml`
in the same commit, because the alternative was a red build. Nobody had to remember two lists,
which is exactly what the rule was written for — the second time now that a guard has paid for
itself in a wave whose author had forgotten it existed.

The same shape held for `lint-selftests`, which discovers self-tests by grep over `scripts/*.py`:
all three new scripts grew a `--self-test` and were covered by being written.

## Each self-test caught a defect in its own script

Worth recording, because they were all written before any document used them:

- `check_requirements.py` read a table's `|---|---|` separator as a row named `---`.
- `check_links.py`'s self-test printed a wall of stderr about a domain that does not exist,
  because it asserted on `report()`'s exit code and `report()` also prints.
- `check_commit_msg.py` **refused `/dev/stdin`**, which is a pipe and not a file — the exact
  invocation T7.6's own acceptance block uses to demonstrate the script. A checker that rejected
  the way its own documentation calls it.

## What the review found

Eight, all fixed, and **the two that matter most are in the prose rather than the code** — which
is the right result for a wave whose product is prose, and is not where the attention had been.

- **The Quickstart was macOS-only, inside the block that promises "nothing installed".** `open
  web/index.html` is nothing on Linux and nothing on Windows, and `make check` sat in the same
  block while `REQUIREMENTS.md` says it wants Python, Node and Docker. A stranger runs three
  lines and the third fails. The irony is exact: `RUNNING-LOCALLY.md`, written in the same wave,
  already printed all three forms — the README was the file nobody re-read.
- **The troubleshooting table recommended the thing that causes the symptom.** *"The panel is
  blank → serve the directory: `python -m http.server -d web`."* `mock.js` returns immediately
  unless `location.protocol === 'file:'`, so over `http:` the feed is inert: the reader gets a
  page that loads, a clock that ticks, and empty rows for ever. Written by somebody who had read
  that guard in the same session and did not connect it.
- **A rate limit would have reported a live page as a dead link.** `check_links.py` bucketed
  every non-2xx as `dead` and exits 1 on those, and CI runs the remote half from a shared runner
  address against six `developer.android.com` pages. The first 429 or 502 reddens somebody's pull
  request with "1 dead link(s)" about a page that is fine. The script had already separated
  `unreachable` from `dead` **for exactly this reason** and then did not use it — 429 and 5xx are
  `unreachable` now, 410 is still dead.
- **`git commit -v` would have failed on the content of the diff.** Git appends the diff below a
  scissors line and those lines are not `#`-comments, so they reached the body scan — and
  committing any edit to a file containing a line that starts `Co-Authored-By:` fails with "no
  attribution trailers". In a repository whose harness notes discuss that trailer, that is not
  hypothetical.
- **The hook picked a different interpreter from everything else here.** `python3`, where the
  Makefile, both workflows and both documents say `python` — and on Windows `python3` is usually
  the Store alias, which exits without running anything. `make hooks` would succeed and then
  every commit would fail, on the platform where `make check` is green.
- Three latent ones, each fixed with a self-test: inline code spans were not excluded from link
  matching (so documenting the checker's own syntax would report a dead link), `|` rows inside
  fenced code could shadow a real requirements row, and `--timeout soon` raised a traceback
  instead of the documented exit 2.
- And one the review found by reading rather than running: `CONTRIBUTING.md` sent contributors to
  `android/CLAUDE.md` four paragraphs before telling them those files "are not documentation and
  you never need to read them". It points at `docs/ARCHITECTURE.md` now.

The pattern across the eight: **the guards were reviewed as code and the documents were not
reviewed at all** by the person writing them, and the two worst findings are instructions a
reader would follow and fail. A document is an interface, and this wave shipped it with less
adversarial reading than a function would have got.

## The link checker's first real run found the split it was written for

`docs/INSTALL-PHONE.md` had **two step 6s**: the vendor's battery list and Android's battery
optimisation exemption, numbered identically since the day they were written — and those are the
exact two the document's own prose warns are constantly confused. Nobody reading it had noticed,
including every session that has edited that file. It is one list of seven now.

The checker also found the thing worth knowing before T7.7: **GitHub answers 404, not 403, for a
private repository's pull requests.** An anonymous checker cannot tell "deleted" from "not
yours", and the harness notes and task files are full of such links. Hence the split: `make
check` runs the local half over every Markdown file in the repository, and CI runs the full half
over the documentation a reader actually follows. When the repo goes public the distinction
disappears and CI's list should widen to `MARKDOWN`.

## The rule that took three cuts: Title Case

`check_commit_msg.py` rejects shape, never content, and the one shape rule with judgement in it
is "not Title Case". Three attempts:

1. **The first letter must not be capitalised.** Fails on `fix: MIC mutes every input` and
   `fix: POST alone does not keep a web page out` — both real subjects, both acronyms.
2. **Two or more capitalised words.** Fails on `feat(android): PcPoller, the panel's only network
   code` and `feat(server): make the login signal work on Linux, macOS and Windows` — proper
   nouns, and normal English.
3. **Density: two or more, and at least half the words.** Title Case capitalises the function
   words too, which is what makes it Title Case. Passes the whole history bar the pre-convention
   squash merges; rejects the task file's own example.

The reasoning is written into the code because the cost is asymmetric, and that asymmetry is the
transferable part: **a false positive teaches a contributor `--no-verify`, and after that the
hook checks nothing at all.** A missed `feat: Add a thing` costs a moment of inconsistency. When
a lint rule is a judgement call, tune it towards letting things through.

## A new task, asked for mid-wave

*"tem alguma onda de revisao do codigo, que ve se precisa de algum design pattern, boas praticas
etc, inversao de dependencia, desacoplamento etc? pensando na contribuicao externa?"*

There was not one. `/code-review` reads a diff; T7.6 writes the rules down; nobody reads the
whole codebase asking whether they are true. **T7.9** now does, scheduled after T7.6 and before
T7.3 — the guide is the yardstick, and a review run before it would have been one person's
taste. The task file spends as much room on what it is *not* (a pattern hunt, a framework, a
rewrite) as on what it is, because that is the failure mode available to a task with this title.

## What is not proven

- **Neither document has been read by a stranger**, which is precisely the manual check both
  tasks ask for and the one thing that cannot be faked from this desk. The defect they are meant
  to find is invisible to the person who wrote them.
- **The commit hook has never rejected a real commit.** Installed here, exercised against the
  history and the self-test, never hit in anger.
- **The issue forms have never been rendered.** GitHub parses them server-side and a schema
  mistake shows up only in the UI.
- **The README's Status section was rewritten from memory of the repository, not from a run.**
  T7.3 owns the final pass and screenshots.
- macOS mute, the twenty taps, the phone on adb: all carried, all unchanged.

## Cost

Two prompts. The second one changed the shape of phase 7 by adding T7.9, and arrived mid-wave —
which is the second time in three waves that the most useful input has been a question rather
than an instruction.
