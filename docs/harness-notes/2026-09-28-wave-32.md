# Wave 32 — a guard that reads the label, and a self-test nothing ran

Two checks that existed and did not check. `check_harness_notes.py` asserted three headings were
*present* in a wave note and never read what was under them; `make lint-selftests` discovered
self-tests by globbing one directory in a repository that has two. Neither could have gone red
for the thing it was written to catch.

## What ran

**T10.4** and **T10.3**, on `wave/32-guard-reads-the-label`, cut with `make wave-start`.

- `scripts/check_harness_notes.py`: a required section now has to survive having its HTML
  comments stripped and reach twelve words. It gains a `--self-test` — fifteen cases, one per
  rule plus the fence, comment and duplicate-heading handling, every one of them hermetic. It
  shipped with a sixteenth that read this repository, and the review deleted it; why is below.
- `Makefile`: `SELFTESTS` globs `scripts/*.py server/*.py`, which brings
  `server/verify_login_scope.py --self-test` and its 97 autostart-parser cases into `make check`
  for the first time. `e2e/` is deliberately still out, and the recipe comment says why.
- `docs/harness-notes/README.md`: what a section has to carry, and why the guard is red while a
  wave is still being written.

Acceptance, all four lines of T10.4 and all four of T10.3, exit 0 — **after the review**, and the
first version of this paragraph said so before it was true. See below.

`make check` is green on the finished note: 362 server tests, the web suite, the Android JVM
suite, every guard, nine self-tests. While the note was still a placeholder it was red on
`check_harness_notes` alone, which is the design.

## The floor is measured, not chosen

The hard part was not detecting a placeholder, it was deciding what counts as written without
teaching anyone to pad. The number came from the record: the sixteen wave notes were measured,
the smallest required section in any of them is 37 words (`## What ran`, wave 16), and the floor
is set at twelve — a third of the smallest honest section anybody has written here, and still
clear of the shortest one the README explicitly sanctions, a wave with nothing outstanding saying
so in one line. The reason is in the code beside the constant, because a number without its
derivation is the next person's coin flip.

## The task file argued from one instance; the record holds two

T10.4 was filed off wave 30's note, and wave 31's resume section claimed it had happened again.
That was checked rather than repeated — `git show` on the first commit of each note — and both
carry `<!-- filled in after the review runs -->` verbatim. One command, and the difference
between a guard written for an anecdote and one written for a pattern.

## What the review found

Six findings, all six applied. The first one is the wave's own lesson arriving inside the wave.

**The self-test was coupled to the repository, and it broke the other task.** The last case
asserted *this repository's own notes pass*. But the design says the guard is red from the moment
`STATUS.md` gains a wave's section until that wave's note is finished — so the case was red for
the whole of every wave, `lint-selftests` stopped at the first red script, and
`server/verify_login_scope.py --self-test` never ran. T10.3's first acceptance line,
`make lint-selftests 2>&1 | grep -q 'verify_login_scope'`, exited **1** on the pushed branch. The
case passed when it was written, because `STATUS.md` did not yet carry wave 32; adding the resume
section is what turned it red, three commits later.

A self-test answers whether the code is right. `make lint-notes` answers whether the notes are.
Mixing them made T10.4 silently delete T10.3, and the comment where the case used to be says so.

**The note claimed a result it did not have.** "Acceptance, all eight lines, exit 0. `make check`
green" was written while `make check` was red — in a wave whose entire subject is checks that
report the wrong thing. Part of that redness was the deliberate kind and part of it was the bug
above, and the paragraph distinguished neither. It does now, and it keeps the false sentence's
correction rather than quietly replacing it.

**`lint-selftests` stopped at the first failure**, so one red script hid every later one — the
same "a self-test no target runs" failure the recipe's own comment is written against, arriving
through the back door. It now runs all nine, collects the failures and exits at the end, and the
list is sorted because `grep` emits directory order. Proved by dropping a deliberately red script
into `scripts/`: the loop reached `server/verify_login_scope.py`, printed 97/97, and the target
still failed naming the red one.

Three smaller ones in the parser, each a way the guard could report the wrong thing:

- **A fence closed with the wrong delimiter.** One boolean for both ``` and `~~~` meant a `~~~`
  line inside a ``` block closed it early — and worse, an odd number of fence-looking lines left
  the rest of the file inside a fence, so every later heading disappeared and the guard would
  report `no ## What is not proven heading` for a note where it is plainly there. A fence now
  closes only with the delimiter that opened it.
- **A heading written twice kept only the last body**, so a note whose second `## What ran` is a
  one-line pointer would fail on the pointer while the real section above it went unread. Both
  bodies are kept.
- **The success line counted heading occurrences, not waves**, and re-read `STATUS.md` to do it.
  A duplicated `## Resuming after` section — a hand-edited file, every wave — would have
  overstated the count. One parse, a dict, one number.

Two of the six are the same shape as the defect the wave was written to fix: **a check whose
green does not mean what its label says.**

## What is not proven

- **The floor is defensible, not validated.** Twelve words is right against the sixteen notes
  that existed today. If a later note is honestly shorter than a sentence and the guard fires,
  the floor is wrong; lowering it is the fix and padding the note is not.
- **Only the three required headings are read.** `## Where the rework went` and `## Cost` are
  still "expected wherever there is anything to say" and nothing checks them — correctly, since
  a wave may have nothing to say under either, but it means a note can still be thin overall.
- **`check_status.py` and `check_acceptance.py` read structure the same way.** T10.4's own notes
  section flags them and they were left alone, which keeps this wave reviewable.
- **`lint-selftests` not stopping early is proved once, by a throwaway.** A deliberately red
  script was dropped into `scripts/`, the loop was seen to continue and the target to fail, and
  the script was deleted. Nothing in the repository holds that property from now on.
- **Widening the glob was verified by running it, not by reasoning about safety.**
  `server/verify_login_scope.py --self-test` costs milliseconds over fixtures and reaches no
  network; the next script that appears under `server/` with a `--self-test` inherits that
  assumption without anybody deciding it.
- Carried unchanged: `server/config.json` is still mode 0644 with the brapi token in it, the
  Windows installer's TOML branch has still never been run, macOS mute and the twenty taps are
  still desk-only.
