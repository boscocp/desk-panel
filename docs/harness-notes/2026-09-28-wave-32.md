## The floor is measured, not chosen

The hard part was not detecting a placeholder, it was deciding what counts as written without
teaching anyone to pad. The number came from the record: the sixteen wave notes were measured,
the smallest required section in any of them is 37 words (`## What ran`, wave 16), and the floor
is set at twelve — a third of the smallest honest section anybody has written here, and still
clear of the shortest one the README explicitly sanctions, a wave with nothing outstanding saying
so in one line. The reason is in the code beside the constant, because a number without its
derivation is the next person's coin flip.

## What is not proven

- **The floor is defensible, not validated.** Twelve words is right against the sixteen notes
  that existed today. If a later note is honestly shorter than a sentence and the guard fires,
  the floor is wrong; lowering it is the fix and padding the note is not.
- **Only the three required headings are read.** `## Where the rework went` and `## Cost` are
  still "expected wherever there is anything to say" and nothing checks them — correctly, since
  a wave may have nothing to say under either, but it means a note can still be thin overall.
- **`check_status.py` and `check_acceptance.py` read structure the same way.** T10.4's own notes
  section flags them and they were left alone, which keeps this wave reviewable.
- **Widening the glob was verified by running it, not by reasoning about safety.**
  `server/verify_login_scope.py --self-test` costs milliseconds over fixtures and reaches no
  network; the next script that appears under `server/` with a `--self-test` inherits that
  assumption without anybody deciding it.
- Carried unchanged: `server/config.json` is still mode 0644 with the brapi token in it, the
  Windows installer's TOML branch has still never been run, macOS mute and the twenty taps are
  still desk-only.
