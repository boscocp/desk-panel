# Wave 21 — the setup that had never been a task

## What ran

T0.6, on `wave/21-the-two-agent-setup`, PR #27. The oldest row in `STATUS.md` that was not
`done`, and the one that had carried the `⬅ start here` marker since the bootstrap session on
2026-09-13: the two-agent arrangement itself — `reasonix.toml`, `.reasonix/skills/verifier/`,
`docs/LOCAL-MODELS.md` — which arrived whole in PR #1, outside the task system it was meant to
live inside. Ten days and nineteen waves later it was still the next thing in the table and
still never the thing anyone picked.

**It was wave 20 until the merge.** A second session was working in this same checkout at the
same time and merged its own wave 20 — PR #25, `scripts/after_update.py` — while this branch was
open, so the number was taken and the collision surfaced as a conflict in `STATUS.md` rather
than anywhere earlier. Two sessions can share a worktree here; two sessions cannot share a wave
number, and nothing in the protocol allocates one.

Renaming the remote branch to match the new number **closed the open pull request**: GitHub
does not retarget a PR whose head branch is renamed away, it closes it. PR #26 is that
casualty and PR #27 is this wave. Worth knowing before doing it again on a branch anyone
has reviewed.

What landed:

- `default_model` and a `[[providers]]` block in `reasonix.toml`. The provider had been in an
  untracked `~/.reasonix/config.toml`, so nothing about "it worked on this machine" was
  reproducible from a clone, or reviewable in a diff.
- `git commit` and `git push` moved from *allow* to *deny* for the local agent. ADR 0011 says
  git belongs to the reviewing side; the file had said the opposite since PR #1.
- `scripts/check_permission_parity.py`, wired into `make check` as `lint-permissions`.
- The keystore closed on the Reasonix side, `curl`, `keytool`, `adb shell`, `adb install`,
  `make lint-*`, `make connected` and `python scripts/*.py` added to both files.

A second, unrelated commit on the same branch: `WINDOWS-NEXT-SESSION.md`, a triage list for the
Windows box, which did not start the server at logon. Nothing about it was diagnosed here — see
the section below.

## What the review found

**Six, all applied, none declined.** The first two are the ones worth reading, and both are the
same failure: a check that was green about something it could not see.

1. **The new checker could not see the guard it was written to protect.** Exemptions were keyed
   by rule alone, and one declaration silenced every comparison that rule appeared in. `git
   commit` is asymmetric *twice* — Claude allows it and Reasonix does not; Reasonix denies it
   and Claude does not — so deleting `Bash(git commit:*)` from `reasonix.toml`'s **deny**, which
   is the whole of ADR 0011's guard against the local model committing unverified work, left the
   allow-side difference behind and the check still exited 0. The reviewer ran the mutation
   rather than arguing it. Exemptions are now keyed by `(list, rule)` and the declaration names
   its list; the same mutation now exits 1, as a stale exemption.

   `git push` alone *was* caught, which is exactly why this was invisible: the obvious half of
   the obvious test passes.

2. **`make lint-permissions` was allowed by neither file.** This wave added the target, and
   `CLAUDE.md` now tells both agents that it fails when the two files drift — and with
   `mode = "ask"` the local agent stops at an approval prompt on the one command the wave exists
   to make routine. Both files agreed, so the new checker was green about it. A parity check
   cannot find a rule that is missing from both sides; only reading the diff can.

3. **`Bash(keytool *)` was unprompted and unscoped.** `keytool -delete` or a second
   `-genkeypair` over `desk-panel.keystore` destroys the release signing key, and the
   consequence is documented in six places in this repo: a differently-signed APK cannot install
   over the one on the phone, the only way out is an uninstall, and an uninstall throws away the
   MIUI autostart and battery grants T2.4 spends a session obtaining by hand. Narrowed to
   `keytool -list` and `keytool -printcert`. Creating the key is a human step in T7.1 and now
   prompts, correctly.

4. **`Bash(adb shell *)` reached `pm uninstall dev.bosco.deskpanel`** — the same loss as above,
   by a shorter path. The acceptance blocks and docs use eight subcommands between them (`am`,
   `appops`, `cmd power`, `dumpsys`, `input`, `ping`, `settings`, `svc`); those eight are granted
   and nothing else is.

5. **The keystore's write side was still open.** The wave closed the *read* hole and left
   `Edit`/write on `*.keystore` allowed in both files. An agent that cannot read the signing key
   can still truncate it, with the same unrecoverable outcome. `Edit(*.keystore)` is now denied
   on both sides.

6. **The marker matched anywhere in a comment**, so the header of `reasonix.toml` — the sentence
   that *explains* the mechanism — was already being parsed as an exemption block. It named no
   rules, so it was inert; pasting the documented example into it would have created live
   exemptions with no rule in sight. The marker is anchored to the start of a comment now.

Findings 3, 4 and 5 are one shape: **this wave granted command families where the acceptance
blocks use prefixes**, and each family contained an irreversible operation one character from
the useful one. T0.6's step 4 now says so, because the next task to add a command will read the
task file and not this note.

## Where the rework went

Two of the five acceptance lines in the task file were wrong, and both were wrong in the same
way: they described a harness from the outside.

- `reasonix run --permission-mode read-only` — there is no such mode. The list is
  `manual | ask | auto | acceptEdits | dontAsk | plan | bypassPermissions`, and `plan`, the one
  that means read-only, answers `--permission-mode plan requires an interactive session`. The
  task file had been written in Claude Code's vocabulary.
- `forbid_read` was assumed to take globs, because the file it is paired with does. The task
  file was at least honest about not knowing — *"verify whether `forbid_read` accepts globs; if
  it does not, list the file"* — which is the only reason the hole got closed.

Both were settled in about a minute each, by a fixture rather than by reading: a decoy
`a.keystore` in a scratch directory, one Reasonix run with `forbid_read = ["*.keystore"]` (the
decoy printed) and one with the literal name (`Permission denied`). The generalisation is the
one wave 19 paid much more for, in a different key: **when the claim is about a tool's own
behaviour, build the two-line fixture.** The docs describe intent; the fixture describes the
code.

The keystore hole is worth naming on its own. `.claude/settings.json` has denied
`Read(./*.keystore)` since T7.1 while `reasonix.toml` allowed `Bash(cat:*)` and listed neither
keystore — so the *less* trusted agent, the one that has been measured narrating work it did not
do, could read the release signing key, and the more trusted one could not. It had been that way
for seven days. Nothing found it because nothing compared the two files; that is exactly what
the parity check now does, and it reported 21 asymmetries on its first run.

## What is not proven

- **The `Bash(cmd *)` spelling in `.claude/settings.json` has never been tested.** Claude Code's
  documented form is `Bash(cmd:*)`; this file has used the space form since the bootstrap and
  every rule in it is inherited. If that form does not match, several of these grants are inert
  and the only symptom is an approval prompt nobody reads as a bug. The parity checker treats
  the two spellings as equal **on purpose** — it is asking what a command may do, not how a
  harness punctuates — so it cannot catch this and is not the place to.
- **A parity check cannot find a rule missing from both files.** Review finding 2 was exactly
  that: the wave's own `make lint-permissions` was allowed by neither side, and the checker was
  green about it because the two files agreed. The gate has a blind spot the size of its own
  premise.
- **`curl`, `keytool` and `adb shell` are granted at prefixes, not as families**, and the
  prefixes are every use in the repository *today*. A different flag order, or a ninth `adb
  shell` subcommand, prompts. That is the intended behaviour and not a defect, but it will look
  like one the first time it happens.
- **The parity check compares command families, not exactness.** `Bash(adb devices)` and
  `Bash(adb devices:*)` are one rule to it. A genuinely narrower grant on one side therefore
  reads as in step; if that ever matters it is a change to `normalise()`, with a reason.
- **Nothing here was run by the local model.** The wave was about its configuration and Claude
  executed all of it, so this note has no pass@1, no trajectory and no completion-report check.
  The first dispatch under the pinned config is still ahead.
- **The Windows autostart failure is undiagnosed**, and no Windows machine is reachable from
  this side. `WINDOWS-NEXT-SESSION.md` is a list of questions with exit codes, not a finding.
  Its first hypothesis is the one the repo already documents: T3.12 moved config to TOML on
  2026-09-20, one day after the Scheduled Task was registered with an absolute
  `--config …\server\config.json` in its action, and deleting that file makes the server exit 1
  at every logon under `pythonw` with no console to say why.
- `server/config.json` is still mode 0644 with the brapi token in it. Carried from wave 19,
  still one `chmod 600`, still not done. T7.3 wants it.

## Where this wave collided with another one

The other session's wave 20 is worth reading beside this one, because the two waves found the
same class of thing from opposite ends. It found that **every liveness check in this repo asks
"does it answer"**, so none of them could tell yesterday's server from today's. This one found
that **a parity check cannot see a rule missing from both files**, and that the wave's own new
gate stayed green after its guard was deleted. Both are gates that were green about something
they could not look at.

The practical cost here was small — a rename, a conflict in `STATUS.md`, and this paragraph —
and it was small only because the collision was in prose. Had both waves touched
`scripts/`, it would not have been.

## Cost

Not measured. No trajectories, no `--metrics`: the one Reasonix run in this wave was the
acceptance line, and the two fixture runs that settled `forbid_read` — three model calls of a
few thousand tokens each, on `gemma4-128k-cc` at 8.1 GB resident and `100% GPU`.
