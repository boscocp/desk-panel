## What the review found

**Seven, all applied, plus one it listed as declined and this wave took anyway.** Three were
holes in the checker written this wave, which is the part worth reading: a tool built to catch
CI claiming more than it does, itself claiming more than it did.

1. **`continue-on-error:` defeated the whole comparison.** Adding it to the android suite left
   `check()` returning zero problems — CI green on a red suite while `make test-android` exits 1
   on the same tree.
2. **`if:` did the same the other way.** `if: github.event_name == 'push'` on `assembleDebug` is
   green and runs no Gradle on a pull request. The reader counted a step that is *present* as a
   step that runs. Both are banned outright rather than inspected: a rule that decides which
   conditions are harmless will one day decide wrongly and say nothing.
3. **A blank line inside a `run: |` block truncated it**, and every command after the blank line
   matched no `run:` and was dropped on the floor — reported as "CI does not run
   `./gradlew assembleDebug`" about a workflow that runs it two lines below.
4. **`web: # the node suite` was not read as a job**, so its steps were attributed to the
   previous one. Two wrong complaints about a workflow whose only sin was a comment.
5. **STATUS.md carried a false claim** — the TT.9 row still said setup-gradle gets
   `build-root-directory` after the commit that removed it. STATUS.md is the next wave's prompt.
6. **A contract assertion that could not fail.** `assertIsInstance(weather["isDay"], bool)` holds
   whatever the upstream sends, because `_is_day` ends in `bool(...)` on every path: local code
   asserted in a file whose only job is asserting upstream shape.
7. `--workfow` was reported as a flag needing a value rather than as a typo.

Declined by the review and taken anyway: **`RUN_CONTRACT_TESTS=0` was truthy**, so the value a
person types to disable the live tests enabled them. Two lines, and a trap rather than a
preference — a shell profile or a CI matrix setting every flag to 0 is how it arrives.

Still declined, and recorded rather than fixed: `on: push` with no branch filter runs all three
jobs twice for every PR from this repo (visible in #29 — two run ids per commit). That is a
change to what the trigger means, which is TT.9's step 1, not a bug.

## What is not proven

- **The `## Manual check` of TT.9 was not done**: nothing deliberately broke one test to confirm
  only that job goes red. Every job has been seen green; the failure path has not.
- **`gh run watch --exit-status` was proved insufficient, by this wave, on this wave.** The first
  android job passed `build-root-directory:` to `setup-gradle` — an input of a *different*
  action. The run went green while annotating that it had discarded it. The acceptance line
  cannot see annotations; only `gh run view` can, by eye. TT.9 says so now.
- **The contract tests passed once, against the upstreams as they were on 2026-09-24.** That is
  all a contract test ever proves. Their value is the run someone does in three months.
- The Node 20 and `setup-java@v4` deprecation annotations are untouched. They are T7.8's.
- Nothing here needed the phone, and the phone is still off adb — unchanged from wave 22.

## Where the rework went

**The session edited `scripts/check_workflow.py` while the review agent was writing to it**, and
produced duplicate self-test cases for findings 3 and 4. The review noticed, removed its own
copies and kept the session's, and reported "another session is reviewing this same branch" —
which was not another session, it was the same one failing to wait. No work was lost and the
duplicates were caught by reading the case list, not by a test. **The rule is the obvious one:
`--fix` owns the working tree until it reports.**

Otherwise the rework was inside the loop and cheap, and two of the three self-inflicted bugs
were caught by the thing written to catch them:

- `--self-test` found `value.strip("'\"")` eating the trailing quote of
  `node --test "web/test/**/*.test.js"` **on its first run**, before the reader was trusted with
  anything. That is the argument for writing the self-test first, made once more.
- The `connectedAndroidTest` rule matched inside the comment *explaining* its deliberate absence.
  Found by running the check against the real file rather than against the fixtures, which is
  the only place that class of false positive lives.
