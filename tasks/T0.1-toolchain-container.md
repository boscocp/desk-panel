# T0.1 — Containerised Android toolchain

Size: L · Prereqs: none · Blocks: all of phase 2

## Goal

Be able to build an APK without installing the JDK, the Android SDK or Android Studio on
Windows. See [ADR 0003](../docs/adr/0003-containerized-toolchain.md) for why this constraint is
non-negotiable.

## Steps

1. `wsl --install`, then reboot.
2. `winget install Docker.DockerDesktop`. Start it, confirm the WSL2 backend is in use.
3. Write `docker/Dockerfile`:
   - base on a JDK 21 image
   - install Android SDK **command-line tools** (not Android Studio)
   - `sdkmanager` for `platform-tools`, `platforms;android-36`, `build-tools;36.0.0`
   - accept licences non-interactively
   - set `ANDROID_HOME` and put the tools on `PATH`
   - working directory `/workspace`
4. Write `docker/compose.yml`:
   - one service, `build`
   - bind-mount the repository root to `/workspace`
   - **named volume** for `/root/.gradle` — a bind mount on `/mnt/d` is noticeably slow
   - no ports, no privileged mode
5. `docker compose -f docker/compose.yml build`.

## Acceptance

```bash
docker compose -f docker/compose.yml run --rm build sdkmanager --list_installed
docker compose -f docker/compose.yml run --rm build java -version
```

Both must succeed inside the container. On the **host**, all three of these must still fail:

```bash
java -version        # expected: not found
adb version          # expected: not found
ls "$LOCALAPPDATA/Android/Sdk"   # expected: does not exist
```

## Notes

- No AVD, no emulator image. Testing happens on the real phone; the emulator is several GB of
  download that this project never uses.
- Pin exact versions in the Dockerfile. "Latest" turns a reproducible build into a moving one.
- The image is large. Budget the download time; this is the one genuinely slow task.
