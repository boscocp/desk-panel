# T2.5 — `.env` for build-time local configuration

Size: M · Prereqs: T2.1, T4.1, T7.1 · Files: `.env.example`, `.gitignore`,
`android/app/build.gradle.kts`, `android/app/src/main/res/xml/network_security_config.xml`,
`docs/BUILD.md`, `docs/INSTALL-PHONE.md`, `tasks/T7.1-release-keystore.md`

Requires: none for the build half; the phone (on adb) only for the manual check

## Goal

Give the two values that must be baked into the APK — the PC's LAN address and the signing
passwords — one gitignored home with a committed example, so the committed artefact stays free of
anyone's home network and the built artefact actually works.

See [ADR 0013](../docs/adr/0013-local-configuration-boundaries.md) for the split between this and
`server/config.json`, and for why an API token must never appear here.

## Why this exists

`network_security_config.xml` pins the PC's address so the app may reach it over cleartext. The
committed value is the placeholder `192.168.1.100`, and the plan was that an operator would edit
that tracked file and remember not to commit it.

On the first real network it failed twice over: the development machine is `192.168.15.3`, so the
placeholder is not merely stale but on a different subnet, and the panel would have reported
offline for ever — the exact symptom the root `CLAUDE.md` warns reads as a bug in the app. And
"edit a tracked file, do not commit it" means the tested artefact is never the committed one.

## Steps

1. **`.env.example`**, committed, with empty values and a comment per key:

   ```sh
   # Build-time only. Read by Gradle, baked into the APK. Copy to .env and fill in.
   #
   # NEVER put an API token here. The phone never talks to a data provider — it talks
   # to the PC, and the PC talks to the provider (ADR 0004). A value Gradle reads is a
   # value compiled into the APK, and an APK is a zip file. Tokens live in
   # server/config.json, which never leaves the PC.

   # The PC's LAN address, from the DHCP reservation made in T3.8. The app is allowed
   # to reach this one host over cleartext http and nothing else.
   PC_IP=

   # Release signing. Absorbed from keystore.properties.
   KEYSTORE_FILE=
   KEYSTORE_PASSWORD=
   KEY_ALIAS=
   KEY_PASSWORD=
   ```

2. **`.gitignore`**: add `.env`. `keystore.properties` stays listed — an old one may exist on a
   machine that predates this task.

3. **`build.gradle.kts` reads `.env`** and substitutes `PC_IP` into
   `network_security_config.xml` at build time. The committed XML keeps the placeholder;
   substitution happens on the copy that goes into the APK, so the tracked file is never
   rewritten. Absent or empty `PC_IP` falls back to the placeholder and the build still succeeds
   — a fresh clone must build.

4. **The build must print which address it baked in.** One line, every build:
   `desk-panel: cleartext pinned to 192.168.15.3 (from .env)` or
   `desk-panel: cleartext pinned to 192.168.1.100 (placeholder — no .env, the panel will not
   reach any PC)`. An APK silently built against the placeholder is indistinguishable from a
   network fault, and that ambiguity is the reason this task exists.

5. **Move signing to `.env`**, keeping T7.1's behaviour exactly: present means release signing,
   absent means fall back to debug so a fresh clone builds. Amend
   `tasks/T7.1-release-keystore.md`, whose acceptance greps `keystore.properties` by name.

6. **Document in `docs/BUILD.md` and `docs/INSTALL-PHONE.md`**: the file, the keys, the
   token prohibition and its reason, and that changing the PC's address needs a rebuild and a
   reinstall because cleartext permission is a property of the APK.

## Acceptance

```bash
test -f .env.example
git check-ignore -q .env
! git ls-files | grep -qx '.env'
python -c "import sys,re; t=open('.env.example').read(); sys.exit(0 if re.search(r'^PC_IP=\s*$', t, re.M) else 1)"
! grep -rlE '^[A-Z_]*TOKEN=' .env.example
grep -q '192.168.1.100' android/app/src/main/res/xml/network_security_config.xml
docker compose -f docker/compose.yml run --rm build ./gradlew assembleRelease
test -f out/desk-panel-release.apk
docker compose -f docker/compose.yml run --rm build ./gradlew assembleRelease | grep -qE 'cleartext pinned to [0-9]{1,3}(\.[0-9]{1,3}){3}'
! git grep -nE '\b192\.168\.[0-9]{1,3}\.[0-9]{1,3}\b' -- . ':!docs' ':!*.md' ':!tasks' | grep -qv '192\.168\.1\.100'
```

The sixth line asserts the **placeholder survives in git** — the whole point is that the real
address is baked without being committed. The last is T7.3's pre-public sweep, run early here
because this task is the one that could break it.

**Verify the substitution actually happened**, which no line above proves: unzip the built APK
and read `res/xml/network_security_config.xml` out of it. A build that prints the right address
and packages the placeholder passes every command here and fails at the only thing that matters.

## Manual check

With `PC_IP` set to this machine's address, build, install, and confirm the phone can reach the
server — `adb shell ping -c 3 <PC_IP>` succeeds and the panel stops reporting offline once T4.2
lands.

## Notes

- **Do not read `.env` from the server.** Python's side is `server/config.json`, which is runtime
  config and changeable without a rebuild — a property `server/CLAUDE.md` protects explicitly.
- The phone and the PC need not share a subnet. On the development network they do not
  (`192.168.3.100` and `192.168.15.3`) and routing between them works; `ping` is the check, not an
  assumption about matching prefixes.
- `.env` is shell-shaped by convention, but nothing sources it in a shell. Parse it in Gradle;
  do not add a shell wrapper that exports it, which would put the signing passwords into the
  environment of every process the build spawns.
