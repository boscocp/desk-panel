# T0.6 — Two-agent setup: pin the model, split the permissions

Size: M · Prereqs: T0.5 · Files: `reasonix.toml`, `docs/LOCAL-MODELS.md`,
`.claude/settings.json`, `scripts/check_permission_parity.py`

Requires: Ollama running locally with the model pulled

## Goal

Make "the local model executes, Claude reviews" reproducible from a clone, instead of depending
on one machine's untracked configuration. See
[ADR 0011](../docs/adr/0011-two-agent-execution.md).

## Why this exists

The Reasonix setup arrived whole in PR #1 — `reasonix.toml`, `.reasonix/skills/verifier/`,
`docs/LOCAL-MODELS.md` — with no task file, no `STATUS.md` row and no ADR, in a repository
whose `CLAUDE.md` makes `tasks/` the unit of work. This is that row, after the fact.

## Steps

1. **Pin the model in `reasonix.toml`.** Today it carries `[permissions]` and `[sandbox]` only.
   The provider lives in an untracked global config, so "it worked here" is not reproducible:

   ```toml
   default_model = "ollama-local/gemma4-128k-cc"

   [[providers]]
   name = "ollama-local"
   kind = "openai"
   base_url = "http://localhost:11434/v1"
   default = "gemma4-128k-cc"
   api_key_env = ""
   context_window = 131072
   ```

   `context_window` is not decoration: at 0 the harness disables compaction entirely, and the
   run dies of context exhaustion instead of compacting.

2. **Deny git to the local agent.** It never commits on its own — it has no git tool at all —
   but the model can reach `bash git ...`, and the git history is Claude's by design:

   ```toml
   deny = ["Bash(git commit*)", "Bash(git push*)", "Edit(server/config.json)", "Edit(keystore.properties)"]
   ```

3. **Close the keystore hole.** `.claude/settings.json` denies `Read(./*.keystore)`;
   `reasonix.toml`'s `forbid_read` lists only `server/config.json` and `keystore.properties`,
   while allowing `Bash(cat:*)`. The keystore is readable by the local agent and not by Claude.
   Add it, and verify whether `forbid_read` accepts globs — if it does not, list the file.

   **Measured 2026-09-23: it does not.** In a fixture with a decoy `a.keystore`, a
   `forbid_read = ["*.keystore"]` let `cat a.keystore` print the decoy; changing the entry to
   the literal `a.keystore` made the same command return `Permission denied`. So the file is
   listed by name, and a second keystore would need a second line.

4. **Add the commands that acceptance blocks actually use** and neither file allows: `curl`,
   `adb shell`, `adb install`, `keytool`, `make lint-tasks`, `make connected`, and
   `python scripts/*.py`.

   Add them **at the prefix the blocks actually use**, not as a command family. Three of these
   have an irreversible form one character away from the useful one, and the useful one is
   always narrower: `curl` at `-sf http://localhost:` is every use in the repository, while the
   bare grant is unprompted egress to any host; `adb shell` reaches `pm uninstall`, which throws
   away the MIUI grants T2.4 spends a session obtaining; `keytool -delete` or a second
   `-genkeypair` destroys the release signing key, after which no APK can install over the one
   on the phone. A grant that has to prompt for the destructive form is working, not broken.

5. **`scripts/check_permission_parity.py`** — the twins are declared to be kept in step by
   three separate documents, and they drifted before the ink dried. A script compares them and
   reports each asymmetry, allowing an explicit `# parity: intentional` marker for the ones
   that are (`WebFetch`, which Reasonix has no equivalent for).

   The marker **names the list it speaks for** — `(allow)`, `(deny)` or `(allow, deny)` — and is
   anchored to the start of a comment. Both came out of the review and both are load-bearing: a
   rule can be asymmetric in the allow lists and in the deny lists for opposite reasons, and one
   blanket exemption let the `deny` that ADR 0011 rests on be deleted with the check still green.

## Acceptance

```bash
python -c "import tomllib,sys; c=tomllib.load(open('reasonix.toml','rb')); sys.exit(0 if c.get('default_model') and c.get('providers') else 1)"
python scripts/check_permission_parity.py
python -c "import tomllib,sys; d=tomllib.load(open('reasonix.toml','rb'))['permissions']['deny']; sys.exit(0 if any('git push' in r for r in d) and any('git commit' in r for r in d) else 1)"
python -c "import tomllib,sys; f=tomllib.load(open('reasonix.toml','rb'))['sandbox']['forbid_read']; sys.exit(0 if any(p.endswith('.keystore') and '*' not in p for p in f) else 1)"
reasonix run --dir . --permission-mode manual --max-steps 5 "print the repository name and stop"
```

The last line is the end-to-end check that the pinned provider actually resolves. It needs
Ollama up; `ollama ps` must show the model on the GPU, not split with the CPU.

`manual`, not `read-only`: Reasonix's modes are `manual | ask | auto | acceptEdits | dontAsk |
plan | bypassPermissions`, and `plan` — the read-only one — **refuses to run headless**
(`--permission-mode plan requires an interactive session`). `manual` is the strictest mode that
runs in `run`, and the prompt needs no tool at all, so nothing is gated either way.

The fourth line is step 3's measurement turned into an assertion: a glob there is inert, so the
keystore has to be spelled out.

## Notes

- `--max-steps` defaults to **0, meaning unbounded**. Every dispatch in this project passes it.
- Reasonix reads `.claude/skills/` but not `.claude/settings.json` — that is deliberate on its
  side (`internal/config/paths.go`, `ConventionDirs`) and is why `reasonix.toml` exists.
