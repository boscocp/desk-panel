# T3.6 — Serve the APK at `/app`

Size: S · Prereqs: T3.1 · Files: `server/server.py`

Requires: none

## Goal

Install and update the app from the phone's browser. No cable, no adb, and none of MIUI's
"USB debugging (Security settings)" dance with its Xiaomi-account requirement.

## Steps

1. `GET /app` serves **`desk-panel-release.apk` if it is there**, and otherwise the newest
   `.apk` in `out/`.

   Newest-by-mtime alone was the first rule and it is wrong in the one way that costs somebody
   a trip to the phone. `make apk` is `assembleDebug` and drops `app-debug.apk` into the same
   `out/`, so the newest file is routinely the debug build -- which cannot install over the
   release-signed one the panel runs. Android answers
   `INSTALL_FAILED_UPDATE_INCOMPATIBLE: signatures do not match`, and the only way past it is
   an uninstall, which throws away MIUI's autostart and battery grants. Those are manual
   per-device toggles (`docs/INSTALL-PHONE.md`) and re-granting them needs a person at the
   phone. Newest-by-mtime remains the rule among the rest, for a checkout that has no release
   build at all.
2. Set `Content-Type: application/vnd.android.package-archive` and a
   `Content-Disposition: attachment` filename, or the browser will not offer to install it.
3. If `out/` has no APK, return 404 with a message saying to build first.
4. Optionally serve a one-line HTML page at `/` linking to `/app`, so the phone only needs to
   remember the host and port.

## Acceptance

```bash
mkdir -p out && printf 'PK\x03\x04' > out/t3.6-acceptance.apk
python server/probe.py --serve --url /app --method HEAD --expect-status 200
python server/probe.py --serve --url /app --method HEAD --expect-header content-type=application/vnd.android.package-archive
python server/probe.py --serve --url / --expect-status 200
rm -f out/t3.6-acceptance.apk
```

`curl -sI | grep -i content-type` succeeded whenever *any* content-type header came back, which
is always. The value is the assertion, and `probe.py --expect-header` compares it exactly: a
prefix does not match, so `application/vnd.android.package` fails against
`application/vnd.android.package-archive`.

**The first and last lines are not decoration.** `out/` is gitignored and `make clean` deletes
it, so on a fresh clone, in CI (TT.9), or after a clean, `/app` correctly answers 404 and both
probes exit 1. The criterion has to bring its own APK or it is a criterion about this desk. The
fixture is four bytes and is named so that nothing mistakes it for a build; deleting it matters,
because an APK in `out/` is a file `/app` will hand to a phone.

Whichever real build is present wins over the fixture anyway -- the route prefers
`desk-panel-release.apk` -- and every assertion here holds for either.

What is *not* asserted here is the 404, which needs an empty `out/` in the same breath as a full
one. `server/tests/test_routing.py` and `server/tests/test_http.py` own that, over a real
socket, against a directory they control.

## Manual check

From the phone's browser, `http://<pc-ip>:8777/app` downloads and installs — the install path
this project exists to avoid needing a cable for.

## Notes

- MIUI asks once to allow installs from the browser.
- This only matters on the LAN, and the server is not reachable off it. Serving a binary this
  way would be a poor idea on a public endpoint; here the network is the boundary.
