# T4.13 — A failing ping says where the phone is

Size: S · Prereqs: T4.8 · Files:
`android/app/src/main/java/dev/bosco/deskpanel/LinkSummary.java`,
`android/app/src/main/java/dev/bosco/deskpanel/PcPoller.java`,
`android/app/src/main/java/dev/bosco/deskpanel/PanelService.java`,
`android/app/src/main/AndroidManifest.xml`,
`android/app/src/test/java/dev/bosco/deskpanel/LinkSummaryTest.java`,

Requires: the phone on adb

## Goal

Reported from the chair on 2026-10-30: the panel did not come on, and the owner suspected the
Windows server was out of date. It was the network. A power cut overnight brought a HUAWEI Mesh 3
satellite back as a router of its own, the phone took `192.168.4.7` from it, and neither PC
(`192.168.3.97`, `192.168.15.3`) was reachable from there. The log said only
`ping=err hosts=...:SocketTimeoutException,...:SocketTimeoutException` for hours, which reads the
same as both PCs being off. Telling the two apart took an adb session: `ip addr`, the DHCP
record, the gateway's MAC.

The README has had this symptom since PR #80 (2026-10-15), and its step 3 is "compare the
phone's address with the PC's". The phone knows its own address. It should say it.

## Steps

1. `LinkSummary.describe(addresses, gateway)`, plain Java: `self=<ip>/<prefix>[,...] gw=<ip>`,
   IPv4 only, `none` for a half that is missing. Two tokens, no space inside either.
2. `PcPoller` takes a `Link` and appends `link.describe()` to the `ping=` line **only when no
   PC answered**. A healthy cycle does not make the binder call. A `describe()` that throws
   logs `self=unknown gw=unknown` and the loop goes on.
3. `PanelService.describeLink` reads the **Wi-Fi** network's `LinkProperties`, falling back to
   the default network only when there is no Wi-Fi: a Wi-Fi with no internet loses the default
   to mobile data, and the carrier's address says nothing about the LAN. IPv4 addresses with
   their prefix, and the first IPv4 default route's gateway that is not `0.0.0.0`.
   `ACCESS_NETWORK_STATE` in the manifest, a normal permission, granted at install.
4. `docs/TESTING.md` documents the two tokens, and stops recommending `awk '{print $NF}'` for
   the hosts field, which is no longer the last one on a failing line. The README's
   troubleshooting example and step 3 use them, and gain the mesh-satellite case.

## Acceptance

```bash
docker compose -f docker/compose.yml run --rm build ./gradlew test
grep -q 'whereAmI()' android/app/src/main/java/dev/bosco/deskpanel/PcPoller.java
grep -q 'ACCESS_NETWORK_STATE' android/app/src/main/AndroidManifest.xml
grep -q 'self=' docs/TESTING.md
python scripts/check_acceptance.py
```

On the phone, with this build installed, Wi-Fi up, and every PC unreachable (the servers
stopped is enough; Wi-Fi off proves only `self=none gw=none`):

```bash
adb logcat -c && sleep 40
adb logcat -d -s DeskPanel | grep 'ping=err' | grep -qE ' self=[0-9./,]+ gw=[0-9.]+$'
```

And with a PC up (display on or off), the healthy line is unchanged:

```bash
adb logcat -c && sleep 10
adb logcat -d -s DeskPanel | grep -qE 'ping=(ok|idle) host='
! adb logcat -d -s DeskPanel | grep -E 'ping=(ok|idle)' | grep -q 'self='
```
