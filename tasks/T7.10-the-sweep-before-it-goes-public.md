# T7.10 — The sweep: what is in the tree, and what is in the history

Size: M · Prereqs: none · Files: `scripts/check_secrets.py`, `docs/PRE-PUBLIC-SWEEP.md`,
`Makefile`, `.github/workflows/lint.yml`, and whatever the sweep turns up

Requires: none — no phone, no network

**Runs before [T7.3](T7.3-pre-public-review.md), which runs before
[T7.7](T7.7-open-to-community.md) makes the repository public.** Asked for from the chair on
2026-09-27: a sweep for loose ends, keys and anything else that makes going public unsafe — in
the working tree *and in the history*.

## Why this is not just T7.3 step 1

T7.3 already greps `git log -p` for the words *token*, *password*, *keystore* and *api key*. That
is a start and it is not a sweep:

- **A word list only finds a secret that sits near a word somebody thought of.** A 40-character
  hex string, a JWT, an `ssh-rsa` blob or a keystore's bytes carry none of those words.
- **It runs once, by hand, and then the repository is public for ever.** Everything else in this
  repo that matters is a command with an exit code that `make check` runs; this is the one with
  the most permanent failure mode and it is the one that is prose.
- **The two halves have different remedies and the task does not separate them.** A finding in
  the *tree* is a deletion. A finding in the *history* is **rotate the credential**, and possibly
  rewrite — and a rewrite of a repository that other people have cloned is a different, worse
  conversation. `scripts/check_links.py` already draws exactly this distinction between a dead
  link and an unreachable one, for the same reason: a reader has to be able to tell which of two
  very different problems they have.

## What the sweep has to cover

Grounded in what a look at this repository on 2026-09-27 actually found. **None of the following
is a secret; all of it is a decision somebody has to take on purpose**, and the point of the task
is that they are surfaced rather than discovered by a stranger.

1. **Credential shapes, by pattern and not by vocabulary.** `-----BEGIN … PRIVATE KEY-----`,
   `ssh-rsa`, JWTs (`eyJ…`), AWS (`AKIA…`), GitHub (`ghp_`, `github_pat_`), bearer headers, long
   high-entropy strings in files that have no business holding one. The brapi token is the one
   this project actually has, and T7.3 step 2 is right that it must appear nowhere — including in
   a fixture, a test, a doc example or a screenshot.

2. **Every blob in the history, not every file in the tree.**
   `git rev-list --objects --all` and `git cat-file` — a file deleted in a later commit is still
   there, and that is the whole point of running this before the repository is public rather than
   after.

3. **Filenames that should never have been committed**, over the whole history:
   `config.json`, `config.toml`, `*.keystore`, `*.jks`, `.env`, `*.pem`, `*.key`. A look on
   2026-09-27 found none — only `tasks/T7.1-release-keystore.md`, which is a task file with the
   word in its name. That is a good result and it is worth having a command that keeps saying so.

4. **The identifiers this project is full of by design.** Each is the owner's call, and each
   should be a recorded decision rather than an oversight:
   - **The pinned LAN address.** It is in about eight tracked files — including
     `android/app/src/test/java/dev/bosco/deskpanel/ActionsTest.java` and
     `server/tests/test_actions.py`, which T7.3's own acceptance line excludes because it skips
     `docs` and `*.md` but not source. ADRs, `SERVER-SETUP.md`, `BUILD.md` and the harness notes
     carry it too.
   - **The phone's adb serial**, in `tasks/STATUS.md`.
   - **Home paths and the owner's identifiers** in `server/fixtures/login_scope/*`, which are
     captured command output and therefore realistic on purpose — a fixture with a fake username
     proves less. Keep or scrub, but decide.
   - The city, the tickers, and anything in a screenshot (T7.3 step 4 owns the screenshots).

5. **Loose ends: files that exist for the private workflow.** `WINDOWS-NEXT-SESSION.md` is
   tracked at the repository root and is a session hand-off note, found by the wave 30 design
   review. Also: anything matched by `.gitignore` that is tracked anyway, empty or stub files,
   and `TODO`/`FIXME` markers — this repo puts its unfinished business in `tasks/`, so one in the
   code is either stale or a task nobody filed.

## Steps

1. **`scripts/check_secrets.py`**, with the two halves reported apart and exiting differently:
   the tree (fixable now) and the history (rotate, and maybe rewrite). Same shape as
   `check_links.py`, which is the model to copy — including the `--self-test`, which is what gets
   it discovered by `lint-selftests` and run by `make check` without anybody editing a list.

2. **A committed allowlist with a reason per entry.** Every finding that is deliberate — the
   placeholder address, a fixture that carries a realistic path, the string `token` in a config
   example — gets one line saying why it is allowed. Without this the script is noise on its
   second run and nobody reads the third. **The reason is the point**: an allowlist of bare
   patterns is a way of turning a guard off with extra steps.

3. **`make check` runs the tree half; the history half runs in CI and before the flip.** The
   history sweep walks every blob and does not need to run on every save. The split is the one
   `lint-links` already makes, and for the same reason.

4. **`docs/PRE-PUBLIC-SWEEP.md`**: what was found, what was decided about each, and what was
   deliberately kept. This is the record T7.7 needs — "we looked, here is what we knew we were
   publishing" — and it is the document that makes the answer checkable a year later.

5. **Act on the findings**, which is the half that is not a script: delete what should not ship,
   replace the pinned address with the agreed placeholder where it is not load-bearing, and for
   anything found in the history, **rotate the credential first and decide about rewriting
   second**. A rewrite is a force-push over published history — stop and ask before doing one.

6. **Fix T7.3's acceptance while here.** Its last line is `python scripts/check_links.py` with no
   arguments, which exits 2 (usage) — the script needs paths. It has never passed as written.

## Acceptance

```bash
python scripts/check_secrets.py --self-test
python scripts/check_secrets.py
python scripts/check_secrets.py --history
grep -q 'check_secrets' Makefile
grep -q 'check_secrets' .github/workflows/lint.yml
grep -q 'deliberately kept' docs/PRE-PUBLIC-SWEEP.md
python scripts/check_links.py --skip-remote docs/PRE-PUBLIC-SWEEP.md
python scripts/check_acceptance.py
make check
```

The third line is the one that cannot be satisfied by tidying the working tree, and the sixth is
the one that cannot pass by accident: a sweep that decided nothing did not look.

## Manual check

Read `docs/PRE-PUBLIC-SWEEP.md` as somebody who is about to clone this repository and has no
reason to trust it. The question is not "is it clean" but **"do I know what is in here"**.

## Notes

- **Prove the script can fail before trusting it.** Plant a fake key in a scratch commit on a
  throwaway branch, watch the history half go red, and delete the branch. A secret scanner that
  has never found anything is indistinguishable from one that cannot.
- Do not put a real credential in a fixture to test the scanner. Generate one that matches the
  shape and is not a key to anything, and say so in the file.
- GitHub has its own secret scanning and push protection for public repositories. They are worth
  turning on in T7.7 and they are not a substitute for this: they run after the push, and the
  push is the thing that cannot be undone.
