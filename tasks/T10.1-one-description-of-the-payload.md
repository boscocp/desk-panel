# T10.1 — One description of the payload, and a fixture that fails when a key is dropped

Size: M · Prereqs: T7.9 · Files: `server/tests/fixtures/payload.json`, `server/tests/`,
`web/test/`, `android/app/src/test/java/dev/bosco/deskpanel/DataPayloadTest.java`,
`android/app/build.gradle.kts`, `web/js/mock.js`

Requires: none — Docker for the Android half of the acceptance, no phone

## Goal

The payload shape exists in four places and nothing compares them:

1. `web/js/mock.js` — what a browser-only contributor develops against
2. `App.quotes()` / `App.weather()` — what the PC sends
3. `DataPayload.merge` — what reaches the page, rebuilt key by key
4. `DataPayloadTest.QUOTES` — the test's own string literal

A key added to the server and not to `merge` **does not reach the phone**, silently, with a
correct server and a correct page. That has shipped twice — `night` in T6.4, `actions` in T8.2 —
the second time with a comment in the file warning about the first. [The design
review](../docs/DESIGN-REVIEW.md) is where the decision to stop relying on that comment was
taken: a warning in the file a change has to touch is not a gate, and this one has now failed in
the file it is written in.

**Make the class of bug impossible to ship green.** Not with a schema library and not with a
build step — both are dependencies this project refuses.

## Steps

1. **One fixture, written by the server, committed.** `server/tests/fixtures/payload.json`, and
   a server test that **generates it from `App`'s own payload assembly** and fails if the
   committed copy differs. That is what makes it the description rather than a fifth copy: it
   cannot drift from the server without a red test naming the difference.

2. **The Android test reads that file.** `DataPayloadTest` asserts `merge` preserves **every
   top-level key** of the fixture, rather than the handful somebody remembered. Pointing the JVM
   test's resources at the fixtures directory is the same move `assets.srcDirs` already makes in
   `android/app/build.gradle.kts`; no new dependency, and `org.json` is already on the test
   classpath. `DataPayloadTest.QUOTES` stops being a fourth copy.

3. **The web test reads it too.** Feed the fixture to the page's reader and assert every section
   it promises is rendered — which also ends `mock.js` being the one copy nothing asserts.

4. **`mock.js` is checked against the fixture**, not replaced by it: it must stay a plain script
   the browser loads from `file:` with no build step (ADR 0006). A test comparing its keys to the
   fixture's is enough.

5. **The same mechanism for the action lists.** `actions.CATALOGUE` (Python), `Actions.ALLOWED`
   (Java) and `words.actions` (JavaScript) are three lists nothing compares — a half-added action
   draws no button, or draws one the bridge refuses. One committed list, three assertions. The
   *duplication* stays: ADR 0015 wants the phone's allowlist independent of the server's, and it
   is only the absence of a check that they agree that is the defect.

6. **Prove each assertion can fail.** Delete a key from the fixture, or from `merge`, and watch
   the right test go red. A cross-layer check that cannot fail is the thing this task exists to
   replace.

## Acceptance

```bash
python -m unittest discover -s server/tests -t .
node --test "web/test/**/*.test.js"
docker compose -f docker/compose.yml run --rm build ./gradlew test
test -f server/tests/fixtures/payload.json
grep -q 'payload.json' android/app/src/test/java/dev/bosco/deskpanel/DataPayloadTest.java
! grep -q 'private static final String QUOTES' android/app/src/test/java/dev/bosco/deskpanel/DataPayloadTest.java
make check
```

The last two lines are the task: the fourth copy is gone, and the test reads the description
instead of carrying one.

## Manual check

Add a key to the server's payload, run `make check`, and read which test failed. If the answer is
"none", this task did not land. If the answer names `DataPayload`, it did.

## Notes

- The fixture is generated from the server rather than hand-written, or it becomes a fifth copy
  with better branding.
- Resist making `merge` copy the whole object. It is arguable — it would flip the default from
  "silently dropped" to "arrives for free" — but it also drops the all-or-nothing validation that
  stops a missing section blanking the panel while the cycle logs `data=ok`. If it is done, it
  is an ADR, because it changes what the phone trusts the PC to send.
