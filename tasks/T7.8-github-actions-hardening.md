# T7.8 — Everything GitHub gives a public repo for nothing

Size: M · Prereqs: TT.9, T7.4, T7.5, T7.6 · Files: `.github/workflows/`, `.github/dependabot.yml`,
`scripts/check_ci_hygiene.py`, `docs/MAINTAINING.md`

Requires: a pushed branch and the `gh` CLI authenticated. The Actions minutes this spends are
free **because the repo is public** — see step 1.

Asked for on 2026-09-20: turn on what GitHub offers at no cost that helps review, linting and
the build, before the repo is opened. It runs after T7.6, which is where the commit convention
and the scripts CI enforces come from, and before T7.3, which is the last look before the repo
goes public.

## What this is not

**TT.9 already owns `ci.yml`** — the three jobs that run the server, web and Android tests on
every push. Do not rewrite it. This task is everything *around* that: the checks a stranger's
pull request should meet before a human reads it, the scanning GitHub does for free, and the
hygiene that stops the workflows themselves becoming the weakest thing in the repo.

If a step here wants to change what `ci.yml` runs, it changes `scripts/check_workflow.py` too —
that script exists to keep CI and the `Makefile` from drifting, and it is the thing that fails
when they do.

## Steps

1. **Say why it is free, in `docs/MAINTAINING.md`, because it stops being true if the repo is
   ever made private.** GitHub-hosted Actions minutes are unlimited on public repositories and
   metered on private ones; CodeQL code scanning is free for public repositories and a paid
   feature otherwise. Both assumptions are load-bearing here, and neither is visible from
   inside a workflow file. One paragraph, so a future decision to go private is a decision
   about this too.

2. **`permissions:` on every workflow, least-privilege, at the top.** The default token is
   read/write across the repo unless the workflow says otherwise. Every workflow here only
   reads code, so `permissions: contents: read` is the default, and any job that needs more
   (CodeQL wants `security-events: write`) declares it on the job and not on the file.

3. **Pin every third-party action to a commit SHA, with the version in a trailing comment.** A
   tag is mutable and a compromised popular action runs with whatever the token allows. This is
   cheap, it is what GitHub's own hardening guide asks for, and the only cost is that
   Dependabot has to do the bumping — which is step 4.

4. **`.github/dependabot.yml` for the two ecosystems this repo actually has**: `github-actions`
   (weekly) and `gradle` (weekly). Not `pip` and not `npm`: `server/` is standard library only
   and `web/` has no `package.json`, both deliberately, and a Dependabot config naming an
   ecosystem that does not exist is a config nobody trusts afterwards. Group the action bumps
   into one PR a week or the repo becomes a stream of one-line PRs.

5. **CodeQL**, the default setup if it is available for the languages here, a workflow if not.
   It reads Python, JavaScript and Java, which is all three of this repo's languages. It is
   free on a public repo and it is the single highest-value thing on this list, because it is
   the only one that looks at what the code *does*.

6. **A lint job, and the choice is constrained by this project's own rules.**
   - **Python** — `ruff`, installed in the job and not in `server/`. `server/CLAUDE.md` says
     the *server* has no dependencies; a linter that runs in CI and never ships is not one.
     Configure it in `pyproject.toml` with the line length this repo already writes to, and
     start from a small rule set that passes, not from `ALL` with fifty ignores.
   - **PowerShell** — `PSScriptAnalyzer` on `server/install_task.ps1`, which is the one file
     here nobody can run on this machine (T3.12's notes) and therefore the one file most worth
     having a machine read.
   - **JavaScript** — **not ESLint.** `web/` has no `package.json` and no build step by design
     (ADR 0006), and adding a node toolchain to lint a no-toolchain directory is the tail
     wagging the dog. `node --check` on every file under `web/` is what CI runs, and that is
     already more than the directory promises.
   - **Shell** — `shellcheck` if any `.sh` exists by then. It may not.

7. **Run the repo's own guards in CI**, because each of them is a rule somebody wrote down and
   none of them runs unless a human remembers: `scripts/check_acceptance.py` (T0.5),
   `scripts/check_workflow.py` (TT.9), `scripts/check_links.py` (T7.4),
   `scripts/check_requirements.py` (T7.5) and T7.6's commit-message check. One `guards` job.

8. **`dependency-review-action` on pull requests**, which is free on public repos and blocks a
   PR that introduces a dependency with a known advisory. Nearly a no-op in a repo with
   almost no dependencies — which is the point: it is how the repo *notices* the day that
   changes.

9. **A pull request template and the review it implies.** T7.6 owns the template's wording;
   what belongs here is that the checks named in it are the checks CI actually runs, so a
   contributor is never asked to confirm something no job verifies.

10. **`concurrency:` per workflow, cancelling superseded runs on the same ref.** Three pushes
    to a branch should leave one run, not three. Free minutes are not a reason to waste twenty
    of them per push.

11. **Do not** add a stale-issue bot, an auto-labeller, or a "thanks for your contribution"
    action. This repo expects a handful of contributors and device reports (T7.7); automation
    that answers a human with a robot costs more goodwill than it saves time.

## Acceptance

```bash
python scripts/check_ci_hygiene.py
python -c "import sys,pathlib; sys.exit(0 if pathlib.Path('.github/dependabot.yml').is_file() else 1)"
python scripts/check_workflow.py
gh workflow run lint.yml --ref "$(git branch --show-current)"
gh run watch "$(gh run list --workflow=lint.yml --limit 1 --json databaseId -q '.[0].databaseId')" --exit-status
```

`check_ci_hygiene.py` is this task's deliverable and it asserts the four properties above that
a reader cannot see at a glance, over every file in `.github/workflows/`:

- every workflow declares `permissions:`, and none of them grants `write-all`,
- every `uses:` that is not `actions/*` or `github/*` is pinned to a 40-character SHA,
- every workflow declares `concurrency:`,
- `dependabot.yml` names exactly the ecosystems the repo has — it fails on a missing one **and
  on an invented one**, because a config listing `npm` in a repo with no `package.json` is the
  kind of thing that looks like coverage and is not.

Each of those must be mutation-tested when it is written: unpin an action, drop a
`permissions:` block, add `pip` to dependabot, and watch the script go red. An assertion nobody
has seen fail is not an assertion, and this repo has paid for that lesson five times.

## Manual check

Open a pull request from a branch with one deliberately bad line — a Python file `ruff` will
object to — and look at what a reviewer sees before reading any code: which checks ran, which
failed, and whether the failure says what to do. That is the whole product of this task, and no
exit code measures it.

Then confirm in the repo's settings that CodeQL is reporting, and that the Actions tab shows
minutes as unbilled.

## Notes

- **Required status checks are T7.7's**, not this task's: that task owns branch protection and
  the settings applied with `gh`. This one makes the checks exist and be worth requiring; that
  one requires them. Neither is much use alone, and T7.3 runs after both.
- Everything here is free **for a public repo**. CodeQL and unlimited Actions minutes both
  change on a private one, which is why step 1 writes that down where a maintainer will find
  it rather than leaving it as an assumption inside a YAML file.
- Resist adding a job per script. One `guards` job running five commands fails just as loudly,
  and a dashboard with fifteen green ticks is one nobody reads.
