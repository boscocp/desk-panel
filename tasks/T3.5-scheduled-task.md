# T3.5 — Login-scoped autostart: the contract and its verifier

Size: M · Prereqs: T3.1, T3.2 · Files: `server/verify_login_scope.py`,
`docs/SERVER-SETUP.md`

Requires: none — the per-OS installers are T3.8, T3.9 and T3.10

## Goal

Make "the server answers ⟺ a human is logged in" a property that can be **asserted**, on any
OS, with an exit code. This task ships no installer. It ships the contract the three installers
must satisfy and the two tools that check them.

See [ADR 0010](../docs/adr/0010-login-signal-is-session-scoped.md) for why the rule had to be
restated without Windows vocabulary, and what each OS's carrier is.

## What changed, and why this task was rewritten

It used to be the Windows installer itself: `install_task.ps1`, a firewall rule, a DHCP
reservation. That content is now T3.8, unchanged in substance. This file keeps the id because
`T3.1`, `T4.1` and `STATUS.md` all link to it, and because the contract is the part that
belongs first.

Its old acceptance was `curl -sf http://<pc-ip>:8777/ping`, which cannot run on the primary
platform: in PowerShell `curl` is an alias for `Invoke-WebRequest`, which does not understand
`-sf`. The probe below replaces it and behaves identically in `cmd`, PowerShell, bash and fish.

## Steps

1. `server/probe.py` **already exists** — it ships with T3.1, because T3.1's own acceptance
   calls it and the two tasks otherwise formed a cycle. Use it; do not rewrite it. If the
   login-scope work needs a flag it lacks, add the flag and say so.

2. `server/verify_login_scope.py` — exit 0 iff, on the current OS:
   - a session-scoped autostart entry exists and carries the fields ADR 0010 names
   - **no** system-scoped equivalent exists (Windows Service, systemd system unit,
     LaunchDaemon)
   - auto-login is off
   - it is not running under WSL, and not inside a container

   Every check is a **pure function over captured text** — `parse_schtasks_xml(s)`,
   `parse_systemctl_show(s)`, `parse_launchctl_print(s)`, `detect_autologin(...)` — with the
   command execution in a thin shell around them. That is what lets TT.10 test all three
   platforms from fixtures on any one machine, and it follows the same rule
   `server/CLAUDE.md` applies to the request handler.

3. `--self-test` runs those parsers against the bundled fixtures and exits non-zero on any
   disagreement, so the verifier itself is verifiable without an installed server.

4. Rewrite the `## Linux` section of `docs/SERVER-SETUP.md`. It currently recommends
   `WantedBy=default.target` and calls it equivalent; it is not, and ADR 0010 explains why.

## Acceptance

```bash
python -m unittest discover -s server/tests -t .
python server/verify_login_scope.py --self-test
python server/probe.py --host 127.0.0.1 --port 1 --expect down
python server/probe.py --serve --expect up
```

The third line is the one that proves the probe can fail: nothing listens on port 1, so a probe
that always returned 0 would be caught here rather than in T3.8.

## Notes

- **Do not make this a service, a daemon, or a container.** Each would answer without a login,
  which is precisely the wrong signal. The full forbidden class is in ADR 0010.
- The probe is also the acceptance tool for T3.1, T3.2, T3.6 and T3.7. Writing it here, once,
  is why those tasks stopped using `curl` in ways that exit 0 whatever the server said.
