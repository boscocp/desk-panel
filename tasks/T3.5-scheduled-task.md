# T3.5 — Scheduled Task, firewall, static IP

Size: M · Prereqs: T3.1 · Files: `server/install_task.ps1`, `docs/SERVER-SETUP.md`

## Goal

The server starts on login, with no manual step, and is reachable from the phone. This is what
turns "a script I run" into "the login signal".

## Steps

1. `server/install_task.ps1` registering a task with an **"At log on"** trigger scoped to the
   current user, running `pythonw server\server.py` with no window.
   Use `New-ScheduledTaskTrigger -AtLogOn`, or `schtasks /create /sc onlogon /xml`.
2. Firewall rule on the **Private** profile only:

   ```powershell
   New-NetFirewallRule -DisplayName "desk-panel" -Direction Inbound -Action Allow `
     -Protocol TCP -LocalPort 8777 -Profile Private
   ```

3. Reserve a static DHCP lease for the PC on the router. Write the address into
   `docs/SERVER-SETUP.md` — T4.1 pins it in the app.
4. In the BIOS, disable **ErP Ready / USB power in S5**. Reason in
   [ADR 0008](../docs/adr/0008-device-longevity.md); it is a battery-longevity measure, not a
   networking one, but this is the session where you are already in setup mode.

## Acceptance

Reboot, log in, wait about a minute, then from **another device on the LAN**:

```bash
curl -sf http://<pc-ip>:8777/ping
```

Testing from `localhost` does not count and will not catch the firewall.

## Notes

- **Do not make this a Windows Service.** It would answer before and without a login, which is
  precisely the wrong signal — see
  [ADR 0004](../docs/adr/0004-server-is-login-signal-and-proxy.md).
- Verify it stops answering after you log off. That behaviour *is* the feature.
- If DHCP later hands the PC a different address, the app will report "offline" forever and
  look like a bug. The reservation is the fix, and it is easy to skip.
