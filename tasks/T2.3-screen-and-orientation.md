# T2.3 — Keep screen on, landscape, immersive

Size: S · Prereqs: T2.2 · Files: `MainActivity.java`, `AndroidManifest.xml`

Requires: phone (on adb)

## Goal

The panel looks like a panel: landscape, no system bars, screen not sleeping.

## Steps

1. `android:screenOrientation="sensorLandscape"` on the activity in the manifest.
   Not `"landscape"`: that pins one of the two landscape directions, so turning the
   phone end for end on its stand does nothing. `sensorLandscape` accepts both and still
   never allows portrait. It also ignores the system rotation lock, which a panel wants.
2. `getWindow().addFlags(WindowManager.LayoutParams.FLAG_KEEP_SCREEN_ON)` — the officially
   recommended approach; screen wake locks have been deprecated since API 17.
3. Immersive full-screen via `WindowInsetsControllerCompat`: hide system bars, set the
   behaviour so a swipe reveals them transiently.
4. Keep the flag in a method that can clear it — T4.4 needs to remove it to let the screen
   sleep. Do not scatter `addFlags` calls around.

## Acceptance

```bash
adb shell dumpsys window | grep -q 'mCurrentFocus.*dev.bosco.deskpanel'
adb shell dumpsys window | grep -qE 'mRotation=ROTATION_(90|270)'
TIMEOUT_MS=$(adb shell settings get system screen_off_timeout | tr -d '\r')
test "$TIMEOUT_MS" -gt 0
sleep $(( TIMEOUT_MS / 1000 * 2 + 15 ))
adb shell dumpsys power | grep -q 'mWakefulness=Awake'
```

`grep -i "mCurrentFocus"` was the original and it asserts nothing: that is the field *label*,
printed on every device whatever is focused, so the grep matched and the real criterion lived
in a trailing comment. Grep for the package.

`sleep 600` was the original screen-on check, and it was a magic number rather than a
criterion. Outlasting the screen timeout is the whole assertion, so a fixed wait only asserts
anything on a device whose timeout happens to be shorter than it: on this phone
`screen_off_timeout` is 60000, so 600s was ten times longer than it needed to be, and on a
phone set to "never" or to fifteen minutes the identical line would have passed while proving
nothing at all. Read the timeout off the device and wait twice it plus slack — 135s here, and
still a real assertion anywhere else.

`test "$TIMEOUT_MS" -gt 0` is the guard that keeps that honest. `settings get` prints `null`
for an unset key, and without the guard that would leave a 15-second wait masquerading as the
check. An unset timeout must fail this criterion, not shrink it. The guard also subsumes the
old `settings get system screen_off_timeout > /dev/null` line, which only ever asserted that
the command ran, so that line is gone rather than kept as decoration.

## Two corrections to this task

**`sensorLandscape`, not `landscape`.** Step 1 pinned a single landscape direction, so the panel
could not be turned end for end on its stand — which is a thing a desk panel gets turned around
for, depending on which side the cable leaves. `sensorLandscape` accepts both directions, still
refuses portrait, and ignores the system rotation lock.

**The wait is derived from the device, not hardcoded.** It used to be `sleep 600`, and 600 is
only meaningful if the device's screen timeout is below it. This phone's
`screen_off_timeout` is 60000 ms, so the fixed number was ten times longer than it needed to
be — while on a phone set to "never sleep", or to a fifteen-minute timeout, the identical
criterion would pass having proved nothing. It now waits twice the device's own timeout plus
slack, which stays meaningful anywhere. The `test -gt 0` guard is load-bearing: `settings get`
prints `null` for an unset key, and an unset timeout has to fail rather than collapse to
`sleep 15`.

## Manual check

No status bar and no navigation bar — immersive mode is the one thing here that `dumpsys` will
not tell you plainly.

## Notes

- `FLAG_KEEP_SCREEN_ON` stops the screen sleeping. It does **not** stop MIUI's battery manager
  from freezing the process — that is T2.4, and it is a separate problem.
