# T5.3 — Adaptive polling

Size: S · Prereqs: T5.2 · Files: `PcState.java`, `PcPoller.java`, `DataPoller.java`

Requires: phone (on adb), PC server stoppable

## Goal

Stop draining the battery while the PC is off. This is a **requirement, not polish**: with ErP
Ready disabled the phone runs on its own battery during those hours, and a 2s poll all night
means a flat device by morning ([ADR 0008](../docs/adr/0008-device-longevity.md)).

## Steps

1. Online: keep polling `/ping` every 2s. Responsiveness to logoff matters and the screen is on
   anyway.
2. Offline: back off — 2s, 4s, 8s, capped at **15s**. A 15s worst case to notice the PC
   returning is imperceptible in practice.
3. Offline: stop `DataPoller` entirely. Nobody is looking at a sleeping screen.
4. Reset the backoff immediately on the first success.
5. Put the schedule in `PcState.java` as a pure function of state and consecutive failures, so
   TT.5 can test it on the JVM with no device and no waiting.

## Acceptance

```bash
docker compose -f docker/compose.yml run --rm build ./gradlew test
```

Backoff tests pass. Then with the PC off:

```bash
adb logcat -c && sleep 60 && adb logcat -d -s DeskPanel > /tmp/desk-panel-idle.log
test "$(grep -c 'ping=' /tmp/desk-panel-idle.log)" -le 4
test "$(grep -c 'data=' /tmp/desk-panel-idle.log)" -eq 0
```

At most four ping **cycles** in the minute, and zero data requests while the PC is off. `ping=` is one line per
cycle, and since ADR 0016 a cycle with every PC away asks each listed host, so requests are cycles × hosts (at most 3).

**The minute has to be a steady-state one.** Four is `60 / BACKOFF_CAP_MS`, which is the
cadence once the ladder has finished climbing; a minute measured from the moment the PC goes
away contains the 2, 4 and 8 second rungs as well and legitimately holds seven. Give the panel
about twenty seconds after stopping the server before clearing the log, or the assertion fails
on a poller that is behaving exactly as designed.

Then start the server and confirm it is noticed within 15s:

```bash
adb logcat -c && <start the PC server> && sleep 15 \
    && adb logcat -d -s DeskPanel | grep -q 'state=online'
```

The clear goes **before** the server starts, never after: the app reacts within one poll, so
the other order is a race the clear usually wins, and it fails looking exactly like an app that
logged nothing.

## Notes

- Resist making the backoff cleverer. Capped exponential is enough, and a pure function stays
  trivially testable.
- Leave the phone overnight with the PC off and check the battery drop in the morning. That is
  the measurement that matters.
