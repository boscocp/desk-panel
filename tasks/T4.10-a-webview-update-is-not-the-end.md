# T4.10 — A WebView update does not leave the panel dead

Size: M · Prereqs: T4.4, T5.6 · Files:
`android/app/src/main/java/dev/bosco/deskpanel/PanelService.java`,
`docs/adr/0023-a-watchdog-brings-the-service-back.md`, `docs/adr/0014-poll-loop-outlives-the-screen.md`

Requires: the phone on adb

## Goal

Found on 2026-10-13. At 03:18:58 the Play Store updated Android System WebView to
154.0.8037.107, and the system killed the app as a WebView dependent:
`am_kill … dev.bosco.deskpanel … stop com.google.android.webview due to installPackageLI`,
recorded in `exit-info` as reason 10 (USER REQUESTED). `START_STICKY` did not bring the service
back, and nothing else does. The panel stayed dead until it was launched by hand at 09:20, so
the PC that came up in the morning lit nothing.

The cheap mitigation is on the device: turn off auto-update for Android System WebView in the
Play Store. This task is the code half. Something has to bring the service back after a
dependent kill. One candidate is an `AlarmManager` watchdog that outlives the process. Measure
first which of these survives this kind of kill on MIUI and is allowed to start the service
from the background on API 31.

## Steps

1. **Reproduce.** `adb shell am force-stop com.google.android.webview` kills the app the same
   way: `exit-info` reason 10, `stop com.google.android.webview due to …`. Nothing restarted it
   for 90 s, and `dumpsys package` still says `stopped=false`, so the app's alarms survive.
2. **Watchdog** ([ADR 0023](../docs/adr/0023-a-watchdog-brings-the-service-back.md)):
   `PanelService` re-arms a 15 min `setAndAllowWhileIdle` alarm on every `onStartCommand`. It
   targets the service via `PendingIntent.getForegroundService` with `ACTION_WATCHDOG`, and
   `onDestroy` cancels it.
3. A revival logs `service revived by watchdog`.
4. `SYSTEM_ALERT_WINDOW` in the manifest, granted in INSTALL-PHONE step 4. Without it, the
   revived service's `startActivity` is refused (`Abort background activity starts`) because the
   kill removed the panel's task.

## Acceptance

```bash
docker compose -f docker/compose.yml run --rm build ./gradlew test
grep -q 'getForegroundService' android/app/src/main/java/dev/bosco/deskpanel/PanelService.java
grep -q 'SYSTEM_ALERT_WINDOW' android/app/src/main/AndroidManifest.xml
test -f docs/adr/0023-a-watchdog-brings-the-service-back.md
python scripts/check_acceptance.py
```

On the phone, with this build installed and the app running:

```bash
adb shell appops get dev.bosco.deskpanel SYSTEM_ALERT_WINDOW | grep -q allow
adb shell dumpsys alarm | grep -q 'dev.bosco.deskpanel.WATCHDOG'
adb shell am force-stop com.google.android.webview
adb shell dumpsys alarm | grep -q 'dev.bosco.deskpanel.WATCHDOG'   # survives the kill
```

## Manual check

- Within about 26 minutes of the kill, without anybody touching the phone, the log shows
  `service revived by watchdog` and, with a PC up, `state=online` and `screen=wake`.
