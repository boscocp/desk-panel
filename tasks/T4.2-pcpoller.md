# T4.2 — `PcPoller`

Size: M · Prereqs: T4.1 · Files: `PcPoller.java`, `PcState.java`, `MainActivity.java`

## Goal

Know, within a couple of seconds, whether the PC is awake and logged in.

## Steps

1. `PcState.java` — a plain class with **no Android imports**: current state, transition logic,
   and the backoff schedule. Kept Android-free so `./gradlew test` can cover it on the JVM with
   no device (TT.5).
2. `PcPoller.java` — a background thread or `ScheduledExecutorService` hitting
   `http://<pc-ip>:8777/ping` with `HttpURLConnection`. Short connect and read timeouts, around
   1500 ms; a hung socket must not stall the loop.
3. Never touch the network on the UI thread. Marshal results back with
   `runOnUiThread` / a `Handler`.
4. Start polling in `onResume`, stop in `onPause`. A poller surviving the Activity is a leak.
5. Log every transition — and only transitions, not every poll:
   `Log.i("DeskPanel", "state=online")` / `state=offline`.

## Acceptance

```bash
adb logcat -s DeskPanel
```

With the server running, a `state=online` line appears. Kill the server: `state=offline` within
a few seconds. Start it again: `state=online`. No log spam between transitions.

## Notes

- Poll every 2s while online. The offline backoff arrives in T5.3 — do not build it here, but
  do put the interval behind `PcState` so T5.3 only changes one place.
- Any failure is offline: timeout, connection refused, non-200, DNS. Do not try to distinguish
  them for the state decision.
