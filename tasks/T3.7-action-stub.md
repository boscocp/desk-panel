# T3.7 — `POST /action/{id}` stub

Size: S · Prereqs: T3.1 · Files: `server/server.py`, `docs/ARCHITECTURE.md`

## Goal

Reserve the shape of the v2 shortcut-buttons feature without building it, so adding it later
does not require reworking anything.

## Steps

1. `POST /action/{id}` returns **501 Not Implemented** with a short JSON body.
2. Add an empty `"actions": {}` to `config.example.json`.
3. Document the intended design in a comment next to the handler and in
   `docs/ARCHITECTURE.md`:
   - `id` indexes a **closed allowlist** in config, mapping to a Steam URI or an executable path
   - the request carries an id and **nothing else** — never a command, path or argument
   - launching uses `os.startfile` for URIs; `subprocess` without `shell=True` for executables
   - unknown ids return 404, never an attempt to run anything

## Acceptance

```bash
python server/probe.py --serve --url /action/anything --method POST --expect-status 501
```

`curl -s -w "%{http_code}"` was the obvious way to write this and it is wrong: it *prints* the
code and exits 0 whatever the server answered. The probe asserts it.

## Notes

- The allowlist is the entire security design of this feature. An endpoint that runs whatever it
  is given is a remote shell on the LAN. Writing that constraint down now, while nothing is
  implemented, is the cheapest moment to get it right.
