# T3.14 — A Python upgrade does not get the Mac's server blocked by the firewall

Size: S · Prereqs: T3.10 · Files: `server/install_agent.sh`, `docs/SERVER-SETUP.md`

Requires: the Mac, with the application firewall on

## Goal

Found on 2026-10-13. Homebrew upgraded `python@3.14` at 09:23 and its cleanup deleted the old
keg at about 12:53. The server, still running the deleted binary, kept accepting LAN
connections, but every one died with `OSError: [Errno 57] Socket is not connected`, while
`127.0.0.1` still answered. The last LAN `/ping` 200 was at 12:53:35. The firewall's allow
rule named the old keg's `Python.app`, and Homebrew's Python is ad-hoc signed, so every upgrade
is a new, unknown app to the firewall. A restart picked up `python3` → 3.15, which had no rule
either. The phone saw `IOException: unexpected end of stream` and reported offline with the
Mac in use.

This is a candidate for the unexplained 2026-10-09 report in wave 46 ("o app não mudou pro
servidor do Mac").

## Steps

1. Make `server/install_agent.sh` add and unblock the interpreter it installs with, via
   `socketfilterfw --add … --unblockapp`, and say so.
2. Document in `docs/SERVER-SETUP.md` that a Homebrew Python upgrade needs the installer re-run,
   and show how to recognise the failure: `Socket is not connected` in
   `~/Library/Logs/desk-panel.log`, and `127.0.0.1` answering while the LAN address does not.

## Acceptance

```bash
grep -q 'unblockapp' server/install_agent.sh
python scripts/check_acceptance.py
```

## Manual check

- After a `brew upgrade` of the Python the agent uses, re-running the installer gets the phone
  `ping=ok host=<mac>` again.
