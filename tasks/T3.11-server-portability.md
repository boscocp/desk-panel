# T3.11 — Server portability hardening

Size: S · Prereqs: T3.1, T3.2 · Files: `server/server.py`

Requires: none

## Goal

Make one `server.py` correct on Windows, Linux and macOS. Every item here is a bug **on
Windows today**, independent of the cross-platform decision — which is why this is worth doing
even if the project ever falls back to Windows-only.

## Steps

1. **Config discovery, cwd-independent.** A Scheduled Task with no working directory starts in
   `C:\Windows\System32`, where `open("server/config.json")` resolves to nothing and the server
   exits. The symptom is "the panel is permanently offline after every reboot", which reads
   exactly like the DHCP trap and is not it.

   Add a pure `config_search_paths(argv, env, script_dir) -> list[Path]`, three entries, in
   order: `--config <path>`, then `DESK_PANEL_CONFIG`, then `script_dir / "config.json"`. All
   three launchers pass an absolute `--config`, so cwd never matters for them; the third is for
   running it by hand. A full XDG/APPDATA ladder is scope creep on a single-user desk PC.

2. **`encoding="utf-8"` on every `open()`.** Python does not default to UTF-8 on Windows; it
   reads cp1252. `"city": "São Paulo"` breaks, and `config.example.json` ships `"Sao Paulo"`,
   which hides it until someone types the accent.

3. **`allow_reuse_address = (os.name != "nt")`.** `http.server` sets it to 1. On POSIX that is
   harmless; on Windows `SO_REUSEADDR` lets a second process bind the same port and steal
   connections, so fast user switching silently produces two servers and nondeterministic
   answers. The second instance must die loudly with `EADDRINUSE`.

4. **Version floor.** `server/CLAUDE.md` says Python 3.13; this machine has 3.14 and macOS
   ships no `python3` at all. Restate as **3.11 or newer, stdlib only**, and guard it with a
   `sys.version_info` check that exits non-zero with a readable message — otherwise the failure
   appears as a restart loop in journald or launchd.

5. **`-u` / unbuffered stdout**, and an optional `--log-file <path>` used only by the Windows
   installer. With `pythonw` there is no console and Task Scheduler cannot redirect without
   spawning `cmd /c`, which flashes a window. journald and the plist capture stdout for free,
   so stdout stays the only log path in the code.

6. **Config permission warning, POSIX only.** `config.json` holds the brapi token; warn when
   `st_mode & 0o077`. Windows cannot express this with `os.chmod` — the real control is the
   NTFS ACL — so the check is POSIX-only. **Warn, never refuse to start:** a login signal that
   dies over a permission bit breaks invariant 2 harder than a loose mode bit on a LAN-only box
   risks. Implement as pure `config_permission_warning(mode, platform) -> str | None` so TT.2
   tests it without touching a filesystem.

7. `--check-only`: load config, validate, report, exit. No listener. This is what makes the
   acceptance below runnable anywhere.

## Acceptance

```bash
python -m unittest discover -s server/tests -t .
python -c "import sys; sys.exit(0 if sys.version_info >= (3,11) else 1)"
python server/server.py --config server/config.example.json --check-only
```

The cwd regression this whole task exists for — it must pass from a directory that is not the
repository:

```bash
cd / && python "$OLDPWD/server/server.py" --config "$OLDPWD/server/config.example.json" --check-only
cd / && DESK_PANEL_CONFIG="$OLDPWD/server/config.example.json" python "$OLDPWD/server/server.py" --check-only
```

## Notes

- None of this is Linux work dressed up as portability. Items 1, 2, 3 and 5 are Windows bugs;
  Windows is the platform that runs this daily.
