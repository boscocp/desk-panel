# T8.7 — Linux puts the volume on the stream too

Size: S · Prereqs: T8.4, T8.5, T8.6 · Files: `server/spectrum.py`, `server/server.py`,
`server/tests/test_linux_volume.py`, `docs/adr/0021-the-spectrum-is-a-stream.md`,
`docs/SERVER-SETUP.md`

Requires: a Linux PC with PipeWire or PulseAudio, `parec` and `pactl` on PATH, `spectrum = true`
and `"volume"` in `actions`, for the manual check

## Goal

Reported from the chair on 2026-10-01, on CachyOS, right after the first full device run of the
wave 40–42 features: "o spectrum ta funcionando, a sincronia de barra de som n". The spectrum
followed the music and the volume bar did not follow the knob.

T8.6 gave the level a ride on `/spectrum` and only Windows took it. `server.py` gated it on
`sys.platform == "win32"`, and the Linux source was a plain `HelperSource` around `parec`, which
writes PCM and complaints and never a `v=` line. So the bar was fed only by `/quotes`, behind
`App.VOLUME_TTL_S` (20 s) and the panel's 2 s poll — measured here as **zero `v=` lines across
three knob movements**, against sub-second on Windows.

T8.6's ADR amendment said "`parec` cannot", which is true and was taken to end the matter. The
level is not a property of the capture process, though; it is a property of the sound server,
and on Linux that can be asked on its own.

## Steps

1. `is_sink_event(text)`, pure: true for `Event '…' on sink #N` and for `on server`, false for
   `sink-input #N` (one application's slider), `source` (a microphone) and anything that is not
   an event line.
2. `volume_events_argv()` → `["pactl", "subscribe"]`. Measured on CachyOS: it line-buffers into
   a pipe, so events arrive as they happen.
3. `ParecSource(HelperSource)`: `open()` starts `parec` first, then the watch. The watch reads
   the level once on opening and once per sink event, through `actions.read_volume` — the same
   `wpctl get-volume` `/quotes` uses — and pushes it to the `on_volume` the hub already set.
   `close()` terminates the watch before the capture.
4. No `on_volume` (the `volume` action off, or `reports_volume` false) means `pactl` is never
   started. No `pactl` on PATH means the bars still work, the bar falls back to `/quotes`, and
   the reason is logged once.
5. `reports_volume(platform, which)` owns the list of platforms that send a level: Windows
   always, Linux when `pactl` is present, macOS not yet. `server.py` calls it instead of
   spelling `sys.platform == "win32"` inline.
6. `source_for` builds a `ParecSource` on Linux.

Nothing changes on the phone: the `v=` line and its two checks are T8.6's, and an APK that
already takes them takes these.

## Manual check

- **CachyOS, done 2026-10-01.** With the user unit restarted on this branch, a client read
  `/spectrum` while `wpctl set-volume` moved the knob four times: `v=49` on opening, then
  `v=70`, `v=25`, `v=90`, `v=49`, one per movement and none in between. Frame spacing puts each
  within the same ~50 ms frame as the change. `/quotes` agreed (`{"level": 90}`), and the bar on
  the Redmi went from 4/10 to 9/10 segments.
- **Not covered:** macOS. Its bar still follows `/quotes`; the Swift helper would need the
  CoreAudio read.
