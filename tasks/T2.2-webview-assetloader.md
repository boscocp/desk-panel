# T2.2 — WebView + WebViewAssetLoader  🏁 Milestone A

Size: M · Prereqs: T2.1, T1.1 · Files: `MainActivity.java`, `app/build.gradle.kts`,
`AndroidManifest.xml`

Requires: phone (on adb), with MIUI's **Developer options → "USB debugging (Security settings)"**
and **"Install via USB"** both enabled, and the screen unlocked while the acceptance runs.
Without the first toggle `adb install` fails with `INSTALL_FAILED_USER_RESTRICTED` and
`adb shell input` is silently ignored, so the phone cannot even be woken from the host; MIUI
gates both behind that one switch, and it needs a signed-in Xiaomi account to flip. MIUI also
raises an on-screen install confirmation that a human has to tap.

## Goal

The clock from T1.1, rendered full-screen on the phone, served from inside the APK. First sign
of life, and it validates the container, Gradle, the asset pipeline and rendering at once.

## Steps

1. Add the `androidx.webkit:webkit` dependency.
2. In `MainActivity`, build a `WebViewAssetLoader`:

   ```java
   WebViewAssetLoader loader = new WebViewAssetLoader.Builder()
       .addPathHandler("/assets/", new WebViewAssetLoader.AssetsPathHandler(this))
       .build();
   ```

3. Set a `WebViewClientCompat` whose `shouldInterceptRequest` delegates to the loader.
4. Load `https://appassets.androidplatform.net/assets/index.html`.
5. Enable JavaScript. Set `setMixedContentMode(MIXED_CONTENT_NEVER_ALLOW)` — see
   [ADR 0002](../docs/adr/0002-native-owns-network-io.md). No `INTERNET` permission is needed
   yet; it arrives with T4.1.

## Acceptance

```bash
docker compose -f docker/compose.yml run --rm build ./gradlew assembleRelease
test -f out/desk-panel-release.apk
adb install -r out/desk-panel-release.apk
adb shell am force-stop dev.bosco.deskpanel
adb logcat -c
adb shell am start -n dev.bosco.deskpanel/.MainActivity
sleep 10
adb shell dumpsys window | grep -q 'mCurrentFocus.*dev.bosco.deskpanel'
! adb logcat -d | grep -q 'ERR_\|net::ERR\|Failed to load'
adb logcat -d | grep -qE 'panel=rendered clock="[0-9]{2}:[0-9]{2}:[0-9]{2}"'
```

The `force-stop` and the `logcat -c` both have to come **before** `am start`, and that is worth
stating because getting it wrong produces a confusing red. `panel=rendered` is emitted once, by
`onPageFinished`, during the launch; clearing the buffer after the launch — as an earlier draft
of this block did, folding `logcat -c` into the error-grep line — wipes the very marker the last
line then looks for, and the task fails with a perfectly healthy app on screen. The `force-stop`
matters for the same reason on a re-run: `am start` against an already-foregrounded Activity
reloads nothing, so `onPageFinished` never fires again and the marker never reappears.

The WebView fails to load silently — a blank screen and a console error nobody sees. The
negated grep turns the noisy half of that into a failure.

It does not catch the quiet half. A WebView that renders nothing logs nothing, so an entirely
black panel passes a "no errors" test exactly as a working one does. The last line closes that
hole from the other side: `MainActivity.onPageFinished` reads `#clock` out of the live DOM and
logs `panel=rendered clock="HH:MM:SS"`, so a time-shaped value is positive evidence that the
asset pipeline, the `https` origin, JavaScript and the DOM all worked. Same reasoning as the
`state=` and `screen=` markers — Android exposes no documented way to ask the device what is on
screen, so the app reports it ([ADR 0009](../docs/adr/0009-testing-strategy.md)).

## Correction — this acceptance block was rewritten

As originally written the block could not pass, and following it would have undone T7.1. Three
separate defects, all from the file predating T7.1:

- `out/desk-panel-debug.apk` is not a path the build ever produces. T7.1 renames only the
  release artefact; debug stays `out/app-debug.apk`, which T3.6 and the server already expect.
- Installing the debug APK is the exact failure T7.1 was moved into phase 2 to prevent. Android
  refuses to install a differently-signed APK over an existing one, so a debug-first install
  forces an uninstall later, discarding the MIUI grants T2.4 spends a session on. This task is
  the **first** install on the device; it must lay down the release key.
- `adb install` does not start an Activity, so the `mCurrentFocus` grep was asserting against
  whatever happened to be foreground. It needs an `am start` in front of it to mean anything.

## Manual check

The clock renders full-screen and updates once per second.

## Notes

- The `https://appassets.androidplatform.net` origin is what makes the page a secure context.
  Do not switch to `file://` to "simplify" — that loses the secure origin and breaks the
  premise the whole design rests on.
- If the page is blank, check `shouldInterceptRequest` is wired and the asset path matches
  `/assets/` exactly.
