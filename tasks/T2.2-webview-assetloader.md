# T2.2 — WebView + WebViewAssetLoader  🏁 Milestone A

Size: M · Prereqs: T2.1, T1.1 · Files: `MainActivity.java`, `app/build.gradle.kts`,
`AndroidManifest.xml`

Requires: phone (on adb)

## Goal

The clock from T1.1, rendered full-screen on the phone, served from inside the APK. First sign
of life, and it validates the container, Gradle, the asset pipeline and rendering at once.

## Steps

1. Add the `androidx.webkit:webkit` dependency.
2. In `MainActivity`, build a `WebViewAssetLoader`:

   ```java
   WebViewAssetLoader loader = new WebViewAssetLoader.Builder()
       .addPathHandler("/assets/", new WebViewAssetLoader.AssetsPathHandler(this))
       .build();
   ```

3. Set a `WebViewClientCompat` whose `shouldInterceptRequest` delegates to the loader.
4. Load `https://appassets.androidplatform.net/assets/index.html`.
5. Enable JavaScript. Set `setMixedContentMode(MIXED_CONTENT_NEVER_ALLOW)` — see
   [ADR 0002](../docs/adr/0002-native-owns-network-io.md). No `INTERNET` permission is needed
   yet; it arrives with T4.1.

## Acceptance

```bash
docker compose -f docker/compose.yml run --rm build ./gradlew assembleDebug
```

Install on the phone (browser download from the PC, or `adb install`). The clock renders
full-screen and updates once per second.

## Notes

- The `https://appassets.androidplatform.net` origin is what makes the page a secure context.
  Do not switch to `file://` to "simplify" — that loses the secure origin and breaks the
  premise the whole design rests on.
- If the page is blank, check `shouldInterceptRequest` is wired and the asset path matches
  `/assets/` exactly.
