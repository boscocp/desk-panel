# T4.1 — `network_security_config.xml`

Size: S · Prereqs: T2.1, T3.1 · Files:
`android/app/src/main/res/xml/network_security_config.xml`, `AndroidManifest.xml`

## Goal

Allow cleartext HTTP to the PC, and to nothing else.

## Steps

1. Add the `INTERNET` permission to the manifest.
2. Create `res/xml/network_security_config.xml`:

   ```xml
   <network-security-config>
     <domain-config cleartextTrafficPermitted="true">
       <domain includeSubdomains="false">192.168.x.y</domain>
     </domain-config>
   </network-security-config>
   ```

   Use the static address reserved in T3.5.
3. Reference it: `android:networkSecurityConfig="@xml/network_security_config"` on
   `<application>`.
4. Do **not** use `<base-config cleartextTrafficPermitted="true">` and do not set
   `android:usesCleartextTraffic="true"`. Both open cleartext globally, which is exactly what
   this scoping exists to prevent.

## Acceptance

A native HTTP call to the PC's address succeeds. A native call to any other `http://` address
is blocked — check logcat for the cleartext rejection. Since API 28 cleartext is off by
default, so the negative case works without extra effort.

## Notes

- The pinned address couples the app to the DHCP reservation. If the PC's IP changes, the app
  reports "offline" permanently and looks broken. This is called out in `CLAUDE.md` for a
  reason.
- This config governs **native** requests. The WebView keeps `MIXED_CONTENT_NEVER_ALLOW`,
  because the page never makes requests at all
  ([ADR 0002](../docs/adr/0002-native-owns-network-io.md)).
