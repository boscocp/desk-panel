# T5.2 — Timeouts, retry and failure tolerance

Size: S · Prereqs: T5.1 · Files: `PcPoller.java`, `DataPoller.java`

## Goal

The panel survives a flaky network without crashing, freezing or needing a restart.

## Steps

1. Short connect and read timeouts on both pollers, around 1500 ms. Never block indefinitely.
2. Catch everything on the poller thread. An uncaught exception there kills the loop, and the
   panel silently stops updating while still looking alive — the worst failure mode available.
3. Data failures keep the last known values on screen rather than blanking them. A stale price
   beats an empty card.
4. A ping failure is simply "offline" — that path already exists and needs no special handling.
5. Do not let failures accumulate state. After a recovery, behaviour should be identical to a
   fresh start.

## Acceptance

Turn the phone's Wi-Fi off for 30 seconds, then back on.

```bash
adb logcat -s DeskPanel
```

No crash, no ANR, no exception trace. The panel resumes on its own without being reopened.

## Notes

- Test with Wi-Fi off, not with the server stopped. They fail differently: one is a timeout,
  the other a connection refused.
- Watch for a thread leak — a poller that restarts on recovery without the old one stopping.
