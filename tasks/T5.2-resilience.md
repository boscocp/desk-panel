# T5.2 — Timeouts, retry and failure tolerance

Size: S · Prereqs: T5.1 · Files: `PcPoller.java`, `DataPoller.java`

Requires: phone (on adb)

## Goal

The panel survives a flaky network without crashing, freezing or needing a restart.

## Steps

1. Short connect and read timeouts on both pollers, around 1500 ms. Never block indefinitely.
2. Catch everything on the poller thread. An uncaught exception there kills the loop, and the
   panel silently stops updating while still looking alive — the worst failure mode available.
3. Data failures keep the last known values on screen rather than blanking them. A stale price
   beats an empty card.
4. A ping failure is simply "offline" — that path already exists and needs no special handling.
5. Do not let failures accumulate state. After a recovery, behaviour should be identical to a
   fresh start.

## Acceptance

`adb logcat -c` goes **before** the Wi-Fi is dropped, never after. The whole point is to
capture the outage; clearing afterwards throws away the part of the log the test is about, and
leaves a window in which a healthy panel and a dead one look identical.

```bash
adb logcat -c
adb shell svc wifi disable && sleep 30 && adb shell svc wifi enable && sleep 30
adb logcat -d > /tmp/desk-panel-resilience.log
! grep -qE 'FATAL EXCEPTION|ANR in|E AndroidRuntime' /tmp/desk-panel-resilience.log
grep -q 'state=offline' /tmp/desk-panel-resilience.log
grep -q 'state=online'  /tmp/desk-panel-resilience.log
test "$(grep -c 'ping=ok' /tmp/desk-panel-resilience.log)" -ge 3
```

The negated grep is the first assertion: no crash, no ANR, no exception trace anywhere in the
log — not just under the app's own tag, because a WebView crash lands under another one.

The two `state=` greps are the second: the panel noticed the network going away *and* coming
back. One without the other is the failure this task is about.

The `ping=ok` count is the third, and it is the one that proves the loop is still alive rather
than silently dead. **`state=` cannot do that job**, which is what this task used to ask it to
do: `state=` is a transition marker, so a panel that has been healthy for a minute logs none at
all, and the assertion passed or failed on whether a transition happened to fall inside the
window rather than on whether anything was still running. `ping=` is the per-probe heartbeat
T5.3 adds for exactly this.

## Notes

- Test with Wi-Fi off, not with the server stopped. They fail differently: one is a timeout,
  the other a connection refused.
- Watch for a thread leak — a poller that restarts on recovery without the old one stopping.
