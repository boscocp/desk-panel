# T7.1 — Release keystore and signing

Size: S · Prereqs: T4.3 · Files: `android/app/build.gradle.kts`, `docs/BUILD.md`

## Goal

Sign with a stable key from now on, so every future install lands on top of the previous one.

Do this **early**. Alternating between the debug key and a release key makes Android refuse to
install over the existing app; the only way out is uninstalling, which throws away device state
and every MIUI permission you spent T2.4 granting.

## Steps

1. Generate the keystore once:

   ```bash
   keytool -genkeypair -v -keystore desk-panel.keystore \
     -alias desk-panel -keyalg RSA -keysize 2048 -validity 10000
   ```

2. Put the path and passwords in `keystore.properties` — **gitignored**, along with
   `*.keystore` and `*.jks`. Already covered by `.gitignore`; verify rather than assume.
3. Read it in `build.gradle.kts` and define a `release` signing config. If the file is absent,
   fall back to debug signing so a fresh clone still builds.
4. Back the keystore up somewhere outside the repo. Losing it means never updating this install
   again.
5. Document the whole thing in `docs/BUILD.md`.

## Acceptance

```bash
docker compose -f docker/compose.yml run --rm build ./gradlew assembleRelease
git check-ignore keystore.properties desk-panel.keystore   # both listed
git status --porcelain | grep -i keystore                  # no output
```

Install the release APK over an existing install without uninstalling first.

## Notes

- This repo goes public later. A keystore or password in the history is not something a later
  commit can remove — T7.3 audits for it, but not committing it in the first place is the only
  real protection.
