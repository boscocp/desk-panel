# T7.1 — Release keystore and signing

Size: S · Prereqs: T2.1 · Files: `android/app/build.gradle.kts`, `docs/BUILD.md`, `.env.example`

Requires: `.env` and `desk-panel.keystore` created once on this machine — both are
gitignored, hold signing passwords, and no agent may create them. The phone is needed only
for the manual install-over check, not for any acceptance command.

## Goal

Sign with a stable key from now on, so every future install lands on top of the previous one.

## The `check-ignore` criterion could never pass

It was written as one call with two paths:

    git check-ignore -q keystore.properties desk-panel.keystore

`git check-ignore` rejects that outright — `fatal: --quiet is only valid with a single
pathname` — and exits **128**, whatever the `.gitignore` actually says. The criterion could not
pass on a correctly configured repository, and it could not fail on a broken one either: it
returns 128 in both cases. Split into two calls.

Its neighbour was self-defeating in a different way. This:

    ! git status --porcelain | grep -qi keystore

greps every path in `git status` for the substring `keystore`, case-insensitively — and this
task's own file is `tasks/T7.1-release-keystore.md`. **Editing T7.1 failed T7.1.** It also could
not tell a staged key from any file whose name merely contains the word. Now anchored to real
key material: a path ending in `.keystore`/`.jks`, or named `keystore.properties`.

This is the same failure mode as T4.1's cleartext grep, which approved the configuration it
existed to forbid. Both are gates, both were written once and never exercised against a case
they should reject, and a gate that cannot distinguish pass from fail is worse than no gate —
it looks like coverage.

## Why `Prereqs:` changed from T4.3 to T2.1

`STATUS.md` moved this task into phase 2 and argues why at length: Android refuses to install a
differently-signed APK over an existing one, the only way out is an uninstall, and an uninstall
throws away the device state and every MIUI permission T2.4 spent a session granting. So the
release key has to exist before the first install.

The header still said `Prereqs: T4.3` — the Milestone B task, far later and gated on the phone.
Followed literally, this task could not run until after exactly the installs it exists to
protect. The real prerequisite is T2.1: a Gradle project to add the signing config to.

`Requires:` was also overstated. It claimed the phone, but not one of the five acceptance
commands touches `adb`; the phone is needed for the manual install-over check only. What it
actually requires is the keystore, which is a human action.

Do this **early**. Alternating between the debug key and a release key makes Android refuse to
install over the existing app; the only way out is uninstalling, which throws away device state
and every MIUI permission you spent T2.4 granting.

## Steps

1. Generate the keystore once:

   ```bash
   keytool -genkeypair -v -keystore desk-panel.keystore \
     -alias desk-panel -keyalg RSA -keysize 2048 -validity 10000
   ```

2. Put the path and passwords in `.env` at the repository root, under the keys
   `KEYSTORE_FILE`, `KEYSTORE_PASSWORD`, `KEY_ALIAS` and `KEY_PASSWORD` — **gitignored**,
   along with `*.keystore` and `*.jks`. Already covered by `.gitignore`; verify rather than
   assume.
3. Read it in `build.gradle.kts` and define a `release` signing config. If the values are
   absent, fall back to debug signing so a fresh clone still builds.
4. Back the keystore up somewhere outside the repo. Losing it means never updating this install
   again.
5. Document the whole thing in `docs/BUILD.md`.

## Acceptance

```bash
docker compose -f docker/compose.yml run --rm build ./gradlew assembleRelease
test -f out/desk-panel-release.apk
git check-ignore -q .env
git check-ignore -q desk-panel.keystore
! git status --porcelain | grep -qiE '(\.(keystore|jks)|(^|[ /])(keystore\.properties|\.env))$'
! git ls-files | grep -qiE '\.(keystore|jks)$|^(keystore\.properties|\.env)$'
```

`git status --porcelain | grep -i keystore   # no output` was the original wording and it is
backwards: grep exits **1** when it finds nothing, so the criterion failed precisely when the
repo was clean. Negating it is the fix. The last line is stronger than both: it catches a
keystore that was committed before it was ignored.

## Manual check

Install the release APK over an existing install without uninstalling first. That is the whole
point of doing this before T2.4, not after.

## Notes

- **`keystore.properties` became `.env` (T2.5).** The signing values moved into the single
  build-time local file described by [ADR 0013](../docs/adr/0013-local-configuration-boundaries.md),
  beside `PC_IP`; the behaviour above is unchanged, only the filename and the key names are.
  The acceptance still guards `keystore.properties` as well, because a machine that predates
  T2.5 may still have one lying around and it must stay out of git either way.
- This repo goes public later. A keystore or password in the history is not something a later
  commit can remove — T7.3 audits for it, but not committing it in the first place is the only
  real protection.
