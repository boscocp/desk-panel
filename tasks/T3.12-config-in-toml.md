# T3.12 — Config the owner can actually edit: TOML, with the catalogue in the file

Size: M · Prereqs: T3.2, T3.3, T3.4 · Pairs with: TT.2 · Files: `server/config_format.py`,
`server/server.py`, `server/config.example.toml`, `docs/SERVER-SETUP.md`, `docs/BUILD.md`

Requires: none

## Goal

Choosing which tickers, currencies and coins the panel shows should feel like editing a
shopping list, not like editing a data structure.

Nothing about this is a new capability: `server/config.json` already drives all of it, and
changing it has never needed a rebuild — that rule is in `server/CLAUDE.md` and has held since
T3.2. What is missing is **ergonomics**. JSON has no comments, so the file cannot say what a
field means or what the legal values are; a trailing comma is a fatal error a page away from
where it was typed; and every string needs quoting. The owner currently finds out which tickers
are allowed by reading `providers_brapi.py`.

## YAML was asked for, and TOML is what this delivers

The request was YAML. It is not available: `server/CLAUDE.md` makes "standard library only, no
pip, no requirements.txt" a **hard constraint**, on the grounds that the server has to run on a
clean box with nothing installed, and PyYAML is a dependency. Writing a YAML subset parser by
hand would be worse — a format everyone thinks they know, implemented almost correctly.

`tomllib` has been in the standard library since Python 3.11, which is exactly this project's
floor (T3.11). It gives every property the request was actually about: comments, no trailing
comma traps, bare keys, obvious lists. The repository already carries `reasonix.toml`, so it is
not even a new format here.

**If YAML is wanted anyway**, that is a decision to break the stdlib-only rule deliberately, and
it belongs in an ADR amending `server/CLAUDE.md` — not in this task file.

## Steps

1. `server/config_format.py` — a pure `parse(text) -> dict` over `tomllib`, plus the merge with
   `DEFAULT_CONFIG` that `load_config` already does. Pure so TT.2 covers it without a file.
2. `server/config.example.toml`, **commented as documentation rather than as an example**: what
   each key does, its default, and the catalogue of values that actually work —

   - which brapi tickers answer without a token (`PETR4`, `MGLU3`, `VALE3`, `ITUB4`) and that
     **one paid ticker 401s the whole request**, so a single unlisted symbol empties the card
   - that FX pairs are anything AwesomeAPI serves, spelled `USD-BRL`
   - that crypto is any Binance symbol, spelled bare (`BTC`), quoted against USDT

   This is the half that matters. The format change is a convenience; the catalogue is the thing
   that stops the owner from having to read provider source.
3. **Read both formats during the transition.** `config.toml` wins where both exist; a lone
   `config.json` keeps working and produces a one-line notice naming the replacement. Nobody's
   running panel may break because a file was renamed.
4. `config_search_paths` gains the `.toml` candidates, in the same order it already uses.
5. A `theme` key, reserved and defaulted, for T6.7 to select against.

## Acceptance

```bash
python -m unittest discover -s server/tests -t .
python server/server.py --check-only --config server/config.example.toml
```

Both exit 0, with no network. And the transition is real rather than assumed:

```bash
python server/probe.py --serve --url /quotes --expect-json-keys quotes,fx,crypto
python -c "import tomllib,pathlib; tomllib.loads(pathlib.Path('server/config.example.toml').read_text())"
```

## Manual check

- The example file answers "which tickers can I put here?" without opening any `.py`.
- An owner holding only a `config.json` starts the server and sees it work, plus one line
  telling them what to rename.

## Notes

- `tomllib` is read-only, which is fine: nothing in this project writes config.
- `server/config.json` is gitignored and holds the brapi token; `config.toml` inherits both the
  ignore rule and the permission warning in `config_permission_warning`.
- ADR 0013 draws the line between build-time (`.env`) and runtime (this file) config. This task
  changes the format of the runtime side and nothing about the line.
