# T6.6 — A very slow scroll, but only when a card overflows

Size: M · Prereqs: T6.7, T5.1 · Files: `web/js/format.js`, `web/js/app.js`,
`web/css/style.css`

Requires: the phone, for the manual check only

## Goal

Let the owner configure more rows than fit and still see all of them, by scrolling each
overflowing card slowly enough that the panel never looks busy.

## The problem this is fixing

`style.css` says it outright today: *"The page is exactly one screen: nothing scrolls, and every
card clips its own content, so an extra ticker arriving from server config can never push a
section off the bottom edge."* That was the right call when the alternative was a broken layout.
Its cost is that the sixth ticker is **invisible** — not truncated, not marked, just absent,
with nothing on the panel saying so. Once T3.12 makes adding tickers easy, that cost is paid far
more often.

## Steps

1. A pure `overflowsBy(rowCount, visibleRows)` in `format.js` — how many rows are hidden, zero
   when they all fit. Pure, so the decision is tested without a DOM; the acceptance asserts on
   it rather than on pixels.
2. Scroll **only** when it returns non-zero. A card that scrolls with two rows in it is motion
   for its own sake, and this panel sits in someone's peripheral vision all day.
3. Slow: on the order of one row every few seconds, and a pause at the top and bottom of each
   pass. The number belongs in a CSS custom property so T6.7's themes can set it.
4. **The refresh must not restart the scroll.** `window.onData` rebuilds each list wholesale
   (`container.textContent = ''`), so any CSS animation resets every 60s and the card would
   never reach the rows it exists to reveal. Either update rows in place when the symbol set has
   not changed, or carry the scroll offset across the rebuild. This is the whole of the task's
   difficulty.
5. Loop rather than snap back: a seamless wrap, or a slow return pass. A jump is the one motion
   the eye cannot ignore.

## Acceptance

```bash
node --test "web/test/**/*.test.js"
```

Covering `overflowsBy` at the boundary in both directions — exactly filling the card must not
scroll, one more row must — and that a rebuild with an unchanged symbol set does not reset the
offset.

```bash
! grep -n 'overflow: hidden' web/themes/neon/theme.css | grep -q 'card-list'
```

**Path amended by T6.7**, which moved the panel's stylesheet to `web/themes/neon/theme.css`
and left `web/css/style.css` holding the box, the ground and the blackout. The scroll this
task adds is presentation, so it belongs on the theme side of that line — which is why T6.7
is a prerequisite here, and why the rule this grep names is now a theme's rule and not the
panel's.

The clip that hid the rows is gone from the lists it hid them in.

## Manual check

- With two tickers, nothing moves at all. This is the one most likely to regress.
- With ten, every row becomes readable within one pass, and the movement is slow enough to be
  unnoticeable unless looked at.
- A data refresh mid-pass does not jump, restart, or skip a row.

## Notes

- Movement helps burn-in rather than hurting it, so this pulls in the same direction as T6.2's
  layout shift. Check they do not fight: two independent motions on one card would be visible in
  a way neither is alone.
- The clock and weather cards do not overflow and must not acquire motion from a shared rule.
- `prefers-reduced-motion` is worth honouring even though this device will never set it, because
  the browser is where this gets developed.
