# T8.8 — macOS puts the volume on the stream too

Size: S · Prereqs: T8.4, T8.5, T8.6, T8.7 · Files: `server/mac/spectrum_tap.swift`,
`server/spectrum.py`, `server/server.py`, `server/tests/test_mac_volume.py`,
`server/tests/test_linux_volume.py`, `docs/adr/0021-the-spectrum-is-a-stream.md`,
`docs/SERVER-SETUP.md`

Requires: a Mac on macOS 14.2+ with the Command Line Tools, `spectrum = true` and `"volume"` in
`actions`, System Audio Recording allowed for the server's python, for the manual check

## Goal

Asked from the chair on 2026-10-09, on the Mac: the volume bar should follow the Mac's sound
slider the way it already does on Windows (T8.6) and CachyOS (T8.7). macOS was the last
platform whose bar followed only `/quotes`, behind `App.VOLUME_TTL_S` (20 s) and the panel's
2 s poll. Wave 43 and wave 44 both left it as the next step.

## Steps

1. The Swift helper reads the default output's
   `kAudioHardwareServiceDeviceProperty_VirtualMainVolume`, the value AppleScript's
   `output volume` reports, as a whole percent clamped to 0..100.
2. It writes `v=<level>` on **stderr**, once on starting and on each change, and never the same
   level twice in a row. stdout stays the `rate=` line and PCM.
3. Property listeners, not a poll: one on the volume of the current output, and one on
   `kAudioHardwarePropertyDefaultOutputDevice` that moves the read to the new output.
4. `reports_volume("darwin")` is True. Nothing else changes in Python, and nothing on the phone.

## Manual check

- **macOS 26.5, done 2026-10-09.** The helper alone printed `v=100` on starting, then `v=30`,
  `v=55`, `v=80` and `v=100` as `osascript` set those levels. `osascript` read back the same
  number each time. Then the agent was restarted with the rebuilt helper, and a client read
  `/spectrum` while the level moved 100 → 40 → 70 → 25 → 100. The stream carried exactly those
  five `v=` lines among 186 lines, and `/quotes` said `{"level": 100}` afterwards.
- **Not measured:** the bar on the Redmi. It runs wave 43's APK, which takes the `v=` line, so
  no rebuild is needed; the owner watching it move is the last check.
- **Not measured:** a change of default output, such as speakers to AirPods. The listener for
  it is in place, but nothing was switched during the run.
- **Not measured:** levels that are not whole percents, like the volume keys' sixteenths. If
  AppleScript rounds differently, the stream and `/quotes` can differ by 1 until the next read.
