# T6.1 — Landscape layout and neon palette

Size: M · Prereqs: T1.1 · Files: `web/css/style.css`, `web/index.html`

Requires: node on the host, and Chrome for the manual check

## Goal

The panel looks the way it was designed to look: cyberpunk neon, landscape, readable across a
desk.

## Palette

Changed at the user's request while the task was being executed. The original cut was cyan on
a violet-tinted black; he asked for purple leaning pink/red and then settled on the exact
values below. The acceptance criteria follow the palette, so the literals asserted there
changed with it.

| Token | Value | Use |
|---|---|---|
| Ground | `#000000` | Pure black — see below |
| Accent | `#D53FA7` | Primary — clock, prices, weather |
| Accent dim | `#BB81AA` | Secondary — date, row labels, card titles, borders |
| Up | `#3FD56C` | Positive change — the accent's hue complement |
| Down | `#FF3D6E` | Negative change — the accent pushed toward red |

**The ground is pure black for a reason that outlives taste.** The panel is an AMOLED showing
one layout for hours at a time, which is exactly the burn-in case ADR 0008 and T6.2 are about.
At `#000000` the pixel is off: no power, and nothing there to burn in. A tinted ground lights
every pixel on the panel all day instead. Anyone tempted to "improve" this back to a
violet-black should change T6.2 first.

**Up and down must never differ only in shade.** On a panel that is otherwise entirely pink, a
red "down" sits too close to the accent to be read at a glance. They are separated three ways
at once: hue (`--up` is the accent's exact complement, 138° against 318°), brightness (10.9:1
against 6.1:1 on black), and the sign `format.js` already writes into the text. Any one of the
three surviving is enough to read the panel — which also covers a red/green colour-blind
reader, for whom the brightness gap and the sign both still work.

**Secondary means desaturated, not dimmer.** `--accent-dim` carries the smallest text on the
panel, read from about 50cm, so it measures *more* contrast than the accent, not less: 6.8:1
against 5.1:1 on black. De-emphasis comes from dropping saturation (64% to 30%) at the same
lightness.

## Steps

1. CSS custom properties for every colour. Hard-coded hex values scattered through the
   stylesheet make the night profile (T6.4) painful.
2. CSS Grid at 2400x1080 landscape: clock and date on the left, quote rows in the middle,
   weather on the right. Leave a reserved area for the v2 shortcut buttons so adding them later
   is not a re-layout.
3. Condensed typography. System fonts only — **no Google Fonts, no CDN.** The WebView has no
   network by design ([ADR 0002](../docs/adr/0002-native-owns-network-io.md)), so a webfont
   would simply fail to load.
4. Tabular figures for all numbers, or prices jitter on every update.
5. Keep most pixels genuinely black. It is the palette's job and it happens to be the best thing
   for both AMOLED power draw and burn-in.

## Acceptance

```bash
node --check web/js/app.js
node --test "web/test/**/*.test.js"
grep -q '#000000' web/css/style.css
grep -q '#D53FA7' web/css/style.css
grep -q 'var(--accent)' web/css/style.css
! grep -qE 'overflow:\s*visible' web/css/style.css
```

The palette is checkable; the layout is not. Colours come from the table above, asserted as
literals so a future edit cannot quietly drift them.

**Be clear about what those greps prove, because it is less than it looks.** The stylesheet
defines the palette as custom properties on `:root`, so `grep -q '#D53FA7'` proves the value is
*defined* somewhere in the file. It does not prove that a single pixel is painted with it: a
`:root` block listing all five literals passes even if every rule underneath ignores them. That
is strictly weaker than it was when the hex sat inline at the point of use, and it is the price
of having one place for T6.4 to redefine.

The `var(--accent)` line closes part of that gap — at least one rule consumes the token — and
no more. Proving the clock is actually painted `#D53FA7` needs a computed style off a real
render, which is T6.3 on the device and the Espresso-Web work in TT.7, not a grep. Read a green
check here as "the palette has not drifted", never as "the panel looks right".

## Manual check

`web/index.html` in a browser at a viewport of exactly **872 x 392 CSS px** — the device's real
landscape viewport, not its 2400x1080 physical resolution — with nothing clipped, nothing
overlapping, and the computed colours matching the table above in devtools.

## How the layout was verified

Not by looking at a screenshot. A screenshot proves the page rendered; it does not prove the
fifth card is on screen, which is the entire defect this task exists to fix. The check that
matters is geometric, and it is cheap to repeat:

Drive a headless browser over its automation protocol (Firefox + Marionette works with no
driver binary and no npm dependency; Chrome DevTools Protocol would do as well), load
`web/index.html` from `file://` so `mock.js` feeds it, then in the page assert:

- `document.documentElement.scrollHeight` equals the viewport height — the page is one screen.
- every element under `body` has a `getBoundingClientRect()` inside the viewport box.
- no section has `scrollHeight > clientHeight`, which is a card clipping its own content.

**Calibrate the viewport before believing any of it.** `SetWindowRect` (and `--window-size`)
sizes the *outer* window, not the layout viewport. Asking for 872x392 on this setup produced an
`innerHeight` of **306**, and every measurement taken against it would have been a lie in the
safe direction. Iterate `SetWindowRect` until `window.innerWidth/innerHeight` are exactly
872x392, and print what you calibrated to.

Run it twice: once on `mock.js` as served, once on a stress payload. `mock.js` already carries
the long symbol, the six-figure price, the sub-1 price and the zero change; the stress pass adds
a long city (`Sao Jose dos Campos`), the longest label in `format.js`
(`Thunderstorm, heavy hail`), a negative temperature, a pt-BR date, and `stale-badge` forced
visible — none of which appear in a typical tick, and all of which are what the layout breaks on.

## Notes

- Check with the longest realistic content: a five-character ticker, a six-figure crypto price,
  a negative change. Layout breaks on the widest case, never the typical one.
- Design for roughly 50 cm viewing distance. Bigger than a desktop UI, smaller than a TV.
