# T3.9 — Linux: systemd user unit scoped to the graphical session

Size: M · Prereqs: T3.5 · Files: `server/desk-panel.service.in`,
`server/install_user_unit.sh`, `docs/SERVER-SETUP.md`

Requires: a graphical login on the Linux host, and SSH access to it from another device

## Goal

The same signal on Linux: the server lives exactly as long as a graphical session does.

## Steps

1. `server/desk-panel.service.in`, installed to `~/.config/systemd/user/desk-panel.service`:

   ```ini
   [Unit]
   Description=desk-panel login signal
   PartOf=graphical-session.target
   After=graphical-session.target

   [Service]
   Type=exec
   ExecStart=/usr/bin/python3 -u %h/projects/desk-panel/server/server.py --config %h/.config/desk-panel/config.json
   Restart=on-failure
   RestartSec=5

   [Install]
   WantedBy=graphical-session.target
   ```

   `WantedBy=default.target` — which `docs/SERVER-SETUP.md` currently recommends — is the wrong
   answer and the acceptance below is written to catch it. `PartOf=` is what stops the unit at
   logout; `WantedBy=` alone leaves it running, because logind defaults to
   `KillUserProcesses=no`.

2. `server/install_user_unit.sh`: render the template, `systemctl --user daemon-reload`,
   `enable --now`.
3. Refuse to install if `graphical-session.target` is not active — a DE without systemd
   integration (bare sway/i3 with no `uwsm`) never starts it, and the panel would be
   permanently offline with no error to explain why. Name `uwsm` in the message.
4. Rewrite the `## Linux` section of `docs/SERVER-SETUP.md` around this, including the firewall
   situation: desktop distros usually ship no inbound filter at all, and when they do it is
   firewalld *or* ufw *or* nftables. Detect and instruct; do not write a configurator.

## Acceptance

Shape:

```bash
sh server/install_user_unit.sh
systemctl --user is-enabled desk-panel.service
systemctl --user is-active desk-panel.service
systemctl --user show desk-panel.service -p WantedBy --value | grep -qx graphical-session.target
systemctl --user show desk-panel.service -p PartOf --value | grep -qx graphical-session.target
python server/verify_login_scope.py
```

The linger proof — static, no reboot, and it must pass **with `Linger=yes`**, which is this
machine's current state:

```bash
! systemctl --user list-dependencies default.target --all 2>/dev/null | grep -q desk-panel
! systemctl list-unit-files --type=service --no-legend | grep -q '^desk-panel'
! systemctl is-enabled desk-panel.service 2>/dev/null
```

If the unit is not in the transitive closure of `default.target`, a lingering user manager
cannot start it at boot. That is the invariant, proved in three greps.

Behaviour. SSH is the right instrument: an SSH session starts the user manager and reaches
`default.target`, but never `graphical-session.target`. With nobody at the console:

```bash
! ssh <user>@<pc-ip> 'systemctl --user is-active desk-panel.service'
python server/probe.py --host <pc-ip> --expect down
```

A `WantedBy=default.target` unit passes the shape checks and **fails these two**. That is the
test earning its keep. Then the graphical round trip:

```bash
# log in graphically, wait 30s
python server/probe.py --host <pc-ip> --expect up
# lock the screen, wait 15s
python server/probe.py --host <pc-ip> --expect up
# log out fully, wait 15s
python server/probe.py --host <pc-ip> --expect down
```

## Notes

- Auto-login makes the target activate with no human present, degrading the signal to "powered
  on". `verify_login_scope.py` reports it; nothing at this layer can fix it.
- A second user logging in graphically starts their own unit, which fails to bind while the
  first still answers. The panel then reads "logged in" — true, but not about the owner.
