# T3.2 — Configuration

Size: S · Prereqs: T3.1 · Files: `server/config.example.json`, `server/server.py`

Requires: `server/config.json` seeded once on this machine —
`cp server/config.example.json server/config.json`. It is gitignored, so it is absent from
every fresh checkout, and step 4 below makes the server refuse to start without it.

## Goal

Tickers, city, token and intervals live in config — never in code, and never in the APK.
Changing what the panel shows must never require a rebuild.

## Steps

1. `server/config.example.json` is **already committed**. Fill in the keys this task owns;
   do not rewrite the file, and do not drop the keys other tasks put there.

   Owned here: `port`, `brapi_token`, `quotes`, `crypto`, `fx`, `city`, `timezone`,
   `quotes_interval_s`, `weather_interval_s`. Owned elsewhere: `night_start` / `night_end`
   (T6.4) and `actions` (T3.7) — all three are in the file today.

   ```json
   {
     "port": 8777,
     "brapi_token": "",
     "quotes": ["PETR4", "VALE3", "ITUB4"],
     "crypto": ["BTC", "ETH"],
     "fx": ["USD-BRL", "EUR-BRL"],
     "city": "Sao Paulo",
     "timezone": "America/Sao_Paulo",
     "quotes_interval_s": 300,
     "weather_interval_s": 900
   }
   ```

   `timezone` is new and it is not decoration: T3.4 hardcoded `America/Sao_Paulo` in the
   weather call, so changing `city` alone silently produced min/max aligned to the wrong day.
   Config decides the city; config decides the timezone.

   The `fx` spelling differs on purpose. Config uses `USD-BRL`, the payload contract uses
   `USD/BRL` (`T1.2`), and the server's `normalise` owns the translation — see T3.3.

2. `server/config.json` is the real one, **already gitignored**. Never commit it.
3. Load it in a pure function — `load_config(path) -> dict` — with defaults for missing keys
   and a clear error for malformed JSON. Pure so TT.2 can test it without a server.
4. If `config.json` is missing, exit with a message pointing at the example file.

## Acceptance

```bash
python -m unittest discover -s server/tests -t .
python server/probe.py --serve --expect up
git check-ignore -q server/config.json
python -c "import json,sys; k=set(json.load(open('server/config.example.json'))); sys.exit(0 if {'night_start','night_end','actions'} <= k else 1)"
```

The last line is a regression guard: this task used to specify the full contents of
`config.example.json` without the three keys T3.7 and T6.4 had already added, so executing it
literally deleted committed work.

## Why this task needs a seeded config.json

Step 4 says the server must exit when `config.json` is missing. The acceptance runs
`probe.py --serve --expect up`, which needs the server to start. On a fresh checkout
`config.json` does not exist — it is gitignored — so those two requirements contradict each
other and the task cannot pass.

The contradiction is resolved in favour of step 4: a server that boots with silently-empty
config looks healthy and shows an empty panel, which is the failure mode this project is least
able to notice. So the seeding is a real prerequisite and now says so in the header, rather than
`Requires: none`.

This is not only T3.2's problem. T3.3, T3.4, T3.5, T3.6 and T3.7 all run `--serve` or `curl`
against a live server, so none of them can pass on a machine where the file was never seeded.
One `cp` unblocks all six.

## Manual check

Change a ticker, restart, and observe the change without touching code. That is the property
`server/CLAUDE.md` is protecting: if a change to what the panel shows needs a rebuild, the
design has been violated.
