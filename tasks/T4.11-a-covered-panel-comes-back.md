# T4.11 — A panel covered by another app comes back

Size: S · Prereqs: T4.4, T4.10 · Files:
`android/app/src/main/java/dev/bosco/deskpanel/PanelService.java`,
`android/app/src/main/java/dev/bosco/deskpanel/MainActivity.java`, `docs/INSTALL-PHONE.md`

Requires: the phone on adb

## Goal

Reported from the chair on 2026-10-19: after moving the peripherals from CachyOS to the Mac with
the USB switch, the panel's screen was out and never came back, with both PCs on.

The switch was not the cause. At 13:26:52 Play Services opened a sign-in screen
(`com.google.android.gms/.octarine.ui.OctarineActivity`) over the panel. `FLAG_KEEP_SCREEN_ON`
holds only while the panel's window is the one showing, so the screen timed out behind that
screen. The PC never left, so no `state=` transition raised the panel again. All afternoon the log
read `state=online` and `data=ok` with the phone `Dozing`. The USB switch re-plugging the
phone's cable woke it (`WAKE_REASON_PLUGGED_IN`) onto that screen for 20 s at a time, which
is what the owner saw.

## Steps

1. `MainActivity.onStop` while the device is still interactive means another app covered the
   panel; `onStart` clears it (`PanelService.panelCovered`).
2. `PanelService` listens for `ACTION_SCREEN_OFF`. Online and covered, it raises the panel the
   way the online wake does, and `setTurnScreenOn` lights the screen again. A panel that was in
   front is left alone.
3. That start comes from behind another app's task, so Android 12 refuses it without "Display
   over other apps". The receiver checks `Settings.canDrawOverlays` and says so in the log
   instead of claiming success.
4. **Measured: `adb install -r` resets `SYSTEM_ALERT_WINDOW` to `ignore` on this phone.** That
   is why it was off today, six days after wave 48 set it. INSTALL-PHONE says so.

## Acceptance

```bash
docker compose -f docker/compose.yml run --rm build ./gradlew test
grep -q 'ACTION_SCREEN_OFF' android/app/src/main/java/dev/bosco/deskpanel/PanelService.java
grep -q 'panelCovered(getSystemService(PowerManager.class).isInteractive())' android/app/src/main/java/dev/bosco/deskpanel/MainActivity.java
grep -q 'canDrawOverlays' android/app/src/main/java/dev/bosco/deskpanel/PanelService.java
python scripts/check_acceptance.py
```

On the phone, with this build installed, `SYSTEM_ALERT_WINDOW` allowed and a PC online:

```bash
adb logcat -c
adb shell am start -a android.settings.SETTINGS
adb shell input keyevent KEYCODE_SLEEP
sleep 8
adb logcat -d -s DeskPanel:I | grep -q 'panel was covered; brought back'
adb shell dumpsys power | grep -q 'mWakefulness=Awake'
adb shell dumpsys activity activities | grep -m1 mFocusedApp | grep -q deskpanel
```

## Manual check

- Open any app over the panel with a PC online and leave the phone alone. One screen timeout
  later the panel is back, lit.
