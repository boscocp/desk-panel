# T4.8 — The log names the PC it is on

Size: S · Prereqs: T4.5, T5.3 · Files:
`android/app/src/main/java/dev/bosco/deskpanel/PcHosts.java`, `PcPoller.java`,
`android/app/src/test/java/dev/bosco/deskpanel/PcHostsTest.java`,
`docs/TESTING.md`, `docs/adr/0016-more-than-one-pc.md`

Requires: the phone on adb for the manual check; two PCs for the last line of it

## Goal

Reported from the chair on 2026-10-10, about the day before: "liguei o PC no CachyOS, depois o
Mac, desliguei o CachyOS, e trabalhei no Mac. Lá o app não mudou pro servidor do Mac, tive que
fechar o app e reabrir pra funcionar."

**The investigation could not answer it, and that is the defect this task fixes.** Everything
the panel knows about which PC it is on, and about what the other one said, is written once per
*transition*:

- `pc answered at <ip>`, on a move, which with two PCs up is the only line that ever names the
  host at all;
- `probe failed: <host>: <reason>; <host>: <reason>`, on the edge into OFFLINE.

A dark panel is noticed hours later. By then both lines are long gone: the device's `main` ring
buffer is 256 KiB by default and this app writes `ping=` to it every two seconds, which on the
Redmi is **about six minutes of history**. What survives is a wall of `ping=err` that says
nothing about which hosts were tried or why they refused — indistinguishable between a PC that
is off, a server that is not running, a firewall dropping instead of refusing, and a cleartext
address the pin does not cover. ADR 0016 created that question and shipped no way to answer it.

T4.5 is still `blocked` on the same scenario — the move between two live PCs — so the next time
it happens the log has to be the record.

## Steps

1. `PcHosts.Cycle` carries a `detail`: `host=<ip>` when a host answered (online or idle),
   `hosts=<ip>:<reason>,<ip>:<reason>` when none did, `hosts=not-attempted` for a cycle a stop
   ended before it dialled. Never null, never contains a space.
2. `PcHosts.shortReason` shortens one failure to a single token: the exception's class without
   its package or message (`ConnectException`, `SocketTimeoutException`), anything without a
   dotted prefix kept whole with its spaces closed up (`HTTP-401`, `not-attempted`), bounded at
   32 characters. The full text still goes out once per transition in `PcPoller.deliver`.
3. `PcPoller` appends the detail to the `ping=` line. Appended, not folded into the marker:
   `Markers` holds single tokens with no spaces (`MarkersTest.everyMarkerIsOneToken`), and
   every existing assertion matches `ping=` or `ping=ok` as a prefix, so T5.2, T5.3 and T5.6
   keep counting what they counted.
4. `docs/TESTING.md` records the buffer: `adb logcat -b main -G 4M` before a session that is
   going to need history, and that it is lost on reboot (`persist.logd.size` is refused to
   `shell` on this device).

## Acceptance

```bash
docker compose -f docker/compose.yml run --rm build ./gradlew test
grep -q 'cycle.detail' android/app/src/main/java/dev/bosco/deskpanel/PcPoller.java
python scripts/check_acceptance.py
```

On the phone, with the panel installed and a PC up. Give the ring buffer room first —
`adb logcat -b main -G 4M`, which exits at once and is lost on the next reboot:

```bash
adb logcat -c && sleep 20
# every ping line says which PC it was about
test "$(adb logcat -d -s DeskPanel | grep -c 'ping=')" -gt 0
! adb logcat -d -s DeskPanel | grep 'ping=' | grep -qvE ' hosts?='
# and the heartbeat the other tasks count is untouched
adb logcat -d -s DeskPanel | grep -q 'ping=ok'
```

With the PC's server stopped, the failing hosts are named with a reason each:

```bash
adb logcat -d -s DeskPanel | grep -q 'ping=err hosts=.*:'
```

## Manual check

- **Two live PCs.** Online on one, shut that one down, and the log has to show
  `ping=ok host=<the other>` from the next cycle on, with no `state=offline` between. That is
  T4.5's blocked half and this task's reason for existing; it needs both machines up.
