# T5.4 — Battery telemetry

Size: S · Prereqs: T5.1, TT.1 · Files: `MainActivity.java`, `web/js/app.js`, `web/js/format.js`

Requires: phone (on adb)

## Goal

Surface battery level and **temperature** on the panel. Heat is what ages a lithium cell; better
to watch the number than to discover the problem as a swollen back cover.

## Steps

1. Register a receiver for `Intent.ACTION_BATTERY_CHANGED` and read `EXTRA_LEVEL`,
   `EXTRA_SCALE`, `EXTRA_TEMPERATURE` (tenths of a degree Celsius) and `EXTRA_STATUS`.
2. Fold it into the existing `onData` payload, as the `battery` key in the T1.2 contract.
   The `window.onBattery(...)` alternative this task used to offer is **not** the design: a
   second bridge means a second thing to mock, a second thing to keep in step, and a render
   path the browser never exercises.
3. Render discreetly — this is diagnostic, not a headline. Small, in a corner.
4. Above **40 degrees**, show a visible but non-alarming warning.
5. Do not poll for this. The broadcast is push-based; polling it wastes exactly the power this
   task is about.

## Acceptance

```bash
node --test "web/test/**/*.test.js"
adb logcat -c && sleep 30 && adb logcat -d -s DeskPanel | grep -qE 'battery=[0-9]+'
```

The unit tests cover the formatting of level and temperature; the marker proves the broadcast
receiver is actually firing, which is the part that silently does not.

## Manual check

Level and temperature track reality — compare against Settings → Battery. Warm the phone
briefly and confirm the warning appears above 40 degrees.

## Notes

- **The app cannot limit charging.** Android exposes no public API; `BatteryManager` is
  read-only. This is settled in [ADR 0008](../docs/adr/0008-device-longevity.md) — read it
  before being tempted to add a charge-limit feature.
- `EXTRA_TEMPERATURE` is in tenths: 315 means 31.5 degrees.
