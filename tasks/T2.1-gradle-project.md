# T2.1 — Minimal Gradle project in Java

Size: M · Prereqs: T0.1 · Files: `android/settings.gradle.kts`, `android/build.gradle.kts`,
`android/app/build.gradle.kts`, `android/app/src/main/AndroidManifest.xml`,
`android/app/src/main/java/dev/bosco/deskpanel/MainActivity.java`

## Goal

An APK that builds in the container and installs. Blank screen is fine — this task proves the
toolchain, not the product.

## Steps

1. Gradle wrapper, Kotlin DSL build files. Java, **not** Kotlin, for application code
   ([ADR 0001](../docs/adr/0001-java-over-kotlin.md)); the `.kts` build files are configuration
   and do not require knowing Kotlin.
2. `app/build.gradle.kts`:
   - `namespace` and `applicationId` = `dev.bosco.deskpanel`
   - `compileSdk = 36`, `targetSdk = 36`, `minSdk = 26`
   - `compileOptions` on Java 17
   - `sourceSets["main"].assets.srcDirs("../../web")` — point at the web folder, **never copy
     it**
   - output the APK into `out/` **at the repository root** — from `android/`, that is
     `rootProject.file("../out")`. Written as `../out/` inside `app/build.gradle.kts` it
     resolves to `android/out`, where `make apk`, T3.6 and the CI artefact step do not look
3. `MainActivity` with an empty `setContentView`. The WebView arrives in T2.2.
4. Ensure `gradlew` is committed LF and executable:
   `git update-index --chmod=+x android/gradlew`

## Acceptance

```bash
docker compose -f docker/compose.yml run --rm build ./gradlew assembleDebug
ls out/*.apk
```

## Notes

- `targetSdk 36` is chosen so the Play Console route stays open. It is well above the API 23
  floor that Android 14+ enforces for sideloading, so installation is not a concern.
- The device is API 31, so nothing here needs an API 36 behaviour workaround.
- Do not let the wizard-style defaults pull in Compose. This project uses Views and one WebView.
