# T6.8 — The weather card earns its space

Size: M · Prereqs: T6.7, T3.4 · Files: `web/themes/neon/`, `web/themes/plain/`,
`web/js/format.js`, `web/test/format.test.js`

Requires: a local Firefox for the two layout checks; the phone for the manual check

## Goal

The weather card is the tallest thing on the panel and holds the least. Make the temperature
read like a temperature instead of like the middle of a sentence.

## What it looks like today

One line of text, centred in a 224x372 box:

```
Sao Paulo: 23°C (18-27°C) Partly cloudy
```

`T6.3` measured 87.3px of free space inside that card — more than twice any other — and put it
there deliberately, because WEATHER is the card whose content varies most: the city is server
config and `Thunderstorm, heavy hail` is a real label. The room was bought and never spent.

Three things are wrong with the line, and only the first is taste:

1. **No hierarchy.** The city, the temperature, the range and the condition are all 24px in one
   colour. The number a person actually looks at is the same size as the name of the city they
   already know they live in.
2. **The range is genuinely ambiguous below zero.** `formatTemp` writes a bare number and the
   card joins two with a hyphen, so the stress payload renders `(-12-42°C)`. That is not a
   styling problem; it is a string that cannot be parsed by eye, and it is on screen today in
   `e2e/layout/stress.js`.
3. **The condition is a sentence fragment.** `Partly cloudy` sits where nothing else on the
   panel is prose, and it is the longest thing in the narrowest column.

## Steps

1. **Fix the range first, in `format.js`.** A pure function — `formatRange(minC, maxC)` — that
   cannot produce `-12-42`. Use a separator no reader can mistake for a sign (`−12° / 42°`),
   and test it at both signs and at zero. This is a bug fix and it does not depend on any of
   the rest.
2. **Give the card a hierarchy**, in `web/themes/neon/theme.js` and its stylesheet. Roughly:
   the city small and in `--accent-dim`, the temperature large, the range and condition below
   it. The exact sizes are a measurement, not a guess — the card has 87px to spend and
   `check_layout.py` says when it has been overspent.
3. **A glyph for the condition.** Inline SVG, built from the WMO code, with no network and no
   webfont (invariant 1, ADR 0002 — a remote font does not fail loudly, it simply never
   arrives). The mapping is a pure function in `format.js`, `weatherGlyph(code)`, returning a
   name from a small closed set — clear, cloudy, rain, snow, storm, fog — so it is testable
   without a DOM. The theme owns the paths.
4. **Keep the label.** The glyph is added to `weatherLabel`, not instead of it: seven glyphs
   cannot say `Thunderstorm, heavy hail`, and the label is what makes the card readable when
   the picture is ambiguous. If they do not both fit, the glyph is what goes.
5. **The plain theme gets the same data and its own answer.** It already renders three lines;
   it must keep rendering legibly with whatever `format.js` gains. A change here that only
   works in neon means the function is in the wrong place.

## Acceptance

```bash
node --test "web/test/**/*.test.js"
node --check web/themes/neon/theme.js
node --check web/themes/plain/theme.js
! grep -rqE 'font-size:\s*1?[0-9]px' web/themes/
python e2e/layout/check_layout.py
python e2e/layout/check_layout.py --theme plain
```

The layout check is the one that matters and it must be run on **both** themes: this task makes
a card taller in one of them, and a card that grows is how T2.3 put a section off the bottom of
the screen.

New tests, in `web/test/format.test.js`:

- `formatRange` at two positives, two negatives, a negative low with a positive high, and zero.
  The negative case is the bug; a test that only covers positives would have passed before this
  task.
- `weatherGlyph` returns a name for every code in `WEATHER_LABELS`, and a defined fallback for
  a code that is not in the table. An unknown code must not render an empty box.

## Manual check

- Read from about 50 cm, on the device, in daylight and in a dark room. T6.3's floor still
  applies: nothing under 20px.
- The stress payload (`Sao Jose dos Campos`, `Thunderstorm, heavy hail`, −12 to 42) has to look
  deliberate, not merely fit.

## Not in this task, and named so it is not smuggled in

The card could say much more — precipitation probability, sunrise and sunset, wind, apparent
temperature. **All of it is a server change**: `providers_openmeteo` asks for
`current=temperature_2m,weather_code` and the daily min/max, and nothing else is fetched, so
there is no field on the phone to render. Adding one means a new task touching the provider,
`normalise`, the payload contract in `tasks/T1.2-mock-fixtures.md`, `mock.js` and the server
tests — and it should be argued for on its own, because every field is a permanent line on a
panel with 392px of height.

This task spends the space the panel already has, on the data it already has.

  shape. An hourly curve would be a different fetch, a different cache and a different task.
