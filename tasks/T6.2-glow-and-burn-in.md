# T6.2 — Glow, micro-animations and burn-in mitigation

Size: S · Prereqs: T6.1 · Files: `web/themes/neon/`, `web/js/format.js`

Requires: node on the host, and Chrome for the manual check

**Paths amended after T6.7.** Glow is a palette and a layout shift is presentation, so both
land in a theme; `web/css/style.css` now holds only the box, the ground and the blackout, and
`web/js/app.js` holds no element name at all. What belongs in core is `offsetFor(now)`, in
`format.js`, which is what the acceptance below tests.

**Read T6.6 before starting.** There is now a second motion available on a card — an
overflowing list walks slowly through its rows — and T6.6's notes ask that the two not fight.
Two independent movements on one card are visible in a way neither is alone.

## Goal

The neon look, plus the thing that keeps a static panel from etching itself into an AMOLED.

## Steps

1. Glow via `text-shadow` and `box-shadow` in the accent colours. Restraint matters — heavy
   shadows on a large panel cost real GPU time and make text mushy.
2. Subtle transitions on value changes. A brief colour pulse on update reads well; anything
   longer than ~300 ms becomes tiring on a panel you sit next to all day.
3. **Burn-in mitigation:** shift the whole layout by a few pixels every few minutes. A CSS
   `transform: translate()` on the root container, cycling through a small set of offsets, is
   enough. Keep the amplitude small enough not to be noticeable and large enough to matter.
4. No animation while offline. The screen is asleep; anything running is wasted battery.

   **Already done, in wave 14.** T6.6 put the first animation on this page and `web/css/style.css`
   gained `animation-play-state: paused` under `:root[data-panel="dark"]` at the same time —
   core rather than per-theme, because it is the page's half of a hardware promise exactly as
   the blackout beside it is, and it covers the thermal cutoff as well as offline.
   `check_blackout.py` asserts it. Anything this task animates inherits the rule; there is
   nothing left to write for this step, only something not to override.

## Acceptance

```bash
node --check web/js/app.js
node --test "web/test/**/*.test.js"
```

The burn-in shift is a pure function of the clock — `offsetFor(now)` — and it is tested as one
in `format.js`, which is what makes "the offset changes" assertable without watching a screen
for ten minutes.

## Manual check

In Chrome, left for ten minutes with devtools open: no console errors, no growing memory.

## Notes

- Prefer `transform` and `opacity` for anything animated — they stay on the compositor. Animating
  `top` or `left` forces layout on every frame, which on this hardware is noticeable.
- The offset cycle should be irregular enough that it does not settle into a pattern that itself
  burns in.
