# T4.9 — The first PC listed comes first

Size: S · Prereqs: T4.5, T4.8 · Files:
`android/app/src/main/java/dev/bosco/deskpanel/PcHosts.java`, `PcPoller.java`,
`android/app/src/test/java/dev/bosco/deskpanel/PcHostsTest.java`,
`docs/adr/0022-the-first-pc-comes-first.md`, `docs/adr/0016-more-than-one-pc.md`,
`docs/BUILD.md`, `.env.example`

Requires: the phone on adb and both PCs, for the manual check

## Goal

Reported from the chair on 2026-10-13, about the day before: the CachyOS PC was on, the Mac was
switched on, and the panel stayed on CachyOS. That was ADR 0016 working as written: the panel
moves only when the PC it is on stops answering. The owner wants a priority order instead: "priority always PC, but if PC server went
down, change to MAC if MAC is on."

## Steps

1. `PcHosts.PRIORITY_EVERY` (5): while the active host is not the first listed, one cycle in
   five asks the hosts in listed order, so the PC wins if it answers with its display on.
2. The other cycles keep asking the active host first. A PC that is off times out at 1.5 s
   (measured from the phone), and paying that on every cycle would make each 2 s cycle about 3.5 s.
3. A PC that answers dark still falls through to the next host (ADR 0020), so a sleeping PC
   monitor leaves the panel on the Mac.
4. ADR 0022 records the decision, and ADR 0016's "no flapping" bullet is marked superseded.

## Acceptance

```bash
docker compose -f docker/compose.yml run --rm build ./gradlew test
grep -q 'PRIORITY_EVERY' android/app/src/main/java/dev/bosco/deskpanel/PcHosts.java
test -f docs/adr/0022-the-first-pc-comes-first.md
python scripts/check_acceptance.py
```

## Manual check

- **Mac first, then the PC.** On the Mac with the PC off, log into the PC. Within about 10 s of
  its server answering, the log shows `pc answered at <pc>` and `ping=ok host=<pc>`.
- **PC goes away.** Shut the PC down with the Mac on. The next cycle shows
  `ping=ok host=<mac>` with no `state=offline` between.
