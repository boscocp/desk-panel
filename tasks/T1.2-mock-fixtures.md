# T1.2 — Mock fixtures for browser development

Size: S · Prereqs: T1.1 · Files: `web/js/mock.js`, `web/index.html`, `web/js/app.js`

## Goal

Develop and review the whole panel in Chrome, with no APK, no phone and no server — by feeding
`window.onData()` exactly the shape the native layer will send in production.

## Steps

1. `web/js/mock.js` — build a payload matching the production shape and call
   `window.onData(payload)` once on load, then on an interval with slightly jittered values so
   animations and transitions can be seen.

   The shape, which the server and `DataPoller` must both honour:

   ```js
   {
     quotes: [ { symbol: "PETR4", price: 38.42, changePct: 1.2 } ],
     fx:     [ { pair: "USD/BRL", rate: 5.12, changePct: -0.3 } ],
     crypto: [ { symbol: "BTC", price: 341200, changePct: 2.8 } ],
     weather:{ tempC: 23, minC: 18, maxC: 27, code: 2, city: "Sao Paulo" },
     battery:{ level: 87, tempC: 31, charging: true }
   }
   ```

2. Load `mock.js` from `index.html` **only when there is no native bridge**, so it never ships
   active inside the APK. Guard on something the native layer sets, or on
   `location.protocol === "file:"`.
3. Extend `app.js` to render that payload into cards.

## Acceptance

```bash
node --check web/js/mock.js && node --check web/js/app.js
```

Then open `web/index.html` in Chrome: cards are populated, and the **Network tab shows no
requests at all**. That last part is the real check — it proves the web layer is not fetching.

## Notes

- This payload shape is now a contract between three places: `mock.js`, the server's `/quotes`
  and `/weather` responses, and `DataPoller`. Changing it means changing all three.
- Keep the mock honest: include a negative change and a long symbol name, so layout bugs show
  up here rather than on the phone.
