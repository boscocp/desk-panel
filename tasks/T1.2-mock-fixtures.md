# T1.2 — Mock fixtures for browser development

Size: S · Prereqs: T1.1, TT.1 · Files: `web/js/mock.js`, `web/index.html`, `web/js/app.js`

Requires: node on the host, and Chrome for the manual check

## Goal

Develop and review the whole panel in Chrome, with no APK, no phone and no server — by feeding
`window.onData()` exactly the shape the native layer will send in production.

## Steps

1. `web/js/mock.js` — build a payload matching the production shape and call
   `window.onData(payload)` once on load, then on an interval with slightly jittered values so
   animations and transitions can be seen.

   The shape, which the server and `DataPoller` must both honour:

   ```js
   {
     quotes: [ { symbol: "PETR4", price: 38.42, changePct: 1.2 } ],
     fx:     [ { pair: "USD/BRL", rate: 5.12, changePct: -0.3 } ],
     crypto: [ { symbol: "BTC", price: 341200, changePct: 2.8 } ],
     weather:{ tempC: 23, minC: 18, maxC: 27, code: 2, city: "Sao Paulo" },
     battery:{ level: 87, tempC: 31, charging: true },
     stale:  false,
     night:  { start: "22:00", end: "07:00" },
     theme:  "neon"
   }
   ```

   `theme` was added by **T6.7**, which made it real: it names a directory in `web/themes/`,
   comes from `theme` in the PC's config, and rides the `/quotes` response. It is optional in
   both directions — absent, unknown or empty, the page falls back to `neon` and says so once
   (`docs/THEMING.md`). `mock.js` sends it only when the page is opened as
   `index.html?theme=<name>`, so the browser's default is the device's default.

   Two fields that were being invented downstream and belong here, in the one place three
   components agree on:

   - **`stale`** — T3.3 serves the last good value with `stale: true` when upstream fails, and
     T5.1 renders "a subtle marker" for it. Neither works if the mock never produces it. The
     mock must emit `stale: true` on some ticks, or the degraded path ships untested.
   - **`night`** — T6.4 sends the night window from server config so changing it needs no
     rebuild. It travels with the data, so it is part of this shape.

   **`battery` is here, not on a second bridge.** T5.4 offered `window.onBattery(...)` *or*
   this key as an either/or; it is this key. One payload, one entry point, one thing to mock.

   `fx` uses `USD/BRL` while `server/config.example.json` uses `USD-BRL`. That is deliberate —
   config spells a key, the payload spells a display pair — and the server's `normalise` owns
   the translation (T3.3).

2. Load `mock.js` from `index.html` **only when there is no native bridge**, so it never ships
   active inside the APK. Guard on something the native layer sets, or on
   `location.protocol === "file:"`.
3. Extend `app.js` to render that payload into cards.

## Acceptance

```bash
node --check web/js/mock.js
node --check web/js/app.js
! grep -rqE '\bfetch\(|XMLHttpRequest|EventSource|navigator\.sendBeacon' web/
grep -qE 'file:|__nativeBridge' web/js/mock.js
node --test "web/test/**/*.test.js"
```

**Amended by T6.7.** The guard that keeps the mock feed inert inside the APK used to be an
inline `<script>` at the bottom of `index.html`, and this line looked for it there. T6.7 put
every script in `<head>` with `defer` — the order is what gets `#clock` into the DOM before
`onPageFinished` reads it — and a script injected from an inline block cannot be placed in that
ordered list, so it could run before `window.onData` existed. The guard moved inside
`web/js/mock.js`, which is where this line now looks. Same claim, same two spellings of it,
different file.

The original called out devtools as "the real check" — read off a panel by a human, which is
exactly what `CLAUDE.md` says a criterion must not be. The negated grep is the same claim with
an exit code: nothing in `web/` can fetch, so nothing in `web/` can issue a request.

The fourth line asserts the mock is **guarded**, so it cannot ship active inside the APK.

## Manual check

Open `web/index.html` in Chrome: cards are populated, the negative change and the long symbol
name both render without breaking the layout.

## Notes

- This payload shape is now a contract between three places: `mock.js`, the server's `/quotes`
  and `/weather` responses, and `DataPoller`. Changing it means changing all three.
- Keep the mock honest: include a negative change and a long symbol name, so layout bugs show
  up here rather than on the phone.
